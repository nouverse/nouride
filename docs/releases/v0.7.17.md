### Secrets you send in chat

- **A password or a key you send in chat is taken out before anything keeps it.** On Telegram, Discord, WhatsApp, the dashboard and `nouride chat` — in a message, an edit, or what you quote — the daemon takes it out of your message as it arrives and puts a handle in its place, `$TMP_SECRET_…`. The value is only in the daemon's memory, for an hour: never in the conversation's history, the dashboard, a log line or a request to a model. The daemon tells you at once, with `/secret undo` for when it was not a secret — your message goes back as you wrote it.
- **What it recognises is one list.** Model providers — Nougate, OpenAI-style, Anthropic, OpenRouter, Google, Groq, xAI, Hugging Face and more — GitHub, GitLab, npm, PyPI, Docker Hub, Atlassian, Telegram and Discord bot tokens, Slack, the clouds, Stripe, Midtrans, Xendit, Twilio, SendGrid, Notion, Linear; private keys, web tokens, a password in a URL; and a value you give a key that names a secret: `password: …`, `TOKEN=…`, `"api_key": "…"`, `kata sandi: …`. A word, a name, a path or a piece of code there stays as you wrote it. A password written into a sentence with no `:` or `=` is not looked for — send it as `password: …`, or keep it with `/secret set`.
- **The agent uses it without seeing it.** A command that names the handle — `curl -H "Authorization: Bearer $TMP_SECRET_…"` — finds the value in its environment, and whatever it prints is masked. `secret_save` keeps one under a name for good; `/secret set <name> <value>` does it from the chat.
- **The secret guard.** Once a turn has read something from outside the conversation — a web page, a file, a forwarded message — the first command to use a handle asks you, at every approval level, `none` included, because what it read may be what asked for it. Once per handle per turn. Turn it off per agent on its **Access** tab, or with `/secret guard off` from an admin.
- **What leaves is masked too.** Every request a model is sent, every text embedded for memory and every line a chat is sent is masked of every credential the daemon knows — the secret store's, and the ones held from chat — by exact value. A key pasted into a chat before this release stops reaching the model from that chat's history once the secret store holds it too.
- **`/secret`** shows what this chat holds: each handle, what it was, and the minutes it has left.

### Credential files

- **A command that reads a credential file has what it holds masked.** `cat .env`, `grep TOKEN .env` or a script that opens it shows what `read` shows — the keys, never the values — and `set -a; . ./.env; set +a` still works.
- **A commit or a push that would carry a credential file is refused**, at every approval level, naming the file: `git add -A` while an `.env` is not ignored, `git commit -a` over a tracked one, a push of commits that hold one. Add it to `.gitignore`, or stage the files you mean by name; you can still commit it yourself. Git run inside a script the command starts is not seen.
- **A command that sends one off this machine asks first** — `scp`, an upload with `curl`, a gist, `aws s3 cp` — under the secret guard, at every level.
- **Nouride's own secrets are refused to every command.** A command — or a line typed into a session — that names the secret store, a copy of it, or the control token is refused at every approval level, `none` included: nothing a task needs is in either. The database, the logs and the credentials directory stay open to commands as they were — an agent still looks back through its own history and logs, and uses the files in the credentials directory by path.
- **What the daemon holds itself is masked out of every tool's result.** The secret store's values, the control token, and the credentials in the credentials directory's files — read again when a file changes, so a refreshed OAuth token counts — are masked out of what any tool hands back, however a command came to print it, and out of everything that leaves the daemon.
- **The agent is told**, so it does not spend a step finding out: credential files show hidden, are not committed, and ask before they leave; the store and the control token are refused.

### The dashboard

- **Deleting a secret deletes it everywhere, and asks first** — on the dashboard, and `nouride secret rm` the same — naming what uses it: the providers and connections that name it, and the agents whose commands are handed it, which lose it from their `exec_secrets` too, so nothing goes on looking for a value that is not there. Where the environment sets it too, nothing changes but the stored copy. A stored value cannot be shown, so it cannot be put back.
- **A Secret guard switch** on each agent's Access tab. Turning it off asks first; turning it on never does.

### Fewer round trips

- **Remote work in one connection.** An agent with a shell is told to send a whole sequence on another machine through one `ssh` with a heredoc, not one `ssh` per command — nearly half of the commands in the most expensive turns were exactly that.
- **A note on the fourth command in a row sent alone**, as the file tools have had: it costs a round trip each, re-sending the whole conversation, and the note says to chain them or send a script.
- **SSH connections reused:** DEPLOY.md has the three `~/.ssh/config` lines that keep one connection open, so several `ssh` in a row skip the handshake, and `nouride doctor` points at them when the agents' ssh config names hosts without them.
- **The agents' ssh config is the one in their HOME.** OpenSSH read `~/.ssh/config` from the service account's home in `/etc/passwd`, not from the agents' `HOME` (`.nouride/home`), so hosts an agent added there were never used. Now `ssh`, `scp` and `sftp` in `.nouride/bin` name that config, it includes the account's own at its end, and new host keys are kept where the service can write them — set up at every start, so an update from any version gets it with no root step. A new install gives the account `.nouride/home` as its home outright.

### Coding agents

- **A worktree per task.** The built-in `coding-agents` skill gives every task handed to a coding agent (OpenCode, Claude Code, Codex, …) a git worktree and a branch of its own, checks what is already there first, and removes it once the work is merged or dropped.
- **The brief is in English, with edges.** Whatever language you wrote in, the agent briefs the coding agent in English — your words translated faithfully, code and paths kept as written — with a goal, the context, what it may and may not touch, how to tell it is done, and the shape of its handoff. You still get the answer in your language.

### One agent per chat

- **An agent you asked no longer answers in your agent's chat** ([#10](https://github.com/nouverse/nouride-releases/issues/10)). When one agent asked another with `ask_agent` and that one started a background job, the job's end woke it in the first agent's chat — it replied through a bot that was not its own, kept a conversation there, and a reply to its line handed your next message to it. Now the job's end goes to the agent that asked, which reports it in its own words; and in a DM, a reply to another agent's line is answered by the bot's own agent. `@name` still reaches the other agent when you mean it, and a job's output that happens to print `@name` no longer runs that agent.

### Under the hood

- **A plain address is not a secret.** In a credential file, an address under a key named for one — Google's `token_uri`, an `AUTH_URL` — is shown as it is; one with a password, a query or a fragment in it is still hidden.
- **Redaction reads the same list.** Drafts, audit rows and memory's transcripts are scrubbed with every shape above, and a bare `password=`, `token:` or `api_key` now has its value masked — the rule used to need something in front of the word.

### Not covered

- What is said in a voice note or shown in a picture is not taken out: a transcript or a description reaches the agent as it is. Send a secret as text.
- A path to the store that a script puts together as it runs is not refused, and git run inside a script is not checked. What either prints of a credential the daemon holds is still masked.

### Upgrading

- **Docker:** `docker compose pull && docker compose up -d`. Check the configuration with the new image first: `docker run --rm -v ./.nouride:/app/.nouride ghcr.io/nouverse/nouride:0.7.17 nouride config check`.
- **Binary:** `nouride update --start`.
- **Before you upgrade:** nothing to change. `secret_save` comes with `exec`: an agent that can run commands can keep a secret under a name, asking at its approval level — `[tools] blocked = ["secret_save"]` if one should not. There is no migration in this release.
