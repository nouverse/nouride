**0.8.10 updates from 0.8.0 or later.** From 0.7.x, start 0.8.0 once first:
[Upgrading to 0.8](https://nouride.com/en/docs/deployment/upgrading-to-0-8/) has the way across.

One database migration, `072`: a mission keeps what a person told it while it worked. 0.8.10 keeps a snapshot of the
database before it migrates, named `…-before-072.db`. 0.8.9 refuses a database 0.8.10 has migrated and says so; to go
back, `nouride db restore` that snapshot first. The event protocol is unchanged, 1.6.

On Docker, check your configuration with the new image before you switch:
`docker run --rm -v ./nouride:/app/.nouride ghcr.io/nouverse/nouride:0.8.10 nouride config check`, with the volume your
compose file mounts.

### Tell a mission something while it works

A mission worked to the end on the goal it started with: what you sent it on the way waited for it to finish.

- **Tell it.** `/mission tell <id> <words>` in a chat, the **Tell it** box on its page in the dashboard, or
  `nouride mission tell <id> <words>`. It reads your words before its next step and follows them: they win over the
  details of its goal. Its goal, checks and limits stay as they were, and its checks still decide when it is done —
  where following you would fail them, or you ask for different work altogether, it asks you instead.
- **You are told where your words went:** "Told. It reads this before its next step." — or, when it waits for your
  answer, at its limit or on an approval, kept for its next turn, with what moves it on.
- **While its checks run.** Checks that fail: its next turn reads your words. Checks that pass where a person accepts
  the result: it waits for you, showing what it was told and has not read — continue it to have it work on that. Checks
  that pass where it would end by itself: one more turn reads them, and its checks run again.
- **Its page lists what it was told,** by whom, and the turn that read it. `nouride mission show` does too.
- **Through its agent.** Ask the agent in a chat to pass your words on to its mission: they are recorded as yours, via
  that agent.
- Who may tell a mission is who may stop or continue it: any operator on the dashboard and the command line, and in a
  chat whoever `/mission` lets act there.

### A reviewer that runs out of time is not a fail

A mission's reviewer has ten minutes for each look. One that ran out of time before it judged the work was read as a
failed check: the agent was sent back to fix what nobody had judged, called done, and the next reviewer ran out of time
again — a mission went round like this by itself until its limits.

- **It is never a fail now.** The next look goes on from the notes of the one before, three looks in all.
- **When none of them finishes,** the mission waits for you, with what the reviewer checked and found: accept it, or
  continue it. At the mission's limit, it waits on the limit, with the reviewer's notes on its page.
- **The reviewer failing it three times in a row stops the mission and asks you,** whatever it found each time. A
  finding new each time never failed "the same way", and done, rejected, done went on to the mission's limits.
- **A result waiting for your accept has Continue and Stop in the chat too,** as on the dashboard, beside Accept.
  Continue with nothing said sends it back to check its work against the goal and call done again; say what is missing
  with `/mission continue <id> <what is missing>`.
- **While it looks, it says so.** The mission's page said "Running its checks" through the whole review; it says "The
  reviewer is looking — pass 2 of 3" now, with how long it has looked, and `nouride mission show` does too.

### Agents answered by Claude Code or Codex, while they work

- **What you send reaches the CLI's running prompt,** where the CLI takes one — Claude Code and Codex do. Before, it
  waited for the prompt to end: hours, in a long mission, after you had been told "I'll read that before my next step".
  Never on top of a command: it waits while one runs, five minutes at most, and goes in the moment the last one ends. A
  mission's words reach its CLI the same way.
- **The agent's own line comes first.** The quick reply in the agent's words to a message sent while it works is said
  before the CLI reads the message, and the CLI reads the two together. Before, a CLI with no command running took the
  message at once and the line was dropped: you were left with "↪ Got it" and nothing in the agent's words.

### Agents answered by Claude Code or Codex, told what a Nouride agent is

- **The time.** Each turn's first message tells the CLI the time in `[daemon] timezone`, as a Nouride agent's does. It
  had the date from its own prompt, not the time nor your zone, and worked out "remind me at five" on a guess.
- **How to write where its words go,** once a conversation and again when it changes — a scheduled job's too: on
  Telegram, no tables. Its tables were flattened into lines it did not choose.
- **Which memory counts.** A CLI may keep a memory of its own, which Nouride and the other agents do not read. It is
  told that what should last goes in `MEMORY.md` with `memory_write`, and what it learns about a person in their facts.
- **Why it is never the orchestrator,** said truly: Nouride's approval level, fixed list and tool switches do not reach
  its CLI's own commands, and the orchestrator is the agent anyone in a room reaches. The refusal said it "cannot route,
  delegate or keep the household's memory", untrue since 0.8.1.

### `/goal`

`/goal`, as other tools name it, starts a mission, and answers every `/mission` subcommand. It was "Unknown command".
Asked in words for a goal mode, an agent now starts a mission too.

### A question sent while an agent works is answered

A message sent while an agent works is read before its next step, as before, and now comes with the rule, for every
agent: if it asks you something, answer it in your reply. Asked "btw, is it pushed?" mid-turn, an agent could look into
it and never say.

### Questions only an admin answers

- **They say so.** A question in a chat that only an admin may answer says "Only an admin can answer this one."
  Before, it said "Tap a button below" to everyone, and refused someone who was not an admin only once they tapped.
- **A copy reaches each admin's own chat** in People, with its buttons — "asked in another chat, where only an admin can
  answer it; you are one." Answered in either, both are settled. A question asked from the dashboard's chat is copied
  too. None is sent where the person who asked can answer it themselves: an admin, or the command line.

### MCP servers that did not start

- **Started again.** A server whose start failed — a box that booted before its network was up, a `uvx` or `npx`
  server still fetching itself — is started again, waiting longer each time up to five minutes, until it comes up. It
  stayed out until the agent was reloaded or Nouride restarted; a server lost after it had connected already came back
  by itself.
- **Five minutes to answer.** A stdio server has five minutes to answer the handshake, where it had
  `[security] tool_timeout_ms`, thirty seconds unless you set it. A `uvx` server fetches itself the first time, and a
  Python with it, which takes minutes on a slow link: it was stopped mid-download, and every start began again.

### Dashboard

- A mission's **Done when**: a reviewer's brief naming a long path breaks inside its card rather than running past it.
- A mission's **Accept**, **Continue** and **Stop** stay on one row beside its title; beside a long one, Stop fell to a
  row of its own.
