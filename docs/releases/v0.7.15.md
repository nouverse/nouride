### Helpers that work in the background

- **An agent can hand a long task to a helper and keep talking to you.** `delegate` with `background: true`: its turn ends at once with what it started, the helper works as a job of its own, and its result comes back to the agent as a message when it finishes — reported in your language. Two helpers are reported one by one, each as it finishes; the first is not held for the second. The agent is told the habit: one helper for a task that takes a while, so it stays free for you; two only for two independent pieces; not for a quick answer or for something you are waiting on.
- **How many at once is a setting:** `[delegate] max_background`, 2 by default, 0 for off, at most 4 — the daemon's in `config.toml`, and each agent's own on its Settings page in the dashboard, which applies to the next helper without a restart. A helper over the limit is refused with what is running.
- **A helper is handed a brief, not a sentence:** a goal, the context, constraints and what to hand back, in English whatever language you speak. A brief with no context is refused with what to add. A helper keeps the agent's tools, grants, approvals, MCP servers and skills; it writes no memory, sends nothing to the chat and starts no helper of its own.
- **It is a job like any other.** It shows in `nouride jobs` and in System Logs → Background work as `helper: <goal>`, and in the chat's strip while it runs. `/stop` in its chat or `nouride jobs kill` stops it, `job_max_ms` bounds it, and it counts against the day's caps. An approval it needs is asked in your chat with its name and goal — "a background task (job_…: …) wants to run this". A restart stops it; the agent is told what it had done and can start it again.

### Helpers, either way

- **A helper runs its commands in the foreground and reads what they print.** A command that waited was moved to a job of its own, which ended the helper there with nothing read — and the job's end woke the agent about work it never ran. A helper in the background may give one command up to thirty minutes (`timeout_ms`); one the agent waits on keeps the usual four.
- **A helper that ran out of time or of rounds says so.** It handed back "success" before, with a summary that said it had not finished.
- **A helper waited on in a turn gets half of an agent's own `max_tool_iterations`** when the pack names one, as intended; it was getting all of it.
- **`delegate` takes briefs, not strings.** A task sent as a single string is refused with the shape to use, and the model sends it again as a brief.

### The dashboard

- **`/start` typed in the dashboard's chat resumes a paused agent.** The chat refused every message to a paused agent, `/start` with them, so an agent paused with `/stop` there could only be resumed from the Agents page. A command the agent still answers while paused — `/start`, `/status`, `/help` — goes through now; anything else still says to resume it first.

### Upgrading

- **Docker:** `docker compose pull && docker compose up -d`. Check the configuration with the new image first: `docker run --rm -v ./.nouride:/app/.nouride ghcr.io/nouverse/nouride:0.7.15 nouride config check`.
- **Binary:** `nouride update --start`.
- **Before you upgrade:** migration 057 adds five columns to `jobs` and converts nothing; the first start takes a snapshot before it. The way back is that snapshot, with the previous version's binary or image: `nouride db restore` names it.
