### Approvals, pauses and restarts

- **An approval you have not answered survives a restart.** It is asked again after the daemon comes back, and the turn that was waiting on it picks up where it stopped. The same call does not ask twice: it waits on the question that is still open. An answer that arrives just after a restart counts once, for the call it was meant for. An approval with less than 30 seconds of its window left is not carried over; it expires and says so.
- **A requested restart no longer waits on approvals nobody answers.** It still waits for a turn that is parked on one.
- **`/stop` survives a restart.** A paused agent stays paused until `/start`, and the alerts' cooldowns hold across a restart too.
- **A memory write waits for you after the agent has read outside content.** Once a turn has read a forwarded message, a webhook's payload or a fetched page, `memory_write`, `person_record` and `person_notes` ask before they write, at the default approval level. They cannot be allowed for always. What is written says where it came from: `(written after reading outside content: …)`.
- **A command that follows a log forever is not sent to the background.** `tail -f`, `journalctl -f`, `docker logs -f`, `watch` and their kin are refused with `background: true` unless the call says `service: true`; the refusal says how to take a snapshot instead. Such a job never ended, held one of the agent's job slots, and held up an update's restart for as long as it ran.
- **One busy room no longer takes the whole queue.** A room holds at most half of the queue's slots, and no more than its agents can use.

### Updating, and the way to 0.8.0

- **0.8.0 will upgrade from the last 0.7.x only, and this release is what makes sure of it.** A release can now declare an upgrade floor, signed into its checksum files. An install below the floor is offered the stepping stone instead — "update to 0.7.N first; 0.8.0 needs it" — by `nouride update`, the dashboard's Update page and a Box's own updates; `--start` takes the stepping stone, never the release beyond it. `install.sh` refuses a release whose floor this install's data has not crossed. Every daemon records the version that last started in its data directory, which is how 0.8.0 will know. No release has a floor yet.
- **Docker: follow `:0.7`.** The production compose file pulls `ghcr.io/nouverse/nouride:0.7`, not `:latest`, so a `docker compose pull` stays on 0.7.x until 0.8.0's notes say how to cross.
- **In a container, `nouride update` names an image tag that exists** — `0.7.11`, not `v0.7.11`, which failed with `manifest unknown`.
- **A lock left by a container that was killed no longer stops the next one.** A lock naming a live process that is not a Nouride daemon — the same PID in a new container — is taken over, with a warning.

### Settings that need a restart

- **Every save says what happened:** "Applied", or "Saved — takes effect after a restart" — in the dashboard, and from every command that writes a setting (`gateway`, `mcp`, `access`, `memory set`, `provider`, `tool-budget`, `people`, `skills`, `agent enable`…), with `applied` and `restartRequired` under `--json`. `nouride config explain` says when each key takes effect.
- **A save that needs a restart offers one**, in a strip above every page until the daemon restarts, and **the dashboard comes back by itself**: it waits for the new daemon, holds its requests while the daemon is away so nothing errors, and refreshes the page you are on — or loads the new build when an update changed it. No manual reload. A restart someone else asked for, from another tab or the CLI, is followed the same way.
- **Adding or removing an agent's MCP server applies at once**, as it always did; it was reported as needing a restart.

### The CLI and doctor

- **`nouride users reset`** recovers a lost first password without `sqlite3`: with the daemon stopped, it snapshots the database, removes the accounts, and the next start prints a new first password. In Docker: `docker compose run --rm nouride nouride users reset` with the daemon's container stopped.
- **`nouride doctor` has a "Ready for 0.8.0" section.** It names each old form this install still uses that 0.8.0 will stop reading — config spellings, Telegram's webhook mode, `local:dev`, a pack's `exec_secrets` list form, `memory_recent`, `USER.md`, a database or memory vault from before 0.7. Each is a warning; nothing stops.
- **`nouride config check` names each agent pack that will not load, and fails.** 0.7.10 said "this configuration would start" over a pack it then could not load — two MCP servers of one name, for instance — and that agent went silent. A pack that failed to load can now be reloaded by name once it is fixed (`nouride agent reload <id>`), and `/health` (`failedAgents`) and the dashboard's Overview name it.
- **The CLI waits for a daemon that is starting**, up to 30 seconds, and says each boot step, instead of saying there is no daemon. When it cannot reach one, it says why: stopped, still starting, another install's, or running with a token this user cannot read.
- **The config's warnings are said at boot, by `doctor` and by `config check`** — not by every command.
- **A word a command does not read is refused**, exit 2, as a flag already was: `nouride agents reload` used to list the agents and ignore `reload`. A bare `nouride db` or `nouride config` prints its help.
- **`db restore` and `db adopt` end with how this machine starts the daemon**, not always with `systemctl`.
- **`/health` and `doctor` say the daemon's own memory**: resident, and the JavaScript heap in use.

### Memory and the prompt

- **A group's recall no longer moves with who is speaking**, and sits behind a cache breakpoint of its own, so a change of speaker no longer re-reads the pack and the harness.
- **Installing a program mid-conversation keeps the prompt cached**: what is installed is listed in RUNTIME, not in the harness.
- **The pieces of one conversation are one search result.** A conversation that crossed midnight was cut into pieces that each took a place among the five a search returns.
- **Compaction has one route:** `summary_model`, then `[memory]`'s `pass_provider`/`pass_model`, then the agent's own model — before an answer, after a reply, for `/compact` and for a job's turn. An install with a pass model set and no `summary_model` now compacts on the pass model; set `summary_model` to keep the agent's own.

- **An agent knows what its peers are for:** OTHER AGENTS gives each a line from its IDENTITY's `Role:`, bounded, so choosing whom to ask is not choosing among bare ids.
- **An agent is told that a memory write waits for you after outside content**, and to say what it wants to save rather than retry.

### Conversations on every platform

- **A long reply is cut where it reads best** — at a paragraph break, then a line, then a space. It was cut at whichever came last, which was nearly always a space: code blocks were split mid-line and sentences mid-way.
- **The event stream (protocol 1.2) carries a helper's, a peer's and a scheduled job's work**, as rows of the turn that did it, marked `via` and `by`, with call ids unique within the turn. A scheduled run has a turn of its own. `waiting` names the approval it waits on (`approvalId`). `nouride chat` follows its conversation on the stream; `/activity` answers from the stream in its old shape until 0.8.0.
- **The event stream hands over each row as it is written.** A stream opened at the newest row waited for its heartbeat — fifteen seconds — before anything new reached it, so `nouride events -f` and a dashboard tab saw a short turn only after it had ended. 0.7.10 had it too.
- **`nouride chat` shows a turn's steps as they happen**, from the stream — the model at work, each tool call and its result, a helper's and a peer's marked as theirs — one line each.
- **A message to a paused agent says it is paused**, and how to resume it, instead of "check routing".
- **Each platform says how to write for it**, from its own adapter; the engine no longer switches on the platform.
- **A listener that throws no longer stops the daemon** — a gateway's, a socket's, an abort signal's; 34 of them were contained, and a check holds every new one to it.

### The dashboard

- **The Nouverse look:** a paper theme and a charcoal-green one, Manrope and DM Mono served by the daemon itself, and every text and background pair at WCAG AA contrast in both. On the light theme the brand lime is an olive, because lime on paper cannot be read.
- **A theme is saved only when you choose one**; until then the page follows the system's, live. The key it is saved under changed: if you had chosen the opposite of your system's theme, choose it once more.
- **Reduced motion is honoured**: no pulse, no press that shrinks, no transitions.
- **The favicon is 7 KB**, not 65 KB; a first visit to Overview is lighter than 0.7.10's even with the fonts.
- **Muted text reads at AA in both themes**, and labels, navigation, status and badges are in DM Mono.

### Builds, releases and the router editions

- **The router editions shut down gracefully again.** The bundled gateway installed its own SIGTERM handler when it loaded, which ended the process at once: on a stop, an update's restart or a crash, no turn was stopped and saved, no approval expired, and no clean stop was recorded.
- **The bundled gateway writes on one 30-second beat**, its checkpoint riding on it, where it flushed metrics every 5 seconds — fewer writes on a Box's card.
- **A failed model call that went through Nougate says which providers it tried**, and the turn's recorded error says so too.
- **Four editions, and no other name:** `install.sh --variant` takes `basic`, `router`, `pro` and `pro-router`; the names from before 2026-09-30 are refused with the four that exist.
- **The Pro image is pushed as `nouride-pro` only.**
- **Builds are reproducible across checkouts**: no artefact names the path it was built in, and the Docker base image is pinned by digest beside its tag.

### Security and privacy

- **Passwords are hashed at OWASP's argon2id cost, 19 MiB**, not 64 MiB: a first start fits in 64 MB again, and every sign-in costs a third of what it did. A password stored at the old cost still signs in, and is hashed again at the new one. The bundled LLM gateway does the same.
- **The journal keeps the last four digits of the linked WhatsApp number**, not the whole number.
- **A pretty-printed log line is scrubbed** of credentials like the JSON line beside it; with `log_pretty` on, the journal carried the unredacted message.

### Upgrading

- **Docker:** `docker compose pull && docker compose up -d`. A compose file of your own that follows `:latest` should follow `:0.7` now (see above). Before you pull, check the configuration with the new image: `docker run --rm -v ./.nouride:/app/.nouride ghcr.io/nouverse/nouride:0.7.11 nouride config check` — Docker has no update guard to put the previous version back.
- **Binary:** `nouride update --start`.
