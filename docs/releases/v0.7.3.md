### Steering from the dashboard

A message you send while the agent works is read by its turn at the next step. On the dashboard it seemed to vanish instead: the agent read it, and all the page showed was a step quoting its first 120 characters.

- **Your message shows at once,** as your own bubble under the agent's steps, with "↪ Got it" and the agent's line under it, and the answer below them. Both lines were sent to the dashboard's connection and dropped there; on Telegram, Discord and WhatsApp they always arrived.
- **In a room** your message keeps its own bubble, and the agent's card quotes it above the lines that answer it.
- **A message the turn never reads is shown once.** When the agent is already writing its final answer, your message starts the next turn, as before, and is now drawn there rather than in both places.
- **Steering a new conversation stays in that conversation.** A message sent before its first turn ended was taken for the start of another chat: the page jumped to an empty conversation, and the agent never read it.
- **The answer before a new turn no longer goes missing.** When a message started the next turn between two refreshes, the answer just written stayed off the page until that turn ended or the tab was focused again.

### A boot you can see

- **`/health` answers from the first second of boot.** The port used to open last, after migrations, the database check, the memory vault and every MCP server, so a daemon that was starting looked like one that was not running: `nouride status` asked whether it was, probes saw a refused connection, and the dashboard could give up on a restart still under way. It now answers 503 `starting` with the step boot is on (`"phase": "connecting MCP servers"`), and every other path says the same until boot is done. A probe that waits for a 200 waits as before.
- **MCP servers connect at once.** They connected one agent after another, each waited out to the tool timeout. Now they start together, four at a time, and boot waits at most ten seconds for any one; a server slower than that joins when it is ready, and its tools come with the next turn.
- **No database check after a clean stop.** Boot ran `quick_check` over the whole database every time, the longest single read it does on an SD card. It now runs after a crash, a kill or a power cut, and at least once a week.

### What a turn cost, and why it was slow

- **`nouride turns show <id>` prints one turn whole.** Every model call with its tokens, cost, how long it took and whether the provider made it retry; the calls added up; the steps; the tool calls from the audit log; the answer. `nouride turns` lists the newest with what each cost. A helper's and a peer's model calls count toward the turn that asked for them.
- **Usage, tool calls and log lines carry the turn's id.** Cost was recorded per conversation and the audit log per chat, so two turns a minute apart in one chat shared every row. Each model call now also records its latency and its HTTP attempts, so a turn that waited half a minute on a provider's rate limit no longer looks like a slow model.

### Steadier turns

- **A scheduled job no longer runs over a conversation.** A job working in the chat's own conversation (`session = "chat"`) and delivering quietly or to a webhook started even while its agent was answering a person there, and the two turns wrote the same conversation. It is skipped now (`agent busy`), and the next occurrence comes as usual.
- **Scheduled turns count toward `max_concurrent_turns`.** Every due job ran beside the ceiling the chat turns kept to. A job waits for a slot like a chat turn, and gets the next free one before a busy room can take it.
- **A restart is not a failed job.** A run the restart cut off was recorded as an error and reported into the chat as a failure. It is `interrupted` now: recorded, not reported, and not counted toward disabling the job.
- **`/stop` ends an MCP call at once.** A call to an MCP server waited out its timeout after the turn was stopped, thirty seconds by default; it is released now, and the server is told the answer is no longer wanted.
- **Helpers keep your approval level and the turn's clock.** A `delegate` helper asked again for writes a person on `/auto` had already allowed, and with no deadline it never wrapped up. It now runs at the parent's level and finishes in time for the parent to use what it found.
- **A message past what one turn reads gets an answer.** After five messages sent while the agent worked, the next waited silently for the turn to end. Its sender is told once that it waits and is answered next — on the dashboard too, where each such message shows under the agent's steps until its own turn begins.

### Smaller fixes

- **A large attachment no longer fills memory first.** Telegram and Discord files were read whole into memory before their size was checked, so a file the platform didn't size, or sized wrong, could put hundreds of megabytes into the daemon before it was refused. A file is now checked against the length its server declares, then counted as it is written to disk and stopped at `max_size_mb`. Each file has 30 seconds; one that takes longer is reported as not downloaded instead of holding up the chat.
- **Telegram fetches messages only.** Edits, channel posts and member changes were downloaded on every poll, only to be dropped.
- **The nightly pass reads its instructions from the cache.** Its rules and the tags it chooses from now go as two cached blocks, so a provider that caches prompts charges them in full once a night rather than for every conversation filed.
- **Changing `[memory.semantic] dimensions` embeds again.** The vectors kept their old size, and search by meaning compared every query with nothing. The size is now part of what a vector is filed under.
- **Switching the embedding model keeps the old vectors until they are replaced.** All of them were deleted before the first new one existed, so a model that couldn't be reached left search by meaning empty.
- **Background jobs get the exec ceilings and a masked log.** `[security.exec] max_memory_mb` and `max_cpu_seconds` now bound a background job as they bound a command in the foreground; a service is spared the CPU-seconds one, which a server spends by running. A credential a job printed went into its log as it was; it is masked now, before it reaches the file.

### Upgrading

- **Docker:** `docker compose pull && docker compose up -d`
- **Binary:** `nouride update --start`

No configuration changes are needed. The first boot migrates the database (`049_turn_ids`: four columns, two indexes), taking a snapshot first as always; `nouride db restore` puts it back.

With search by meaning on, your vectors carry over. Any made at a size other than `dimensions` asks for are embedded again at the next catch-up.
