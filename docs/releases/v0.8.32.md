**0.8.32 updates from 0.8.0 or later.** From 0.7.x, start 0.8.0 once first:
[Upgrading to 0.8](https://nouride.com/en/docs/deployment/upgrading-to-0-8/) has the way across.

On Docker, check your configuration with the new image before you switch:
`docker run --rm -v ./nouride:/app/.nouride ghcr.io/nouverse/nouride:0.8.32 nouride config check`, with the volume your
compose file mounts.

### Changes

- **Each person's chats are their own.** Every account used to see every chat. Now each account sees its own: its
  conversations with each agent in the dashboard, its private chats with the agents on Telegram, Discord and WhatsApp
  (through the person it is under People), the groups that person spoke in, and the rooms it made or spoke in. Two
  accounts talking to the same agent each have their own conversation now.
- **An operator or a viewer sees no one else's chat**, not in the lists and not by its link: Nouride answers as if the
  chat were not there. An admin still opens every one, and picks whose in a dropdown beside the search, in Chats and in
  an agent's History: their own, everyone's set apart by person, one person's (found by typing part of their name), or
  the chats of people not yet in People.
- **Every account is someone in People.** Making an account asks who it is: someone already in People, or someone new,
  named after the account. Each account made before this gets a person of its own when Nouride starts. None is matched
  to an existing person by its name, so if an account is someone you already had in People, link it to them on Users.
- Scheduled jobs' conversations and missions are not held by person yet: everyone sees them as before.
- **Router is no longer offered as an install.** Install Community and turn Nougate on from the dashboard.
  `install.sh --variant router`, still accepted, now downloads Community's own files and switches Nougate on. A Router
  install you already have keeps updating onto Community, as before.

### Fixes

- **A few everyday programs no longer run unasked with a flag that does more than read.** `rg --pre` and
  `--hostname-bin` ran a program of the agent's choosing without a question at any approval level, `tree -o` could
  overwrite a file such as `~/.profile`, and `date --set` could set the clock. With such a flag, the command now asks
  like any new one. A credential path inside a shell's script (`bash -lc "cat .env"`) now asks as the same read
  written as a command does. Found by a review that ran Nouride's own decision on these commands.
- **`nouride policy check` tells an everyday program apart.** It said every command off the fixed list asks once at
  `careful`, `rg -n` included. It now says an everyday program runs at every level without asking, and that one with a
  flag that writes or runs something asks.

### Before you upgrade

With one account, nothing you see changes. With several, each one's chats are its own from the first start. A chat
from before is its person's when Nouride can tell who started it; one it cannot (its turns gone with their retention)
is an admin's to see, under **Not known**.
