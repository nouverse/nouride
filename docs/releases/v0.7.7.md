### Security

- **Open access is refused when an agent can run commands.** With a chat gateway on and an agent holding `exec`, `[security.access] mode = "open"` let every stranger reach a shell — an allowlist did not help, because `open` admits everyone before any list is read. The daemon now refuses that configuration at boot, and the CLI and dashboard refuse to switch to it. Use `pair` or `allowlist`.
- **There is one allowlist.** `[security] sender_allowlist` is read into `[security.access] allowlist` at load, with one log line saying so; the Approved tab and `nouride access` show the list that is used. Move it — it is refused from 0.8.0.
- **The daemon's environment stays out of the model's context.** `cat /proc/<pid>/environ` ran without asking and handed every provider key and bot token the daemon was started with to the model. On Linux the daemon now makes itself non-dumpable at boot, so its `/proc` files are root's; reading any process's `environ` or `mem` is asked for, never approved automatically. A tool call's step line is redacted the way its audit row already was.
- **An install or update takes only a release Nouverse signed.** `install.sh` checks the download against the release's `SHA256SUMS` and that file's signature (OpenSSL 3; without it the checksum alone, and it says so). `nouride update` requires the signature from every release since 0.7.4, public editions included.
- **The binary runs nothing from the directory it stands in.** A `.env` or `bunfig.toml` in the working directory is no longer loaded by the compiled binary; `nouride start` reads the install's own `.env` itself. The CLI checks it reached its own install's daemon before sending the control token, and reads `NOURIDE_PORT` — no longer `PORT` or `HOST`, which a web project's `.env` sets.
- **"Allow always" for a script is tied to the script.** A grant for `./deploy.sh` was bound to the command line alone, so rewriting the script kept it approved. Every grant now covers the content of each script the command runs, and of each program it runs by a path inside the agent's folders.
- **In a group chat, only the person who asked — or an admin — answers an approval.** `/approve all` answers only what the sender may answer, and an id typed in another conversation is refused.
- **Smaller ones:** a credential pasted where a pack names a secret is refused at load (it was logged); a file named `..notes` is no longer mistaken for one outside its folder; a failing `/reload`, `/reset` or `/commands` tells the chat what happened without paths or upstream bodies; the gateway's old copy of its accounts in the data directory is deleted; a token bound to one agent no longer sees other agents' conversations through `memory_read`'s related list; a memory tidy's undo writes only inside its own vault.

### Config files

- **Every save is checked before it is written.** A save through the dashboard, the CLI or an agent's tool is made under the file's lock, checked the way the next boot will load it, and refused if it would not — where before it answered "saved" and the next restart did not come back. The previous version is kept as `config.toml.bak.1` to `.bak.5`. A pack that stops loading after a save is put back.
- **Two saves at once both land.** Most save paths took no lock, so one of two concurrent saves was lost.
- **Edits keep what they do not touch** — comments, single-quoted strings, values over several lines, inline and dotted tables, and an MCP server's `parallel_safe`, `env` and `headers`.
- **A save made against an old view is a conflict, not an overwrite.** The raw config editor, a pack's file editor and the People dialog say the file changed since they opened it. A refused save no longer replaces a stored token.
- **A value of the wrong type or out of range is reported, and its default used.** `allow_private_urls = "false"` was a string, so it was true; a negative spend cap or retention was accepted. `nouride config check`, `doctor` and the boot log now name each one as bad. **From 0.7.8 they are refused at boot** — run `nouride config check` now.
- **A key a gateway or provider does not read is reported** at load — `enable = true` left a gateway off without a word.
- **The time zone is this machine's when you have not set one** (it was UTC), so the 01:00 memory pass, cron jobs without a zone and the daily spend cap's rollover follow the clock on the box. A zone that cannot be used — a typo, or a POSIX `TZ` such as `CET-1CEST` — is refused at boot, by name; `TZ=:/etc/localtime` is read for the zone it points to.
- **Boot advisories are said at warn once,** then at info until what they say changes; a default chosen on purpose is not a warning.

### Turns

- **A turn's journal opens before the message's files download,** so a crash while a file arrives is recovered like any other.
- **A journal write that fails is counted and shown under `/health`,** and is never read later as a call that did not start.

### Restarts and the dashboard

- **A restart no longer signs you out of the dashboard.** While the daemon restarts, the page stays — with whatever you typed — shows that it is reconnecting, and picks up on its own. Only the daemon saying the session is gone signs anyone out.
- **The update page follows the restart the way Overview does.** While the daemon finishes running work it says so — and offers to restart now — instead of reporting after 45 seconds that the daemon is not answering. If the version that comes back is not the one installed, it says that too.
- **A page that fails shows what failed, with Reload**, inside the dashboard rather than a bare "Something went wrong!"; an unknown address links back to Overview. A tab left open across an upgrade reloads itself into the new dashboard, once.
- **On a Box, `/tmp` stays bounded in privileged mode,** so an agent filling it cannot starve the daemon of memory.

### For integrations

- `POST /api/control/agents/:id/skills` takes `{ "changes": { "<skill>": true|false } }` — only the skills that change — instead of the whole `states` map.
- `POST /api/control/config` and `POST /api/control/agents/:id/files/:name` accept the text the editor opened as `expected`, and answer 409 when the file has changed since.

### Upgrading

- **Docker:** `docker compose pull && docker compose up -d`
- **Binary:** `nouride update --start`

Before you upgrade:

- A daemon with `mode = "open"`, a chat gateway and an agent with `exec` will not start. Switch to `pair` or `allowlist` first.
- A `TZ` that is not a zone name stops the daemon at boot. Unset it, or set a name such as `Asia/Jakarta`.
- An install that never set `[daemon] timezone` moves from UTC to the machine's zone.

After:

- `nouride config check` lists any value of the wrong type or out of range — fix them before 0.7.8, which refuses them.
- A grant made with "allow always" for a command that runs a script, or that is handed a secret and runs one script, is asked for once more.
- `UMask=0027` and the privileged `/tmp` reach a service unit when it is written again: `nouride service install` (or a flash, on a Box).

No database changes.
