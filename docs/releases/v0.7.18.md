### Memory

- **Forgetting a person no longer touches what was never about them.** A conversation is someone else's about the person only when it mentions them, or names them by key, full name or alias. A single word of their name decided it too, in any case: forgetting "Claude Test" replaced every "test" and "Claude" in memory — on one box, 3,648 lines across 512 files. A word of the name is now replaced only inside the conversations already tied to them, and only as written, so "Test" goes and "test" stays.
- **Whoever writes from a terminal is `terminal`, not `dev`.** `nouride chat`, a script or a test with the control token wrote as `dev`, "Developer", and memory filed it as a person, `web:dev`. It is `web:terminal` now, and still nobody's until you link it: whoever holds the control token — a script, an agent running `nouride` — writes as it, so linking it to you makes them you. An install's standing "stop asking me" for it moves with it, and a `[[people]]` entry that named `web:dev` still matches.

### What an agent is doing

- **Every agent says what it is doing: waiting for you, working, paused or idle.** The pack's `running` read the same for an agent mid-answer, one stuck on an approval only you can give, and one with nothing to do. Now the first that is true is shown — waiting for you before working, because only you can move it — with how many chats it is working in and its background jobs. On the Agents pages, which refresh while open, in `/status` in chat and in `nouride agents`.
- **Unavailable, and why**, beside the status when an agent could not work if asked: switched off in its pack, a pack that failed to load, or a model provider with no credential.

### Rooms with several of your bots

- **The default agent is now the orchestrator — and the front desk of your rooms.** One agent answers a message that names nobody: in the dashboard and `nouride chat`, and in a room several of your bots share, where it answers the untagged message once, through its own bot, and hands it to the agent whose headline fits — the others stay quiet. Before, nobody answered there. A room that requires a mention stays quiet for it too. `[daemon] default_agent` is read as `orchestrator` and rewritten in `config.toml` at the first start, with the old file kept beside it; the dashboard's **Make default** is **Make orchestrator**. The first agent you make becomes it, and a new install asks for a mention in groups (`groups_require_mention = true`, written in its config); an install that never set it keeps answering without one, as before.
- **Agents see who their peers are, not just their ids.** The OTHER AGENTS part of the prompt, and the list `ask_agent` answers a wrong name with, give each peer its name and its headline — `nero: Nero — Infra: servers, deploys, VPN` — so an agent picks whom to ask by itself.
- **Every agent has a headline**: one short line, 150 characters at most, saying what to bring it — not its system prompt. Set it in onboarding, the New Agent form or `nouride setup --headline`; left empty, it starts as its preset's. The Agents list shows it, and the agent's Settings tab edits it. It is the `Headline:` line of its IDENTITY.md; a pack's old `Role:` line is read the same until you set one.

- **A group decides whether it needs a mention.** In a group, `/mention off` means no mention is needed there, `/mention on` requires one again, and `/mention default` goes back to the gateway's or daemon's `groups_require_mention`; plain `/mention` says the setting and where it comes from. It belongs to the group, so every one of your bots there reads the same value, the command is answered once however many bots receive it — by the orchestrator, through its own bot — and it survives a restart. Only an admin changes it; in a DM it says a DM always gets an answer.

### Edits and MCP

- **An edited message says so.** The dashboard chat shows a small "edited" mark under a message the agent answered as edited — one edited while it was working too — and `nouride turns` and `nouride events` mark those turns `edited`.
- **An MCP server's answers are held to the shape it declares.** When a server says what its answers look like, each one is checked: an answer with a missing or wrong-typed field reaches the agent as an error naming the field, instead of as data it might act on, and the log says which server and tool sent it.

### Dashboard

- **An agent's Skills tab filters and scrolls inside its card**, as the Skills Workshop does. Type a name, a word of what it is for, `built in`, or a missing program to narrow it; the count and the link to the workshop stay under the card.

### The journal

- **Whether an approval prompt reached the chat is a line of its own**: `approval prompt sent`, or a warning that it was not delivered and can be answered from the dashboard or with `/approve`. Before, a prompt that never arrived left the same line as one nobody answered.
- **A secret `exec_secrets` names and the store does not hold is said once per agent**, not on every command that names it.
