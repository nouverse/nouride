**0.8.15 updates from 0.8.0 or later.** From 0.7.x, start 0.8.0 once first:
[Upgrading to 0.8](https://nouride.com/en/docs/deployment/upgrading-to-0-8/) has the way across.

No database migration. The event protocol is unchanged, 1.7.

On Docker, check your configuration with the new image before you switch:
`docker run --rm -v ./nouride:/app/.nouride ghcr.io/nouverse/nouride:0.8.15 nouride config check`, with the volume your
compose file mounts.

### Docker

- **Agents install system packages in the container, and an update keeps them.** `nouride pkg install ffmpeg`, or an
  agent asking for it, installs from Alpine's repositories through a small root service the image starts before the
  daemon, under the same rules as on a server (the repositories only, by exact name), and nothing the image ships can
  be removed. What agents installed is kept on the volume, in `.nouride/system-packages`, and installed again before the
  daemon starts when the container is recreated, as every update does, from the downloaded packages, with or without a
  network. `NOURIDE_SYSTEM_PACKAGES=off` turns it off, and a container started as another user (`--user`) has it off.
  The image grows by about 2 MB.
- **An MCP server run with `npx` says how to get Node in the container:** `nouride pkg install nodejs npm`, kept across
  a recreate. Building your own image with it is still the other way.
- **The examples publish the dashboard on the host's loopback,** `127.0.0.1:18254:18254`, as a native install listens.
  A port Docker publishes goes around a firewall such as `ufw`, so on a server the old examples opened the dashboard
  and its API to the internet. Your compose file is yours: change its `ports` line the same way, and reach the
  dashboard on the machine itself or through `ssh -L 18254:127.0.0.1:18254 you@your-server`.

### Setup and secrets

- **The key `nouride setup` stores is kept.** Run beside a running daemon, as the Docker guide runs it, setup's key
  was written over by the daemon's next change to the secret store, and the bot answered nothing. The daemon now sees a
  key another process stored without a restart, and each write starts from the file as it is.
- **`nouride setup` beside a running daemon says to restart it:** `docker compose restart nouride` from the host,
  `sudo systemctl restart nouride` on a server. It said `nouride start`, which a running daemon refuses, and the
  running one had not read what setup wrote.
- **`nouride secret list` says `not set`** for a credential the configuration needs and nobody set, with what needs it
  and the command that sets it. It listed it as `store`, and the install looked fine while its bot answered nothing.

### Approvals

- **Changing this machine's system packages asks every time again.** Since 0.8.0, `nouride pkg install`, `remove` and
  `upgrade` were on no class of the fixed list, so an agent at `balanced` changed packages as root with nobody asked.
  They ask at `careful` and `balanced`, allow once only, and in a chat only an admin answers. At `trusted` they run,
  and the agent says what it installed.
- **What a level asks is said the same way everywhere.** What the agent is told, `/approvals`, the hint under
  `careful`, the Access tab and the installer name system packages, and what the agent is told and `/approvals` name
  what every level asks: a program installed for every agent, an agent's own persona, who People says a person is. At
  `trusted` an agent was told that nothing asks while those did.

### Chats

- **A message sent before the provider's key was set no longer holds the chat.** That turn failed before it began, and
  every later message, the key set by then, was taken into it as a steer ("↪ Got it", never an answer) until a
  restart. The turn now ends and says the credential is missing, and the next message is answered.
- **After a restart, what one person sent while nothing answered is answered once.** Waiting messages were put back
  one at a time, so a question sent five times was answered five times. Each person's are now one message; in a room,
  each person is still answered on their own.
- **An agent knows what its missions in the chat are waiting for.** A mission's question asks for the answer in the
  chat, and the agent's turn now carries the open question, so a reply that answers it is passed on to the mission
  instead of being read as something new.
- **Claude Code and Codex have a secret kept earlier in the same turn.** A coding CLI's shell keeps the environment it
  started with. A turn now waits up to two minutes for the CLI to start again with the new secret, or is told which
  variables its shell does not have yet, so it does not ask for a key already kept.

### Starting

- **A gateway slow to connect no longer holds the daemon's start.** The daemon waits at most 30 seconds for its
  gateways, then opens the dashboard, answers the CLI, starts the scheduler and the missions, and names the gateways
  still connecting. They keep connecting, and what is sent through them meanwhile goes out once they are up. One Telegram
  connect that hung held everything for a minute; a box started before its internet would have waited until Telegram
  was reachable.

### Office and Overview

- **The Overview shows the Office** where the Agents and Gateways lists were: the office, small, with a line of who is
  working, waiting for you, idle or asleep, and the whole office a click away. The stats above still count agents and
  connections.
- **An agent stays at its desk while anything of its runs:** a background job, a command Claude Code or Codex left
  running in the background, or a mission at work, between that mission's turns too. Each read as idle before, and
  the cat sat on the lobby's sofa. Its badge, `/status` and `nouride agents` say what runs ("1 background job", "on 1
  mission"), and its bot stays online.
- **A mission that needs you puts its agent's hand up:** a question to answer, stuck, at a limit, or its result to
  accept. Only a mission waiting on an approval did.
- **An agent that cannot work sleeps in its bed** (a pack that does not load or is off, a model with no key, a coding
  CLI not signed in), its card and label saying why. It sat on the sofa under a red `!`; the `!` now shows only over
  one still at its desk while it cannot work.
- **The orchestrator wears its crown in the Office,** by its name and on its card.
- **The Office page has a table of every status** and what puts a cat where, with a picture of each.

### Dashboard

- **No em dash in the dashboard or the docs.** Their wording uses commas, colons and parentheses instead; the
  messages an agent sends in a chat that the docs quote changed with them ("↪ Got it, I'll read that before my next
  step.").
- **A conversation whose first turn is still running is in the chat list,** with its spinner, and opens as its
  agent's. A coding CLI's first turn can run for many minutes; it was missing from History, and opened from the Office
  it showed the orchestrator.
- **The Office's Open chat starts a chat with the agent you picked.** It opened the orchestrator's, and what you sent
  went to the orchestrator.
