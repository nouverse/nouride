**0.8.35 updates from 0.8.0 or later.** From 0.7.x, start 0.8.0 once first:
[Upgrading to 0.8](https://nouride.com/en/docs/deployment/upgrading-to-0-8/) has the way across.

On Docker, check your configuration with the new image before you switch:
`docker run --rm -v ./nouride:/app/.nouride ghcr.io/nouverse/nouride:0.8.35 nouride config check`, with the volume your
compose file mounts.

### Automations and missions are each person's own

- **Each person's automations and missions are their own.** Every account used to see and change every automation and
  every mission. Now each one belongs to a person: an automation to whoever made it on the dashboard or turned it on
  after an agent proposed it, a mission to whoever started it, from a chat or from the Missions page. A mission an
  automation starts belongs to that automation's owner. The Automations and Missions pages show your own.
- **What reports to your chat, you can read.** An automation or a mission of someone else's that reports to a chat of
  yours is on your page too, saying whose it is. You open it and read its steps and its runs, and you cannot change it.
- **An operator or a viewer sees no one else's**, not in the lists and not by its link: Nouride answers as if it were
  not there. The conversation an automation or a mission keeps of its own is held the same way, where every account
  could read it before.
- **An admin sees everyone's**, and picks whose in a dropdown beside the search, as on Chats: their own, everyone's set
  apart by person, one person's, or the ones that are nobody's. While the page shows an admin's own, it says how many
  more there are. On an automation's page an admin hands it to a person, or to nobody.
- **Only its owner or an admin changes one**: edits, runs, pauses or deletes an automation, answers a step that waits,
  and tells, stops, continues, accepts or deletes a mission. One an agent proposed is the exception: whoever may open
  the chat it was proposed in says yes, and it becomes theirs. A change an agent proposes to an automation that is
  already there is its owner's or an admin's to say yes to.
- **A webhook's address is shown only to whoever may change it.**
- This is about the pages. An agent still answers from every automation and mission it has, whoever made them: two
  people who must not learn of each other's work want two agents.

### A conversation's model, picked on its page

- **Pick the model and the effort for a conversation from the dashboard.** `/model` and `/effort` were the only way,
  and a command is easy to miss. The bar over a conversation with one agent now has a button with the model's name:
  pick another from the list or type its name, and pick how long the model thinks. It is for that conversation only,
  from your next message; everywhere else the agent keeps its own, and **Back to the agent's own** undoes it. The
  commands still work, and each reads what the other set.
- **`/model` reaches an agent a coding CLI answers.** For an agent answered by Claude Code or Codex, `/model` said the
  model was changed and nothing was. The conversation's choice is now set on its own CLI session, among the models the
  CLI offers.
- **A sign-in code sent to Claude Code is taken at once.** Signing a Claude Code account in from the Models page or
  an agent's page, the code you pasted and sent sat in the terminal as stars until Enter was pressed by itself. Send
  now sends it. If a sign-in ever sits there again, the note under the field says to press Enter first.
- **A conversation that begins with `/model` is yours at once.** On an install with several accounts, an operator who
  typed `/model` as a conversation's first message could not open that conversation again until an agent had answered
  in it.

### Mockups, as a skill

- **A new built-in skill, `mockup-design`.** Ask an agent to mock up a screen, a page or an app and it first asks how
  you want it: a link you can open and click, pictures, pictures inside a phone and a laptop, or the HTML file. It
  writes the mockup as HTML, draws it in a real browser at a desktop's width and at a phone's, measures what can be
  measured (a page that scrolls sideways on a phone, text too small or too faint, a button too small for a finger,
  text cut off or drawn over other text) and looks at the pictures itself, for up to four rounds, before it sends
  anything. A change you ask for is made in the mockup you saw, and the earlier one is kept.
- **It has no look of its own.** The skill names no colour and no font and ships no template: a mockup's look comes
  from what you said, from your brand or the site it is for, or is chosen for that request. The motion-graphics
  skill's example no longer names a font or colours either.
- It needs a browser, so it draws on machines that can run one. On a board too small, it says so first, and can
  still send the mockup as a link or a file that nobody has looked at.
- Each thing its checker finds says where the fix is: the element, what causes it, and the line of the mockup's own
  file and of its style rule.

### Automations that watch

- **A step can go on only when something changed.** A check that runs every ten minutes told you the same thing every
  ten minutes. Mark a step, and what it said is compared with what it said last time: the same again, and the run ends
  there quietly, with no agent woken and nothing sent. So a disk check tells you once when the disk fills, and once
  when it is fine again.
- **An automation can tell you once, and then turn itself off.** "Tell me when the build is done" went on telling
  after it was done. With **Tell me once, then turn off**, the automation turns itself off after the first run that
  tells you something, and its page says so. Turn it on again to be told once more.
- **Quiet hours.** One setting for the install, on the Automations page: two times of the day between which what
  automations would say to a chat is kept. They still run. When the hours end, each chat gets one message with every
  automation that had something to say, the ones that failed first. A question a step waits on is asked then too. An
  automation marked **Tell me at once, even in quiet hours**, and a run you start by hand, are said whatever the hour.
  While something is kept, the page says how many messages are waiting, and until when.
- **A script in front of a webhook.** When the first step of a webhook's automation is a command, the command is
  handed what the caller sent, on its standard input. What it prints goes on to the next step, and printing nothing
  ends the run: a script decides which calls are worth an agent's turn, at no model cost for the ones that are not.
- **Ask an agent for a watch.** "Kabari aku kalau disk lewat 90%": the agent proposes a check on a clock that speaks
  only when what it found changes, and its card says so in words before you turn it on.

### An automation you turned on is not asked again

- **Turning an automation on is your yes to what it does.** A run used to be held, whatever your approval level, for
  a message to any chat but the one the automation was made in. So an automation asked for from the dashboard, "a news
  digest on my WhatsApp every morning", wrote its digest and then could not send it, and its page offered *Always
  allow for this job* for a yes you had already given by turning it on. A run now sends what its automation sends,
  and nothing is held. What earlier runs kept of that hold is taken off them, so no old run shows it again.
- **An automation's results can go to another chat.** Ask an agent for "and send it to my WhatsApp" and it names that
  chat in what it proposes. The card you turn on says where each run's result is sent, and so does the automation's
  page. The run reports there itself, with no message of its own to send.
- **The second look is off on automations unless you choose it.** It is the check that weighs, once an agent has read
  a web page or a mail, whether what it sends next fits the work, and it could hold a run for the same second yes. It
  looks at missions as before. To keep it on an agent's automations, choose **Always look** on the agent's Access
  tab, or name a model in `[security] model_guard`.

### Code, several files at once, and content

- **Code in a reply is coloured, and copied with a press.** In the dashboard's chat a block of code was one grey box,
  and a command to run had to be selected by hand. Each block now has **Copy** at its top, and its words are coloured
  by its language in the theme's own colours, light and dark. A block that names no language stays plain: nothing is
  guessed. What colours the code is fetched only when a reply has code in it.
- **An agent sends several files as one.** Files that belong together, the slides of a carousel or the pages of a
  scan, used to arrive one message each. An agent now sends them in one go, in order: as one album on Telegram, as
  one message on Discord, and one after another on WhatsApp and in the dashboard. Every file is checked before any
  is sent, so a set arrives whole or not at all.
- **A new built-in skill, `carousel`.** Ask an agent for a carousel and it first asks where it is posted, which
  decides the shape of every slide: the feed's portrait, a square, a taller portrait, or a full phone screen. It then
  sends the words slide by slide, each fact with where it comes from, and waits for your yes: the first slide that
  makes someone stop, one idea a slide, a last one that says what to do. Only then does it draw: every slide in one
  HTML file, at the platform's exact size, measured for a phone (text too small once a phone shows it, text cut off
  or off the slide, text too faint, an emoji this machine cannot draw) and looked at as one set, for up to four
  rounds. You get the slides as one album in order, the caption as text to copy, or a PDF for where a carousel is a
  document. Like `mockup-design`, it has no look of its own and needs a machine that can run a browser.
- **Motion graphics made for a feed.** The `motion-graphics` skill now asks where a video is watched, which decides
  its shape: a screen, a full phone screen for Reels, TikTok or Shorts, or a feed post. For a feed it puts the hook
  in the first scene, one idea in each scene, what it says on screen for a viewer with the sound off, and an end card
  last. Each line of words is given the time to be read, a second for every 17 characters. And more of each round is
  measured: in a vertical video, text where the app draws its own bars and buttons over it, and text too pale against
  what is behind it. A round of looking is one command now.
- **A fresh chat offers four things to try.** Under an agent's greeting in the dashboard there were three openers;
  there are four now: the agent introducing itself, a carousel from your own writing, a mockup of a landing page, and
  how to connect Telegram, Discord or WhatsApp. A press puts the words in the message box and sends nothing, and the
  two that end at a colon are for you to finish, with your writing pasted in or your subject named.

### The small gaps

- **A very large picture no longer ends every turn of its conversation.** A long screenshot, or a photo straight from
  a camera, could be refused by the model's provider for its size in pixels, and because a conversation keeps its
  pictures, every turn after it failed the same way. A picture longer than 2,576 pixels on a side is now sent as a
  smaller copy, which is as much as a model reads. Your file is not changed. The copy is made with ffmpeg; on a
  machine without it the picture is left out, and the agent is told its size and that it was too large. A
  conversation that already holds such a picture answers again from its next turn.
- **A gateway with no account for a model is reported as that.** When a model gateway had no account for the model an
  agent uses, the agent said its own requests were built wrong. The gateway that ships with Nouride now answers as a
  missing credential, and the alert an operator gets carries the provider's own sentence, which says which account to
  add.
- **`/secret undo` works in a room of several agents.** Typed with no tag where several of your bots share a
  group, it reached none of them, so a message Nouride had taken something out of could not be put back from there.
  One of them answers it now, once.
- **A message to an agent that names somebody with an @ is answered.** Written one-to-one to an agent's own bot,
  a message holding an `@name` that is not one of your agents, a GitHub handle for instance, got no answer at
  all, however often it was sent: it was read as addressed to somebody else. That rule is for groups, where it
  stays.
- **A very long turn no longer ends on a full context.** A task of a few hundred steps could fill the model's
  context with the steps alone, and the turn ended there with the work unfinished. The agent now sums up its
  earliest steps and carries on from those notes, as a long conversation already did between turns.
- **Continue under your own request that failed in a group.** When an agent stopped partway through what you asked
  in a group, you had to tag it again and say "continue". The line it leaves now has a Continue button, for you or
  an admin.
- **In a dashboard room, an answer is written out as it is in a one-to-one chat.** An agent that says nothing
  while it works used to vanish for a moment when it finished, then show its whole answer at once.
- **Agents carry less with every request.** The tools an agent manages its skills with are sent to the model as one,
  opened when it needs one. They were about a tenth of what an agent's tools take up in every request, for tools that
  are almost never called. Nothing changes in an agent's settings, its approvals or the audit log.
- **An approval belongs to the chat it was asked in.** On an install with several accounts, an operator saw and could
  answer every request for a yes, whoever's chat it was asked in. Now an operator sees and answers the requests asked
  in a chat they may open: their own conversations, the groups they spoke in, their own automations and missions.
  Another person's is not on their pages. An admin sees and answers every one.
- **An agent finds the chats it can send to without a made-up message.** To see where it could send, an agent
  called `send_message` with a recipient it had invented, such as "list", and a text of "test": the refusal was the
  only place the list of chats came from. Nothing was sent, but it showed as a failed step, on every run of an
  automation that sends to another chat among them. The list has a call of its own now, which sends nothing and asks
  nobody.
- **A send that an automation's run held can be read on its page.** Under Recent runs, the words of a held send
  shrank to a sliver beside *Always allow for this job* and ran under the button. The button now goes under the words
  where the column is narrow.
- **A long command in a turn's steps can be read.** In the list of steps under an answer, a long command stood in a
  narrow column beside its result: a dozen lines, broken in the middle of words. It now has the whole row, under its
  result, and breaks at its spaces. A very long one shows three lines, with **Show all** for the rest.
- **The daemon's log and the audit log are an admin's to read.** They hold every line of everybody's chats, commands
  and decisions, and every account could read them. On the Logs page, anyone else keeps the two other tabs.

### Before you upgrade

Nothing to do first. What is different after it:

- **Automations send without a second yes.** Until now a run was held before it messaged any chat but its own, and
  the second look weighed what a run sent after it had read a web page or a mail. Neither holds a run any more by
  default. An automation that reads pages or mail you do not control can be told by what it reads to send something
  somewhere else, so for an agent with such automations choose **Always look** on its Access tab, or set
  `[security] model_guard` to a tier or a model: the look is then on for its automations too, as it was. What a job
  was always allowed stays allowed.
- **The Automations and Missions pages open on your own.** What belongs to someone else, or to nobody, is under
  **Everyone** in the dropdown beside the search, for an admin. Nothing is deleted or paused: every automation runs as
  it did.
- **Who owns what from before** is worked out once, when Nouride first starts on 0.8.35. An automation belongs to the
  account that made it or turned it on, or to the person who turned it on in a chat. A mission belongs to whoever
  started it. One made with the `nouride` command, or by an account that is gone, is nobody's: an admin finds it under
  **Nobody's** and hands it to a person on its page. Nothing is given to anyone by a name that only looks like theirs.
- **An automation turned on in a chat app is yours on the dashboard once People knows that account is you.** If your
  Telegram, Discord or WhatsApp account is not under your name in People yet, add it there, and what you turned on from
  that chat shows as yours.
- **On an install with several accounts, an operator no longer changes another person's automation or mission**, and
  no longer sees it unless it reports to a chat of theirs. Where an operator looks after automations someone else made,
  an admin hands each one to them on its page.
- **An operator no longer sees another person's approvals**, and no longer reads the daemon's log or the audit log.
  Where an operator looks after the server, make that account an admin under **Settings → Users**.
- The `nouride` command sees and changes every automation and mission, sees and answers every approval and reads
  every log, as before.
- **A webhook's body goes to the first step, whatever it is.** If your automation's first step is a command and an
  agent's step after it read what the caller sent, that agent's step is now handed what the command printed instead.
  Have the command print what the agent should read (`cat` prints all of it).
- **`[media] max_image_side`** is new, 2576 by default: the most pixels a picture sent to a model may have on its
  longer side. Raise it only for a model that reads more.
