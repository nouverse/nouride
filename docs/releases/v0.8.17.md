**0.8.17 updates from 0.8.0 or later.** From 0.7.x, start 0.8.0 once first:
[Upgrading to 0.8](https://nouride.com/en/docs/deployment/upgrading-to-0-8/) has the way across.

**Everyone signs in to the dashboard once more after the update.** Its one database migration keeps sign-in sessions
as a hash of their token from now on, and clears the ones kept before. The event protocol is 1.8: a `/btw` answer is
metered as a purpose of its own, `side_question`.

**Scheduled snapshots are weekly now, and four are kept.** An install that set `[daemon] backup_keep` keeps its number;
one on the default keeps the newest four of its daily snapshots at its first weekly one.

On Docker, check your configuration with the new image before you switch:
`docker run --rm -v ./nouride:/app/.nouride ghcr.io/nouverse/nouride:0.8.17 nouride config check`, with the volume your
compose file mounts.

### Effort

- **`/effort` works for every agent.** For an agent its own model answers, the chat's level is sent with each request,
  over the agent's own. A model that refuses it is asked again without it, and the answer ends with one line saying
  so, once; `/effort` alone says it too. Claude Code and Codex agents set it on their session, as in 0.8.16.
- **`/effort <level> lock` makes a level the agent's own,** for every chat and every mission, and kept across a
  restart: it is written in the agent's config, as its Model tab does. `/effort max` alone stays one chat's, and a
  mission runs in a conversation of its own, so it never saw a chat's level. `/effort lock` locks the level the chat
  set, and `/effort unlock` takes the agent's own away. Only an admin can: someone whose person under People is linked
  to an admin's dashboard account.
- **The Model tab chooses the effort** of an agent its own model answers: Default, or low to max. A Claude Code or
  Codex agent's CLI tab has had the choice since 0.8.7.

### Agents

- **An agent picks who does the work by whose it is and how long it takes.** A few minutes: in the chat. Longer,
  but under an hour: a helper or another agent in the background, while you keep talking to it. More than about an
  hour, with little needed from you (long development, a deep analysis, a long scan, a migration): a mission, which
  keeps going on its own and survives a restart. Work of ten minutes was being drafted as a mission.

### Chat

- **`/btw <question>` asks a side question,** while the agent works or when it does not. It is answered at once beside
  the work, marked `btw:`, on the agent's own model with only the tools that read, in a few steps. It is kept out of
  the conversation, so neither the running turn nor the next one sees it. One at a time in a chat.
- **Sizes are spelled one way.** An approval to replace a 2 GB file said "2048.0 MB"; approvals and the "generating"
  line now say "2.0GB" and "3KB", as the rest of Nouride does.

### Tokens

- **A tool's output is made smaller by what it is before the model reads it.** A terminal's colour codes are taken
  out, a line a progress bar redrew is kept at its last state, three or more identical lines become one counted
  `[× N]`, and JSON loses the spaces between its parts. Diffs and files read with `read` are kept exactly. The whole
  output is kept on disk, and the result's last line names the file, so the agent can still open it.
- **A streamed answer is counted by its own figures, cache reads included,** wherever the provider puts them. They
  were read only where the answer starts, and a gateway in front of an OpenAI or Gemini model learns them only at the
  end and sends them there, so those turns were recorded as estimates or with no cache hits. Gemini through the
  gateway's Anthropic wire showed 1 % of its input cached against 94 % on the OpenAI wire; the two now read alike.

### LLM Gateway (router and Pro)

- **Claude on the OpenAI wire reads the conversation back from the cache,** not only the system prompt. The gateway
  marks the last tool, the system prompt and the two newest messages, so an agent's next step reads what the last one
  sent. Claude Sonnet had 38 % of its input cached on this wire, against 81 % on the Anthropic one.
- **Gemini on the Anthropic wire says how large the prompt is where the answer starts,** instead of zero. What it read
  from the cache is given where the answer ends, as before.
- **An answer Gemini gives without streaming carries its usage** on the OpenAI wire, the cache read included. It had
  none, so a client estimated it.
- **`total_tokens` counts the prompt the cache served** in a Claude answer to an OpenAI client that did not stream. It
  came out smaller than the prompt it contains.

### Schedule

- **A scheduled command that prints nothing wakes nobody.** With `--then agent`, the agent is woken only when the
  command printed something, and a run with no output sends nothing to the chat: a check every five minutes that
  finds nothing costs no turn. A command that fails is reported as before.

### Backups

- **The database, the vault and the packs are snapshotted weekly, and four are kept,** a month back. They were daily,
  and seven were kept: the daily copy of the whole database was the largest write Nouride made. A box that restarts
  for its update no longer takes one at every start. The snapshot a migration takes first and `nouride db backup` are
  unchanged.

### Reliability and security

- **A copy of the database no longer holds a sign-in someone could use.** Dashboard sessions are kept as a hash of
  their token, so a snapshot, on a USB drive or anywhere else, carries none.
- **An empty secrets file stops the start and says what to do,** instead of opening as if there were no secrets: a
  write cut off by a power cut left every credential gone, with no reason given. Put back a copy of it, or delete it
  and set the secrets again.
- **Config, the agents' files and memory, and the secrets are on the disk before they replace the old copy,** so a
  power cut leaves the old file or the new one, never an empty one.
- **Built-in skills stay as this release shipped them.** Each told the model to read a newer copy online when its own
  seemed out of date, so a change made for a later release reached every install.
