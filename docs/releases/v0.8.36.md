**0.8.36 updates from 0.8.0 or later.** From 0.7.x, start 0.8.0 once first:
[Upgrading to 0.8](https://nouride.com/en/docs/deployment/upgrading-to-0-8/) has the way across.

On Docker, check your configuration with the new image before you switch:
`docker run --rm -v ./nouride:/app/.nouride ghcr.io/nouverse/nouride:0.8.36 nouride config check`, with the volume your
compose file mounts.

### System: what your machine is using, and the files Nouride keeps

A box that was slow or full was found out over SSH. An admin now has **System** in the dashboard's menu, with four
tabs.

- **System** says what the machine is using right now, each figure a bar with a sentence beside it. **RAM**: how much
  is in use of what Nouride may use, and who holds it, Nouride itself and the agents' commands. **Disk**: the disk
  Nouride's files are on, how much is free, and how much Nouride's own files take, the largest folders first. From
  three quarters full a bar says **Getting full**, from nine tenths **Nearly full**. A figure the machine does not
  give is said as not known: it is never drawn as an empty bar. The version says which edition it is, Community or
  Pro, and when a newer release is out a button beside it opens the Update page.
- **In a container the figures are the container's own.** Where Docker, a pod or a service sets a limit on Nouride's
  memory, the ceiling shown is that limit and the figure in use is the container's count, the one `docker stats`
  shows, not the machine's around it. The disk is the volume Nouride's files are on.
- **Logs** is the page it was, now a tab here for an admin. Anyone else still finds it under Settings, with the two
  tabs they had.
- **Files** shows what Nouride keeps on the machine: its agents, their workspaces, what people sent, its settings.
  Open a folder with a press; a file opens as what it is, a page of markdown as a page, code in its colours with
  **Copy**, a picture as a picture, a video or a sound in a player. A PDF opens in the browser's reader, in a tab of
  its own. On a wide window the list and an open file scroll inside the card, and where you are stays in view.
- **Download** keeps a copy of the open file on your own computer. A file that cannot be shown on the page says so,
  with the button in its middle.
- **Delete** clears what agents and chats left behind: what is in the agents' workspaces, the files people sent in a
  chat, the long output a tool kept, and the logs of background jobs. The page asks first, naming how many files and
  how much of the disk would go. Nouride's own files have no such button: its settings, its database, its agents'
  persona and memory files, and the folder it keeps for each agent. While a mission or a background job is still
  working in a folder, that folder waits until it has ended. Each delete is written to the audit log, with who did it.
- **Credentials and secrets are not shown in Files.** What holds one is left out of every list, by its name too:
  Nouride's own keys and its secret store, the credentials folder, a chat app's session, `.env` files, SSH and other
  keys, and the sign-ins tools keep in the agents' home. Asked for by its address, such a file says it is kept
  private. Inside an ordinary file, something that looks like a credential is hidden where it was, and a file like
  that is read on the page and not downloaded. The database is listed with its size, and neither opens nor
  downloads.
- **A path is a link.** Where an agent writes a path inside Nouride's files, in a reply, among a mission's result
  files or in a command a turn ran, an admin can press it to open that file in Files. The folder a mission works in,
  on its page, opens the same way.
- **Update** is a tab of System for an admin, where it was a card on Settings; anyone else still finds it there.
  **Your box**, at the foot of the menu, opens it when pressed, a newer version out or not.

On a Mac the page says how much RAM there is and not how much is in use: macOS keeps no figure of what could still be
handed out, and the one it does keep reads nearly full on a machine with room to spare.

### Where a key comes from, and whether it will charge you

Adding a model provider asked for an API key and said nothing about where one comes from. On the Models page and
in the first-run setup, **How to get an API key** now folds out under the key's field.

- **Eight services people most often mean**: OpenAI, Anthropic, Google Gemini, DeepSeek, Z.ai, OpenCode Zen,
  OpenCode Go and Command Code, each a link to the page its key is made on.
- **Each says what using it costs.** *Pay per use*: charged by use, apart from any chat subscription (a ChatGPT or
  Claude subscription does not cover the API). *In your plan*: OpenCode Go, which stops at the plan's limits unless
  you turn on Extra Usage there, and Command Code, whose plan includes the key and stops when its credits run out,
  on every plan but Go.
- **Use it** on a line fills the provider's name, how it is talked to and its address. A name you typed yourself is
  kept, and a provider that is already saved keeps its name.

### Extra headers, for a provider that asks for more than a key

A provider's form has **Extra headers** under the key's field, on the Models page and in the first-run setup: one on
each line, as `Name: value`. Most providers ask for nothing, and it stays folded.

- **OpenCode Go works.** It refuses any request that does not say which conversation it is for, so a provider on a
  Go subscription answered nothing. **Use it** for OpenCode Go fills `x-opencode-session: {session}`, and Nouride
  writes an id of the conversation where a value says `{session}`: the same through a conversation, holding no chat
  id, name or number.
- **Every line is yours**: change it, add one, remove one. In `config.toml` they are the profile's `headers`.
- **A saved header shows its name only.** Its value is not sent back to the page; a line left as it is keeps it.
- **The key stays in the key's field.** The form does not take `Authorization`, `x-api-key` or `Content-Type`.
- **A plan is not shown as money spent.** A provider on OpenCode Go or Command Code is counted in tokens, and its
  use is left out of the daily cost cap.
- **Requests say they come from Nouride.** Every request to a model says `user-agent: nouride/<version>`, where it
  said the HTTP library's name before. A `user-agent` in a profile's `headers` replaces it.

### A new agent follows the install's provider

Every agent made from the dashboard named its provider profile in its own pack. The day an install moved to
another profile, each of those agents named one that no longer existed and stopped loading, until every pack was
edited by hand ([#18](https://github.com/nouverse/nouride/pull/18)).

- **The first agent's provider and model are recorded as the install's**, under `[llm.defaults]`, and its pack
  says neither. An agent that says nothing follows the install when its provider changes.
- **An agent made with another provider or another model says both in its own pack**, as before: it is different
  on purpose.
- **Defaults you set are never written over.** A key you left empty is filled in only by an agent that agrees with
  the ones you set; an agent made with another model than your default keeps its own, in its pack.
- **An agent that does not load leaves nothing behind**: what was recorded for it is taken back with its pack.

Agents you already have are untouched: their packs say what they said.

### What nothing pointed at any more is cleared

The daily clean-up went by Nouride's records: a job's log went with the job, a mission's own folder a week after
the mission ended. What no record named was never looked at again, and stayed.

- **A job's log that no job points at** is deleted with the old ones, after `[retention] job_log_days` (three days
  unless you set it; `0` keeps everything).
- **A mission's own folder whose mission is no longer on record** is deleted once it has gone a week untouched.
  Never one that holds work nobody committed: that one is named in the log, and stays.

### The log says what made a conversation cost more

A model's provider keeps the front of a conversation, so the next request pays a fraction for what it has read
before. That only holds while the front stays the same: when something in it changes, everything after it is paid
for in full again, the whole conversation with it. Nouride knew when that had happened and not why.

- **When a part of what is sent in front of a conversation changed since its last request**, while the provider
  would still have had it, one line in the log says which parts: the tools, the model, or a section of the prompt
  by its name (the agent's memory file, what it knows about the people in the chat, its skills), with how much
  conversation is written again. Names and a size, never what a part holds. An admin finds the lines under
  **System**, **Logs**, by searching for `cached prefix`.

Nothing an agent reads or does changes with it. What the lines show on a real install decides what is moved or held
still in a later release.

### Before you upgrade

Nothing to do first. What is different after it:

- **Logs and Update have moved for an admin**: from Settings to tabs of **System**, in the menu. Their addresses are
  the same, so a bookmark still opens them.
- **The first clean-up after the upgrade deletes what the earlier ones left**: job logs older than
  `[retention] job_log_days` that no job points at, and missions' own folders, a week untouched, whose mission is no
  longer on record. Look in `jobs/` and in each agent's `missions/` folder first if you keep anything there by hand.
- **New lines in the log** when a conversation's cached front changed: they name what changed, and change nothing.
- **A provider on OpenCode Go or Command Code is written `billing = "included"`** at the first start, once, unless
  its profile already says `billing`: its use is counted by `max_daily_tokens` and no longer by
  `max_daily_cost_usd`. Write `billing = "metered"` to keep it as it was. `nouride config check` says so before
  the upgrade.
- **Requests to a model carry `user-agent: nouride/<version>`.** A gateway or proxy of your own that filters by
  user agent needs to let it through, or the profile can name another in `headers`.
