**0.8.7 updates from 0.8.0 or later.** From 0.7.x, start 0.8.0 once first:
[Upgrading to 0.8](https://nouride.com/en/docs/deployment/upgrading-to-0-8/) has the way across.

### Missions you can close, answer and follow from the chat

- **A mission waiting on you can be accepted as it is.** `/mission accept <id>` used to work only after its checks
  passed. A mission stuck on a check it could never pass, or waiting on a question, answered "not waiting for an
  accept", and there was no way to close it as done. Now accepting it closes it as done, and its notice says it was
  accepted without its checks passing. The mission page has an **Accept as it is** button that asks first.
- **Buttons instead of commands.** A mission waiting on you has buttons under its message: **Continue**, **Accept as it
  is** and **Stop** when it is stuck or reached a limit, **Accept** when its checks passed, and **Start it** or
  **Drop it** on an agent's proposal. A question with options (A, B, …) gets a button for each, and free answers still
  work. A button pressed after the mission moved on does nothing and says so.
- **Checks that could never run are refused when the mission starts.** A check runs with nobody to ask, so one that
  would need a person's approval never runs. That used to come out only when the agent said it was done, and the
  mission then went round in circles. Now the agent is told at the start and writes another.
- **`git` and `gh` checks run for agents with a token for them.** A check no longer gets the credentials bound to its
  program, so it no longer asks for approval. Checks read what is on disk: a file, a local branch, tests in the
  worktree.
- **Shorter, clearer notices.**
  - The start is one line: what the mission does, how many checks, and how to stop it.
  - A question comes whole, up to 3,000 characters, and says where to read the rest.
  - Progress is one message, updated in place where the chat allows it.
- **An agent sees its own missions, background jobs and approvals.** It can tell you how far a mission is, step by
  step, and stop one or answer its question for you. It no longer needs to ask another agent to look.
- **A mission can be closed as done outside its checks** when the work landed another way:
  `/mission accept <id> --outside "<where>"`. Its own report is kept.
- **A mission can work on a branch you name** when it is started in a repository, and one that has to wait for a free
  slot says why it waits.
- **Related work has one owner.** An agent starting a second mission in a repository where one of its own is already
  running is asked to make it part of that one. The extra worktrees a mission made for itself are removed when it ends.
- **A mission whose model cannot answer pauses and tries again by itself.** A usage limit, a rate limit, a provider
  down: it tries again after 2, 10 and 30 minutes, then hourly, for about a day, and only then asks you. It used to
  fail three times in a row within seconds and wait for you, and fail again as soon as you continued it. You are told
  once when it pauses and once when it goes on, with **Retry now** and **Stop**.
- `nouride approvals --all` lists answered approvals too, and `nouride approvals show <id>` shows one.

### Agents answered by Claude Code or Codex

- **The `[llm] effort` setting reaches them**, where the coding CLI offers it — chosen on the agent's CLI tab, or set by
  the agent itself when you ask it to think harder.
- **In a mission, their tokens are counted**, and the mission is held to time and tokens rather than turns. Where the
  CLI does not report its tokens, the mission says "tokens unknown", not 0.
- **Deleting inside the mission's own folder no longer asks.** `rm -rf build` inside the mission's folder runs without
  a person. A delete anywhere else, or one Nouride cannot read for certain, is asked as before.
- **Approvals from a mission say which mission they come from**, show the command once, exactly as it will run, and
  offer **Approve similar** for that kind of command in that mission until it ends.
- **Pictures and voice notes reach them.** A picture you send goes to the coding CLI as a picture where it says it
  takes them, and as its file's path where it does not. Before, it got only `[image_ref attached]`, and a note telling
  it the picture was in front of it.
- **What it writes before a step is kept.** An explanation written before a command, then a short closing line, showed
  as the closing line alone on the dashboard and in the conversation's history.

### While an agent works

- **A long answer no longer looks stuck.** After its last step the progress line says it is thinking or writing a
  reply, with how long, instead of standing still for minutes.
- **A message sent while it works is answered in one bubble.** "Got it" becomes the agent's own short line where the
  chat can rewrite a message. That line is a guess written without the conversation: the agent goes by your words and
  corrects it if it misread you. When your message replies to another one, the agent sees which.
- **Questions for approval come one at a time per chat, a mission's included,** and the one on screen says how many
  wait behind it. The dashboard marks the ones not yet sent to the chat. `/approve` typed in the chat answers a
  mission's question shown there.

### Fixed

- The missions' Limits card kept clearing what you typed when the settings were read again; it keeps it until you save.
- A Discord bot no longer logs "health check failed" about 30 seconds after every start. It was judged before its
  first heartbeat was due.
- A mission's goal and review an agent writes are in English, like its memory, whatever language you speak. Its
  report and its questions stay in yours.
- An agent asked by another agent says where it went past what it was asked.
