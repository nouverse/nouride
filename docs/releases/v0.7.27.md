### Skills

- **An agent writes a skill for a kind of task, not for one task.** What an agent learns now has three places: a task's progress goes in its work notes, facts about machines, accounts and people go in memory, and a skill holds only the steps for work of that kind — the steps an agent would follow the next time, on another task. Before, an audit of one workbook became a skill of its own, and skills filled up with addresses and the story of a session.
- **A new kind of work is noted before it is written.** The first time, the agent keeps a name and a "Use when" line as a candidate; the skill is written when another conversation turns out to be the same kind of work, or at once when you ask for one in words. A candidate that does not come back within 30 days lapses.
- **A skill is checked before it is saved.** A skill that names a machine's address, an account or email, or tells what happened in a session is refused with the reason, as is a description that says what was changed instead of when to use it, and a body past its size — the detail belongs in a reference file beside it. The same checks apply when an agent saves a skill because you asked it to.
- **A new skill is on for the agent that learned it.** The others can see it and switch it on (`nouride skills on <skill> <agent>`, or the Skills page), so one agent's lesson no longer lands in every agent's prompt unasked.
- **A weekly review keeps the library tidy.** Once a week the daemon proposes tightening a skill that has grown too long or holds facts, merging skills that cover one subject, and archiving one nobody has read in 45 days. Every proposal waits for you on the Skills page, in every mode; approving a merge or an archive moves the old skill to `skills/.archive/`, and moving it back undoes it. **Review now** on the Skills page, or `nouride skills review`, runs it at once.
- **When a skill was last read is kept for as long as the skill**, not only for as long as the audit log keeps its rows, so the Skills page, `nouride skills` and `nouride doctor` say "no read on record" rather than "never read" for a skill read weeks ago.
- **Approving says what it moves.** `nouride skills drafts` and `/drafts` mark a proposal that archives or merges skills, and approving one says what was archived, what was updated, or which agent a new skill is on for.
- **`[rsi]` is now `[skills.learning]`**, with `mode = "off" | "ask" | "auto"` (`ask` is the default), `model` and `notify_chat`. `require_approval` is `ask` and `always_allow` is `auto`; the five tuning settings are gone — when the review looks is the daemon's own. On the dashboard the panel is called **Self-Improving Skill**.

### Memory

- **What an agent recalls about a person says when each fact was learned**, and a conversation waiting to be filed is marked as not read yet.
- **A fact learned in several chats is shown once.**
- **Recall can be switched off** — for everyone with `[memory] recall = false`, or for one person on the People page (In prompts). Facts are still kept every night and agents can still search them; only what goes into the prompt stops.
- **Three conversation summaries go into each prompt by default, not five** (`[memory] prompt_recent`, also on the Memory page).
- **The Memory page says when the nightly pass ran, when it runs next, and when it is running.**

### Privacy

- **A file sent to one of your bots is no longer seen by another.** On Telegram and WhatsApp a direct chat's id is the person's own id, so two of your bots talking to the same person shared one id: a screenshot sent to one agent's DM showed up in another agent's context and in its `attachment_read`. A direct chat's files now belong to the bot they were sent to; a group's are still shared by every bot in it (#12).

### Chat

- **A scheduled job's turn is the daemon's own, not a stranger's.** Since 0.7.26 an agent running a scheduled job, a background job's end, an answered approval or a resume was told it did not know who was speaking and should not assume your authority. It is now told the daemon started the turn, and there is nobody to identify (#13).

### WhatsApp

- **A file sent with a caption arrives.** WhatsApp on a phone sends a document with a caption in a form the daemon did not read, so it dropped the message without a word — the file had to be sent first and the text after it. The file and its caption now arrive together; so do messages in a chat with disappearing messages on, and view-once photos.
- **A document keeps its name.** A file reached the agent as `01-file.pdf`, and a spreadsheet or Word file as `01-file.bin`; it now keeps the name and extension it was sent with.

### Before you upgrade

- **Two database migrations**, with a snapshot of the database taken first.
- **`[rsi]` is rewritten as `[skills.learning]` at the first start**, the old file kept as `config.toml.bak.1`. An install that had `always_allow` keeps learning without asking (`auto`); set `mode = "ask"` to review every new skill first.
- **Docker:** `docker compose pull && docker compose up -d`. Check the configuration with the new image first: `docker run --rm -v ./.nouride:/app/.nouride ghcr.io/nouverse/nouride:0.7.27 nouride config check`.
- **Going back:** to 0.7.26, `nouride db restore` the snapshot taken before the migration. To a release before 0.7.23, also put back each agent's `config.toml` from the `.bak` file beside it — those releases do not read the approval names 0.7.23 wrote.
