### Editing a message you sent

- **An edit reaches the agent**, on Telegram, Discord and WhatsApp. A message not answered yet is answered as you corrected it, once. One a turn is working on reaches that turn at its next step, as a message sent while it works does, and the agent says "↪ Got your edit — I'll go by it from my next step." One already answered is asked again — the agent is told it is an edit and what the message said before, so it can say what changes — within fifteen minutes of when you sent it: the quarter hour after which a message is too old to answer at all.
- **An edit that changes nothing you can see starts nothing**, and neither does one that now reads as a command: an edit is words. Telegram and Discord send a message again when its link preview loads, and that is not a question. A picture swapped in by an edit is not read again.
- **In a room an edit is routed like any message.** One that now names the agent reaches it; one that names nobody only corrects what the room's agents overhear.

### Approvals

- **An approval on Telegram and Discord has buttons:** Approve, Deny, and Always where `/approve always` would be honoured. A press is the same answer as the command, by the same rule for who may give it — in a room, the person who asked or an admin; anyone else is told so, privately, and nothing changes. The prompt still says how to answer by command, and WhatsApp keeps the text prompt.
- **A prompt says how it settled.** By a button, `/approve`, the dashboard, the CLI or its window running out: the prompt says what was decided and by whom, and its buttons go. A button pressed after that, or after a restart, says it is already settled.

### The event stream

- **Protocol 1.3 says when a turn answered an edit:** `editOf` on a turn's start and on a `steer`, whose line starts `✎ `. `nouride turns show` says it too.

### Upgrading

- **Docker:** `docker compose pull && docker compose up -d`. Check the configuration with the new image first: `docker run --rm -v ./.nouride:/app/.nouride ghcr.io/nouverse/nouride:0.7.14 nouride config check`.
- **Binary:** `nouride update --start`.
- **Before you upgrade:** the WhatsApp bridge speaks protocol 4, and a bridge from another release is refused — the log says `bridge protocol mismatch`. The release's own bridge, in the image, in the tarball or built into the Pro editions, is the one that runs; only a bridge started by hand needs replacing. There is no migration in this release.
