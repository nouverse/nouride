**0.8.1 upgrades from 0.8.0 only.** An install on 0.7.x takes 0.8.0 first, starts it once, then takes 0.8.1:
`nouride update` and the dashboard's Update page offer 0.8.0 first and say why, and 0.8.1 once 0.8.0 has started. By
hand, `sh install.sh --version v0.8.0`, start it, then install 0.8.1. On Docker: set
`image: ghcr.io/nouverse/nouride:0.8.0` — that tag, not `0.8`, which is 0.8.1 now — `docker compose up -d`, wait for it
to say it is ready, then set the image back. From a 0.7.x older than 0.7.28, start 0.7.29 once before 0.8.0 (the `0.7`
tag on Docker), as 0.8.0 asks. 0.8.1 started on data 0.8.0 has not run on refuses to start, before it writes anything,
and says how across.

### What 0.8.1 no longer reads

- **A database from before 0.8.0** — below the schema 0.8.0 leaves (69) — is refused with "install 0.8.0 first" and
  left as it is, and so is such a snapshot in `nouride db restore`: 0.8.0's `db restore` puts it back. The schema is
  one file now, `069_baseline.sql`, folded from the two 0.8.0 had; a database 0.8.0 left is taken as it is, with no
  migration and no snapshot.
- **`[llm] fallback_model`** in a pack is refused for that agent, naming the line to write:
  `fallbacks = [{ provider = "<the pack's provider>", model = "<the model>" }]`. 0.8.0 rewrote it in every pack at its
  first start, so one met now came back — a pack pulled from git, a hand edit — and the other agents load. Nothing is
  rewritten at boot any more.

### External agents: a coding CLI as an agent

An agent whose turns a coding CLI answers — **Anthropic's Claude Code** and **OpenAI's Codex** built in, any other
that speaks the Agent Client Protocol added as `[[external_clis]]` in `config.toml`.
You talk to it as to any agent: its own bot, a room, the dashboard, `ask_agent`, a mission. The CLI keeps its own
model, context and prompt; Nouride gives it a channel, approvals, missions, memory and its tools. A pack says which
CLI: `[external] cli = "claude-code"`, with `profile` (the account), `permissions` and `model`.

- **Make one from the dashboard.** **Agents → New Agent** asks who it is as for any agent, and under **Answered by**
  offers the CLIs the box has, each with its maker, then the account it answers with. Its **Brain** tab holds the CLI,
  the account, the preset and the model. `nouride agents scan` lists the CLIs from a terminal. Nouride ships no CLI:
  Claude Code and Codex install with npm, and the orchestrator installs either for every agent, on your yes.
- **Accounts.** **Models → Coding CLIs** lists each CLI's accounts and the agents on each. A Claude Code account signs
  in once there — Claude Code's own `setup-token`, kept in the secret store — and every agent on it uses it. A Codex
  account signs in once per agent, on its Brain tab, in the agent's own folder. **Sign in** runs the CLI's login on the
  box and takes the code back from the page — or, where the browser ends on a page on the box that does not load, its
  address, which Nouride opens there; `nouride agents login <id>` does it in a terminal.
- **Run as the agent.** One CLI process per agent, as its own user, started at its first turn and stopped after five
  quiet minutes. Each conversation keeps its session, reopened after a restart where the CLI can; `/new`, `/reset`, a
  rollover and a delete start the CLI's side over too.
- **Asked as Nouride asks.** The preset — free in its folder, ask when risky, ask for everything — is the CLI's own
  mode, set on a conversation already going at its next message when it changes. *Free in its folder* asks nothing,
  a push or a POST included, and is free only where each agent is its own user; on Docker and macOS it asks as *Ask
  when risky* does. What the CLI still asks is a Nouride approval, from the chat or the dashboard, parked in a
  mission. A stop reaches it however early it comes, and a CLI that does not stop when asked is stopped.
- **Who it is** comes from its persona files, written into the CLI's own instruction file (`CLAUDE.md` or
  `AGENTS.md`) between markers Nouride keeps; your lines in that file stay. Each message starts with where it came
  from — the platform, a DM or a group, and the agents `ask_agent` reaches from there.
- **Its skills** — those switched on on its Skills tab — are copied into the CLI's own skills folder, for Claude Code
  and Codex; one that needs a Nouride tool the CLI cannot call is left out. A change reaches a conversation as it
  starts: in one going, `/new`.
- **Nouride's tools, lent.** While its turn runs, the CLI reaches `ask_agent`, `delegate`, memory, people, the
  conversation's plan and notes, `schedule`, a mission's own tool, `send_message`, `send_file` and the agent's MCP
  servers from the library over MCP — each call through the same gate and audit as a model's. Its bearer is in the
  CLI's environment, which only the agent's own user reads. Claude Code's claude.ai connectors are off: they reached
  outside the gate. Its files, shell and web stay the CLI's.
- **Lists show the model it answers with** — the pack's, or the CLI's own default as its session named it: "Claude
  Code · Opus 5.5 (default)" on the agent picker, Home, the Agents page and `nouride agents`, and on each turn's record.
- **When it cannot answer** — not installed, not signed in, failing — its status says why, and its own model answers
  that message with a line that says so. A new version of a CLI answers a one-line question before its agent takes
  work; one that does not stops that agent, naming the version, and the others go on.
- **In a mission** it keeps one session the mission long, works in the mission's folder and ends with the mission's
  tool; its plan is the mission's checklist.
- **Never the orchestrator**, and **only where the box can hold one**: measured with a session open and idle, Codex
  holds about 190 MB and Claude Code about 330 MB, so with less than 512 MiB for the agents' commands nothing is
  offered.

### Adding an agent from a chat

Ask the orchestrator — "add an agent", "tambahin agent baru dong" — and it asks the rest, one thing at a time: what
the new agent is for, a Nouride model or a coding CLI, its name, its persona, its look. It offers only the CLIs
installed on the machine and installs a missing one on your yes. It says it all back and creates it on your yes,
through the approval prompt as before. `agent_create` takes `external` (a CLI, an account and a model) and `look`;
for an external agent it gives the link to its Brain tab, where the sign-in happens — never in a chat, and never by
the orchestrator. The guide is the built-in `nouride` skill's `references/adding-an-agent.md`.

### Nouride's agents in Zed

`nouride acp [--agent <id>]` serves an agent to Zed and the editors that speak ACP. The editor runs it on the machine
the daemon runs on; the agent works in the daemon as always, and the editor shows its reasoning, each tool call with
its arguments and result, and the answer as it is written. A call that needs a person is the editor's permission
prompt; a cancel is `/stop`; a reopened session shows what was said in it. A session opened in a folder that is not
one of the agent's roots is refused, naming `[workspace] roots`.

### Missions in a repository work side by side

A mission whose folder is in a git repository, on a box with room for it, works in a worktree of its own on the branch
`mission/<id>`, from the repository's last commit — what was not committed is neither taken nor touched. Two missions
in one repository no longer wait for each other. The notice that asks for your yes, the done notice and the mission's
page name the branch; merging it is the agent's call, through the gate like a push. The worktree goes with the mission's folder after the keep days,
and the branch stays.

Helpers that write can each have one too: `delegate` with `isolated` gives every helper a worktree of the mission's on
a branch of its own (`mission/<id>-helper-<n>`), and the result names the branches for the mission to merge.
`isolated` is offered only in a mission that works in a worktree of its own.

Two notices of 0.8.0 said what had not happened. A mission with no checks that waits for your yes said it "passed its
checks"; it now says it is done. A mission an agent proposes said the same before anything had run; it now says
`<agent> proposes a mission: <goal>`, and how to start it.

### Nouride Office

**Monitor → Office** draws your agents' statuses as a small office of cats: a workroom, the lobby with the Nouride
Office sign on its wall, and a bedroom, side by side over a hall. Every agent has its own desk, its own seat on a sofa
and its own bed, three to a row; the orchestrator's desk stands alone at the front of the workroom, in the middle, on a
rug of its own. An office holds twelve: the orchestrator always, then the agents made first. The rest are in another
office — a door at the end of the hall with how many on its sign — and a line over the office says how many agents
there are in all, how many are here, and how many of those elsewhere are waiting for you. A working agent sits at its desk behind its laptop, `…` over it; one waiting for you has a hand up and
a `?`; an idle one is on its seat; an asleep one is tucked into its bed, a `z` drifting over it. A red `!` marks one
that cannot work, with the reason on its label. When a status changes, its cat gets up and walks there — round its
desk, along the aisle, out through its room's door, along the hall and in through the other — and its name walks with
it. Nobody moves desk because somebody else came or went. The windows show the sky as it is where you are, day or
night, and the lobby's clock the time.

Click a cat for what its agent is doing and where — each chat and mission a link — and to put it to sleep or wake it,
open the chat, or change its look. Over each cat is a button with its name and status in words, so a status never
depends on colour and every cat can be reached from a keyboard.

It costs the daemon nothing: the page reads the status every five seconds while the tab is seen, draws only then, and
moves nothing for reduced motion. On a page narrower than the three rooms side by side — a phone — they stand one
above another beside a hall down the left, as wide as the screen. Its code and artwork
together are 29 KB as built, 11 KB compressed.

### A look for each agent

Every agent is a Nouride cat, drawn here in 32×32 pixel art, with a look of its own. An agent's page has a **Look**
tab, showing the cat as it will be — idle, waiting for you, asleep — with each part to pick:

| Part | Words |
|---|---|
| `fur` | ginger, grey, black, white, brown, cream |
| `pattern` | plain, tabby |
| `outfit` | none, hoodie, tee, jacket |
| `outfit_color` | blue, lime, peach, charcoal, sage, lilac, white — a hat and a scarf wear it too; white only when picked |
| `hat` | none, beanie, cap, beret, headband, headphones |
| `accessory` | none, glasses, sunglasses, scarf |
| `eyes` | round, sleepy, sparkly |

A part nobody picks comes from the agent's id, so an agent nobody styled keeps the look it always had, a rename does
not change it, and no two agents in one office are twins. What is picked is `[look]` in the agent's `config.toml`:

```toml
[look]
fur = "black"
outfit = "hoodie"
outfit_color = "lime"
hat = "beanie"
```

A word that is not one of its part's stops that agent from loading and says which words the part takes; the others
load. `POST /api/control/agents/:id/look` saves a look, operator and up, an empty part its id's again. 0.8.0 does not
read `[look]`, and warns about it as an unknown key — nor `[external]`: back on 0.8.0, an external agent answers with
its `[llm]` model until 0.8.1 is back.

### Fixed

A review of 0.8.0's and 0.8.1's work before this release found these; each has a test now.

- **What an agent may not do, it could not do by spelling.** A `nouride` call with `--json` before its verb — or
  `--json=` — passed the tool's refusals and the approval list, so any agent could install for every agent, schedule
  a shell command, answer approvals or turn an agent external, unasked. The call is classified as the CLI reads it.
  `nouride tools run` reads an installer's flags by name, `--flag=value` too, and refuses a path anywhere in a word.
- **Work nobody watches keeps its guards.** The second look is taken when nobody can be asked, not skipped; a helper
  that `delegate` gives such work runs under its guards and level; a scheduled job's turn put into its chat is never
  `trusted`; curl's attached and clustered short options (`-d@file`, `-sXPOST`) are read as sending. A proposal that
  changes another agent's job, or one reporting to another chat, is an admin's to turn on, and the old job's standing
  allowances go with the change; only a person answers a proposal, and a webhook's is an admin's; ten waiting
  proposals are counted by who proposed them. A job due while its agent is asleep is skipped, whatever it runs.
- **Missions.** A mission's turn the pipeline dropped — a pack's sender allowlist, the rate limit, a full queue — no
  longer holds it `running` for good; one stopped or deleted while its worktree is made stays so; a parent waiting on a
  mission it handed out is not stuck, and its child's end is on its page; only a restart that cut one of its turns
  counts toward failing it; a waiting mission resumes only on what answers its wait; a proposal's wait for the yes is
  not counted in its hours; a waiting mission still holds its repository; the week's sweep keeps a worktree with
  uncommitted work, and an agent in a worktree is told to commit; approvals a person answered are not read as expired.
- **External agents.** An update the CLI sends that no reader can take no longer stops Nouride reading it — the turn
  hung, and the CLI died at its next write; a stop that comes while the CLI starts is kept, and a CLI that does not
  stop when asked is stopped; the preset and model reach a conversation already going; the idle sweep leaves a CLI
  whose turn is opening its session; a sign-in check's session is closed, and a check still running answers a fresh
  ask; a mission's CLI session is let go when it ends; a shared account's token is hidden from the sign-in page
  however the terminal splits it; the daemon reads the agent's instruction file and skills list only as plain files —
  never through a link. Answering a question under a stopped turn is ACP's `cancelled`. A pack that named *Free in its
  folder* on Docker or macOS ran its CLI unasked as the daemon's user, which reads the database and the secret store;
  it asks as *Ask when risky* does there now, as the Brain tab said.
- **The daemon's own events** — a mission's turn, a job's end, an answered approval — pass a pack's sender allowlist
  and the rate limit: a background job's report was lost for an agent with an allowlist.
- **Another provider when one is down.** A provider that cannot be reached — refused, timed out, a stream dropped
  before its reply began — is answered by the next pair, and so is the turn's closing call.
- **Each agent its own user.** A daemon that is root runs its agents' commands as their own users (each failed);
  an agent's HOME is seeded once when it is readied twice at once; `write` and `edit` save into an agent's linked
  folders as the agent; `~/` in the file tools is the HOME its commands have; a mission's git runs with its agent's
  own HOME; a new agent's user reads the credentials only once its pack grants them.
- **An agent's stdio MCP servers run as its own user**, with its HOME and installs, started in its folder unless the
  server's block names a `cwd`. As the daemon's, a shell or file server given to one agent read the database and every
  other agent's folder. A server that kept its sign-in or settings in the daemon's HOME no longer finds them — the
  agent's user cannot read that folder: sign it in again for each agent, give it its token through `env_secrets`
  where it reads one, or copy what it saved into the agent's own folder.
- **Setup.** A new agent is an admin's to make, as its provider and its CLI are — operators see New Agent disabled;
  an agent's sign-in terminal is an admin's to see; an agent switched to another CLI drops the model named for the
  one before; a save that makes the orchestrator external is put back, and a start that finds one runs with no
  orchestrator, saying so, rather than refusing to start.

### Under the hood

- `@nouride/acp`, a package with no dependencies: the protocol both ways, the built-in CLIs as data.
- `/mcp` and the new `/mcp/agent` share one JSON-RPC handler. `/mcp/agent` answers loopback only, with a token a CLI's
  session was given.
- `/status` carries an agent's `external` CLI, account, model and the CLI's default. New routes: `GET
  /external-clis`, `GET` and `POST /agents/:id/cli`, `GET /agents/:id/cli/profiles`, `POST /agents/:id/cli/login` (and
  `/answer`, `/stop`), `POST /agents/:id/answered-by`, the accounts under `/cli-accounts`.
- New state files beside the database: `external-sessions.json`, `external-versions.json`, `external-models.json`,
  `cli-accounts.json`, and `agents-seen.json` —
  when the daemon first saw each agent, written at the first start of 0.8.1 for those already there and as each new
  one loads. `/status` carries it on each agent as `since`, the order the Office fills up in.
- The agents' status badge is shared by the Agents pages and the Office.

### Not in 0.8.1

- **Update CLI** as a button: the Brain tab and `nouride agents scan` say how to install each; updating it is the
  orchestrator's (`nouride tools run`) or yours, and the next start checks the new version.
- A question before what an external agent sends out under *Free in its folder* — a push, a POST, `ssh`: the CLI asks
  nothing in that preset. Use *Ask when risky* where that matters.
- **Antigravity.** Google's ACP server for it (1.4.3) stopped in its own start-up on the test box, a Linux container,
  before reading anything from Nouride, and its CLI (`agy` 1.4.7) has no ACP mode. It comes back once one of the two
  does.
