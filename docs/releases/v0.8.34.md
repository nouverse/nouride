**0.8.34 updates from 0.8.0 or later.** From 0.7.x, start 0.8.0 once first:
[Upgrading to 0.8](https://nouride.com/en/docs/deployment/upgrading-to-0-8/) has the way across.

On Docker, check your configuration with the new image before you switch:
`docker run --rm -v ./nouride:/app/.nouride ghcr.io/nouverse/nouride:0.8.34 nouride config check`, with the volume your
compose file mounts.

### Automations

- **Schedule and Webhooks are one page now: Automations.** Work → Automations lists everything that runs on its own,
  whatever starts it: on a schedule, when a webhook is called, or when you press Run now. One dropdown beside the
  search shows only the scheduled ones, the webhooks, or the ones you start by hand. Your schedules and webhooks are
  all there, as they were.
- **An automation can be several steps in a fixed order.** Send a message, ask an agent, run a command, start a
  mission, wait for your OK: as many as you need, in the order you put them. Nouride runs them in that order every
  time, hands each step what the one before it said, and an agent does only the step it is given. Before, work in
  several parts was one paragraph an agent carried out its own way each time.
- **A step can send the run somewhere else.** When a step is done, when it failed, and when it had nothing to say, the
  run goes on to the next step, ends there, or jumps to a later step. So a check can end quietly while all is well,
  and only wake an agent when something is wrong. A run only goes forward, so it always ends.
- **A mission can be a step, anywhere in the list.** The automation waits for it, however long it takes and across a
  restart, and hands its result to the next step.
- **A step can wait for your OK.** The automation's chat gets the question, what the step before said, and Continue
  and Stop. The same question is under Waiting for you. Nothing after it runs until you say yes; a no, or no answer in
  time, ends the run there without calling it a failure.
- **An automation you start yourself.** One with no schedule and no webhook, for work you want on a button.
- **The steps are drawn, and a run is drawn over them.** Each step is a card: press it to change it, drag it to move
  it, press the plus to add one. While it runs you see which step is at work, what each one said, and which path the
  run took.
- **An agent can make one for you.** Ask in a chat, and the agent proposes the automation with all its steps. It
  stays off until you turn it on, and a change an agent proposes to one that runs waits on its page as Suggested, with
  Accept and Discard.

### A chat on every page

- **Talk to an agent from any page.** A button on every page but Chats opens a small chat with one agent, the same
  conversation you have with it in Chats. The agent is told which page you are looking at, so on an automation's page
  "add a step that tells me on Telegram" is enough.
- **The Ask buttons open it.** A page's Ask button no longer takes you to Chats: it opens the chat where you are, with
  its message filled in for you to change or send. One automation's page has one too, for a change to that automation.
- **Start a new conversation there.** The chat opens on your newest conversation with the agent. The speech bubble
  with a plus, at the top of the chat, starts a new one.
- **The page follows the agent.** Ask for an automation from the page that makes one, and what the agent proposes
  opens there by itself, its steps drawn. On any page, what the agent made or changed shows without a reload, and a
  button under its answer opens it.
- **"Take me there."** In that chat the agent knows the dashboard's pages, so it can answer with a link to one. The
  link opens the page under the chat, in the same tab. In every chat on the dashboard, a link to one of its own pages
  is now a link you can press: it was drawn as plain words.
- **An answer that arrives in one piece is still written out.** Some models say nothing while they work and hand
  the whole answer over at the end. The chat showed that as nothing, then everything; it now writes it out like any
  other answer, and follows it down as it does.
- **A chat keeps you at the newest message.** Sending a message takes you to the end of the conversation, wherever
  you were reading; it used to leave you where you were, with your own message out of sight. A long answer no longer
  makes the chat stop following it. On the Chats page, a small arrow at the foot of the conversation takes you back
  to the newest message once you have scrolled up.

### From the command line

- `nouride cron add --steps <file.json>` and `nouride cron update <id> --steps <file.json>` take a list of steps from a
  file. `--manual` makes an automation you start yourself. `nouride cron runs <id>` says how each step of a run went,
  and `nouride cron continue <run id>` or `stop <run id>` answers a run that waits for a person.

### A group, or a topic, for one agent

- **`/mention @YourBot` gives a group to one agent.** In a group with several of your agents, a message that tags
  nobody was always the orchestrator's. Now an admin can type `/mention @NovelistBot` (or the agent's name) in the
  group, and that agent answers every message there that tags nobody. In a Telegram group with topics, each topic can
  have its own agent. A tag and a reply still go to whoever they name.
- **`/mention required` replaces `/mention on`,** and `/mention off` is gone from the help: one setting now says
  both whether a tag is needed and who answers without one. The old words still work.
- **`/mention@YourBot`, as Telegram's command menu writes it, is answered by that bot.** It was answered by the
  orchestrator, which read as the wrong agent taking over. The answer says how to give the group to that agent.
- **The same choice is on the Groups page:** one list per group, "who answers a message that tags nobody".
- **An agent keeps one conversation in a group.** Where several of your bots sit in one group, a message that tagged
  nobody, or named an agent in its words, could be answered in a conversation kept under another bot, apart from
  the one the agent has when it is tagged, so it did not remember what was just said. It is one conversation now.
- **A command written with a bot's tag in front (`@Nox /status`), as on Discord, is answered once, as a command.**
  With several bots in the channel it could reach the agent as an ordinary message instead.
- **`/secret undo` in a group of several bots puts the message back for the agent that answers there.** It was
  read again in a conversation kept under another bot, and in a Telegram group that is not a supergroup, by nobody.

### Models that take no temperature

- **Claude Sonnet 5.5 and Claude Haiku 5.5 answer again on Anthropic's own API.** Nouride sends a temperature with
  every request, and these models refuse one, so every message to an agent on them got "Something is wrong with how
  I am building requests". A model that refuses the temperature is now asked again without it and sent none from
  then on, on any provider. Summaries of a long conversation and what an agent learns from its chats failed the same
  way, and work again too. Nothing to set: the temperature in your settings still reaches every model that takes one.

### A new install asks less

- **A new install is `balanced` throughout.** The agents setup makes were already `balanced`: they run by
  themselves and ask only before the few things that matter (changing settings, giving someone access, stopping
  Nouride, replacing a stored secret, a credential leaving the machine, changing its system packages). The level
  for the install as a whole, which an agent that sets none of its own falls to, was written `careful`, and is
  `balanced` now. An install you already have keeps what its settings say.

### Before you upgrade

Nothing to do. Every schedule and webhook is on the Automations page as an automation of one step, with the same
address, the same history and the same `nouride cron` and `nouride webhook` commands. Links to the old Schedule and
Webhooks pages open Automations.
