**0.8.39 updates from 0.8.0 or later.** From 0.7.x, start 0.8.0 once first:
[Upgrading to 0.8](https://nouride.com/en/docs/deployment/upgrading-to-0-8/) has the way across.

On Docker, check your configuration with the new image before you switch:
`docker run --rm -v ./nouride:/app/.nouride ghcr.io/nouverse/nouride:0.8.39 nouride config check`, with the volume your
compose file mounts.

A release about what an agent makes. A formula, a diagram, a picture written as SVG and a page of HTML are now shown
in the dashboard as what they are, where they used to be shown as code. The files of one reply open as one set and
download in one go. With it: rooms where you pick who answers and where an agent asked by another answers for itself,
missions that are named, ask when they have a question and show that a long turn is alive, and a dashboard checked
page by page on a phone.

### What an agent wrote is drawn, not left as code

An agent that wrote a formula, a diagram or a picture gave you its source, in a grey block.

- **Formulas are typeset.** In a line: `$E = mc^2$` or `\(..\)`. On lines of their own: `$$..$$`, `\[..\]`, or a code
  block named `math` or `latex`. A price stays text: "$5 and $10" is not a formula.
- **A diagram is drawn.** A code block named `mermaid` (a flowchart, a sequence, a mindmap and Mermaid's other kinds)
  is its diagram, in the colours of the look you are on.
- **A picture written as SVG is drawn.** A code block named `svg` is the picture, on a white card in both looks.
- **Each keeps its code a press away.** The block's head switches between the drawing and **Code**, and **Copy** copies
  what the agent wrote, whichever shows. A diagram or a picture opens large on a press, and can be saved from there.
- **What cannot be drawn stays code**, with no error box: a diagram with a mistake in it, a formula that is not one.
- **A wide table shows there is more to its side**: its edge is shaded where it goes on, and each column keeps a
  readable width, on a phone and on a laptop alike: the table scrolls sideways in its box, where a wide table used to
  squeeze every word onto a line of its own.
- **Everywhere an agent's text is read**: a chat, a mission's result, a job's report, notes, a file in Files and the
  Workspace, a memory document. **Save as PDF** on a Markdown file carries the pictures and the formulas.
- **Nothing an agent wrote runs in the page.** A picture and a diagram are shown as images, and a script inside one
  does nothing.
- The diagram viewer is loaded the first time a reply holds a diagram, so a chat without one loads no more than
  before. It makes the dashboard's files on disk about 9 MB larger.

### A page of HTML an agent wrote can be looked at

A mockup an agent wrote as HTML was its source. To see it you saved it and opened it somewhere else.

- **An `html` block of a reply is drawn in the chat as the page it is**, in the reply itself, as tall as the page up
  to a limit. Its head switches between **Preview** and **Code**, and a link opens the page in a tab of its own.
- **HTML an agent wrote straight into its reply is such a block too.** Asked to "write some HTML here", an agent often
  writes the tags as they are, with no code block around them. They were lines of tags in the text.
- **An `.html` file in Files and the Workspace has Preview**, which opens the page over the dashboard when you press
  it. **Open in a tab** gives it a tab of its own.
- **The page is held apart from Nouride.** It can show what is written in it and run its own scripts. It cannot read
  your sign-in or the dashboard around it, cannot reach Nouride or the internet, cannot open a window or send a form.
  A page that loads pictures or fonts from the web shows without them.
- A reply still being written shows the block as code until it is over, a mission's report keeps it as code, and a
  page larger than 2 MB is not drawn.

### The files of one reply are one set

A carousel an agent sent was eight loose pictures, opened and saved one at a time.

- **Pictures of one reply open as a set.** The arrow keys, a button on each side and a swipe go to the next one, and
  "4 / 8" says where you are.
- **Download all** under a reply with two files or more saves them as one `.zip`.
- **A Markdown file sent to a chat app comes with a link that opens it as a page**, with its headings, tables and
  diagrams drawn. The link is written for an admin, and only where `[dashboard] public_url` is set, as every link to
  the dashboard is.

### Rooms: pick who answers, and an asked agent answers for itself

- **Who answers a message that tags nobody is picked in the room's header**, for a room made in the dashboard: the
  default, a tag is needed, or one of its agents. On a phone it is in the room's menu. The Groups page picks for such a
  room too. Before, it could only be typed as `/mention`.
- **`/mention` typed in such a room is answered in the room.** Its answer did not show there, and an admin's change was
  refused.
- **An agent asked by another answers in the room itself.** When one agent asks another that is in the same room, the
  answer is now also that agent's own message there, above the reply of the agent that asked. Before, the first agent
  retold it. In a group on Telegram, Discord or WhatsApp it comes from the asked agent's own bot, where it has one in
  the group; a one-to-one chat is as it was.

### Missions: named, asking when they have a question, and alive while they work

A mission that a coding CLI works on (Claude Code, Codex) is often one turn of hours, and most of what a mission said
was said at a turn's end. So a question could wait for hours, and the page read "0 turns" the whole time.

- **A mission has a name**, apart from its goal: a few words. An agent gives one when it starts a mission, and the
  dashboard's form has a **Name** field. The missions you already have are named from the first sentence of their goal.
  Notices, the list, the cards and `nouride mission` show the name.
- **A question reaches you when it is asked**, with its buttons, and no longer at the turn's end. A mission can ask and
  go on with work that does not depend on the answer: the notice says it works on meanwhile, and your answer is handed
  to the work in progress. One question is open at a time.
- **A waiting card says what is waited for**: a question with the question, a result to accept, a draft not started
  yet, a limit reached. Every one of them used to read "Waiting for your answer". A mission at work that asked is among
  what waits for you, marked **Working · asked a question**, and its page has the question and a box to answer it.
- **A long turn shows it is alive.** What the turn at work has spent so far is shown, as an estimate, and the mission's
  card says when its last step was ("last step 7 min ago"). The notice at 80% of a limit now comes during a long turn,
  where it used to come only after the limit had already stopped it.
- **A stopped mission keeps what its last turn spent.** One stopped in the middle of a long turn read "0 turns" and
  unknown tokens. Its notice now also names the work it left that nobody committed, with the branch.
- **A mission's question goes to the chat it reports to.** When a mission sent a message itself, the chat it reports to
  was one of many in the list, with nothing to mark it. It is now first and marked, and the conversation a mission keeps
  for its own work is no longer offered as a chat to send to.

### The dashboard on a phone

Every page of the menu, and what each opens, was measured at a phone's width in a real browser. What follows is what
that found, and what was asked for before it.

- **Every panel that comes up from the foot of the screen is one kind of sheet**: its name, a close button, and a swipe
  down on its head closes it. "Add a step" on an automation had neither.
- **The tab bar goes away as you scroll down** and is back at the first scroll up, so a page has the whole screen.
- **No empty band under the message box** in a chat.
- **Home's use by route reads as rows on a phone**, as Groups, People, Users and the audit log do. It used to scroll
  sideways inside its card.
- **What you press is large enough for a finger**, on every page of the menu. Links that were a line of small text,
  small pills, the rows of an agent's tool list, a switch on its own and the round buttons inside a field were smaller.
- **Logs: the component filter is readable.** On a phone it was squeezed to its arrow, with no words.
- **A button keeps its words on one line**: "Save automation" broke in two inside its button.
- **Inside Nouride Home, the pages with no header have the way back to the app**: the sign-in, the setup and the
  welcome page, in the corner where the header's button is on every other page. The phone's back gesture was the only
  way out of them.

### Fixes

- **Home's cards keep a long word inside them.** A mission with a long goal, or a file's path in it, ran out of its card
  and under the one beside it.
- **System says how much memory is in use on a Mac.** It read "not something Nouride can tell here": only Linux's own
  figures were read. It is now what the system counts as held, close to Activity Monitor's "Memory Used".
- **The setup wizard's model field lists the models as it takes the focus**, in a wide window. It listed none until
  something was typed, so a person making their first agent had nothing to pick from. On a phone it waits for typing,
  as before: the keyboard there moves a list opened on focus.
