**0.8.37 updates from 0.8.0 or later.** From 0.7.x, start 0.8.0 once first:
[Upgrading to 0.8](https://nouride.com/en/docs/deployment/upgrading-to-0-8/) has the way across.

On Docker, check your configuration with the new image before you switch:
`docker run --rm -v ./nouride:/app/.nouride ghcr.io/nouverse/nouride:0.8.37 nouride config check`, with the volume your
compose file mounts.

A small release of fixes, for steadiness.

### An agent keeps its full context window after a restart

Nouride learns each model's context window from the provider's own list of models, when the provider states one, as
Nougate and OpenRouter do. Until that list was back after a restart, and while it could not be read, a turn was sized
by a guess from the model's name: 200,000 tokens for Claude Opus 5.5, which Nougate lists at a million. The first
messages after every restart, the ones that waited while Nouride was down among them, ran in a fifth of their room. In
a long coding session that meant the conversation summed up early, and a file the agent had just read cut from it.

- **What the provider last said is kept across a restart**, and used until the provider says something new. While its
  list cannot be read, it is used too, instead of the guess.
- **Only for the same address.** A provider moved to another address starts from its new list.
- Nothing to set. A `context_window` in an agent's `[llm]` still wins over both.

### Why a mission could not start is in the log

When an agent's `mission` call is refused (a start without the person's own words, a draft that is not its own, a file
outside the mission's folder), the agent is told why and tries again. The log said only that it failed. It now says
**"mission call refused"**, with the agent, the chat, what was asked, and the words the agent was given.
