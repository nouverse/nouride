**0.8.39 updates from 0.8.0 or later.** From 0.7.x, start 0.8.0 once first:
[Upgrading to 0.8](https://nouride.com/en/docs/deployment/upgrading-to-0-8/) has the way across.

On Docker, check your configuration with the new image before you switch:
`docker run --rm -v ./nouride:/app/.nouride ghcr.io/nouverse/nouride:0.8.39 nouride config check`, with the volume your
compose file mounts.

A release about agents working together: several steps of an automation at the same time, what one agent did for
another reaching both of them, and one list of public skills to search, with Nouverse's picks first.

### Skills: one list to search, Nouverse's picks first

Finding a skill somebody else wrote used to ask three public hubs and mix what came back, in no order of ours.

- **Explore on Skills, `nouride skills search` and an agent's `skill_search` now ask one list**: Nouverse's list of
  public skills, which holds ClawHub's listing and the skills of the repositories Nouverse lists, in one order.
- **Explore opens on Nouverse's picks**, each marked with a badge, before you type a word. A search runs when you
  press **Search**; a result says where it is from, who made it and how much it is used, and the line over the list
  says how many matched.
- **Installing is unchanged.** A result is fetched from where its author published it, ClawHub's scan is read where
  there is one, and it waits as a draft on the Pending tab until you approve it. Nothing runs before that.
- **When the list cannot be reached, the hubs are asked directly**, as before, and the answer says so. A hub can
  still be asked by name from the command line and by an agent (`--source`, the tool's `source`).
- [`NOURIDE_SKILLS_CATALOG_URL`](https://nouride.com/en/docs/reference/environment/) names another list, or, set
  empty, none: then every search asks the hubs.

### Automations: several steps at the same time

One automation can now ask several agents at once and put their answers together.

- **A step can hold two to five parts that start together**: agents' turns, one for each agent, and commands. The step
  ends when the last of them has.
- **What each part said is joined, each under its name**, and handed to the next step, or sent as the run's report
  when the step is the last. No model sits between: three agents asked the same morning question are three answers.
- **A part that fails makes the step's failed exit**, with what the others said kept beside the reason, so a step
  after it has both. All of them saying nothing is the step's empty exit.
- **It is made where steps are made**: the dashboard's step editor ("Several at the same time") and an agent's
  `schedule`. A run shows each part with how long it took and how its answer began, on the automation's page and in
  `nouride cron runs`.
- How many turns really run at the same moment is still `[queue] max_concurrent_turns`: parts past it wait their
  turn inside the step.

### What one agent did for another reaches both of them

When an agent asks another for something, or starts a mission for it, the report goes back to the one that asked.
That used to be all of it.

- **The agent that did the work is told of it in its own chats.** Before, it had no trace there of work it had just
  done for another agent, so when you spoke of it in your own chat with it, it read it as news and started from
  nothing. For a day after such work ends it is told what it did, for which agent and how it ended.
- **The agent that asked is told what followed.** Once the other agent has answered you in a private chat of its
  own, the one that asked is told, on its next turn for you, that the two of you talked and how that answer began.
- **Each person's chats stay their own.** The words go only where you are the same person, or in the chat the work
  was asked from. Anywhere else an agent is told only that it did a job for another agent, and when. What is said in
  a room is never carried out of it.
