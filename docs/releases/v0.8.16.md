**0.8.16 updates from 0.8.0 or later.** From 0.7.x, start 0.8.0 once first:
[Upgrading to 0.8](https://nouride.com/en/docs/deployment/upgrading-to-0-8/) has the way across.

No database migration. The event protocol is unchanged, 1.7.

On Docker, check your configuration with the new image before you switch:
`docker run --rm -v ./nouride:/app/.nouride ghcr.io/nouverse/nouride:0.8.16 nouride config check`, with the volume your
compose file mounts.

### Claude Code and Codex agents

- **`/effort` sets how long the CLI thinks, for one chat.** `/effort high` takes effect from the next message, over the
  agent's own effort, on the session already running, so the CLI keeps the conversation. Only a level the CLI offers
  for the model it is on is taken, and the others are refused with the ones it offers. `/effort` alone says the level
  now; `/effort default` puts back the agent's, or the CLI's own. For an agent its own model answers, `/effort` says
  where its effort is set.
- **They open a fresh session at their first turn after the update,** as they do whenever what they are told changes.

### Dashboard

- **A fresh chat greets you with the agent's own cat,** as its Look draws it in the Office, instead of Nouride's
  mascot. A room keeps Nouride's.

### Skills

- **A skill learned on its own is announced with its reason cut at a word.** The reason was cut at 200 characters
  wherever that fell, mid-word, right above `/drafts show`.
- **The example pack names Claude 5 models.**

### Nougate

- **A custom provider's model can be switched off.** Its row in the Models table has an On switch: off stops serving
  it, and "Auto-load from upstream" no longer brings it back. The table could only remove a model, and the next
  auto-load imported it again, so an aggregator kept listing a model you did not want.
- **A save through the API changes only the fields it states.** A model's price written alone reset the context window
  its upstream had stated, its output limit and its thinking setting, and switched it back on if it was off. `null`
  still clears a field.
