**0.8.13 updates from 0.8.0 or later.** From 0.7.x, start 0.8.0 once first:
[Upgrading to 0.8](https://nouride.com/en/docs/deployment/upgrading-to-0-8/) has the way across.

One database migration (074): three counts on a mission's record, below. It runs at the first boot on 0.8.13.

On Docker, check your configuration with the new image before you switch:
`docker run --rm -v ./nouride:/app/.nouride ghcr.io/nouverse/nouride:0.8.13 nouride config check`, with the volume your
compose file mounts.

### Missions

- **Delete an ended mission** from its page or with `nouride mission delete <id>`. Its record, its conversation and
  the folder Nouride made for it go; a folder you named and the mission's branch stay. One still running is refused —
  Stop it first — and work in its folder nobody committed is named, and deleted only when you ask again
  (`--force`).
- **A mission run by Claude Code or Codex keeps its token count across a restart.** After one, a mission that had
  counted nothing showed "tokens unknown", one that reported for some turns only showed a full count instead of "at
  least", and its helpers' tokens were counted again at the next turn — a count that only grew, and a token limit
  reached early. An ended mission lost "at least" at once.
- **An English brief may carry a table or a code block in another language.** A translation's brief, with the
  Indonesian strings it was about in a table, was refused as not English.

### Approvals and personas

- **A question in a chat shows what a file change does** — a persona's diff, a new file's size — not the call's
  arguments as JSON. An admin answering from Telegram had never seen the diff of a persona change.
- **A persona diff reads as the file does:** a table row under its header, a long rule's later lines shown once and
  unchanged when only its first line was reworded, a nested rule under its own label, and `-->` in prose not taken
  for the end of a comment.
- **What an admin approved is checked after a restart too.** A restart between the question and the yes forgot which
  file the diff was made from, so the write went over whatever the file had become, the admin's own edit included.
  The diff's file is now kept with the question.
- **A shell command that writes an agent's persona is asked of an admin,** as the persona tool's change is — `sed -i`
  on its own SOUL.md by a path from its workspace too. Where agents run as the daemon's user (Docker, macOS, an
  install without the helper), it ran with nobody asked.

### Chats

- **`/status` counts a conversation's first turn.** Right after an agent answered — a coding CLI said it most
  plainly — `/status` said "Tokens: none reported".
- **On Telegram, the line above a code block stays on its own line;** it ran into the block's first line.

### Fewer tokens

- **Old tool output leaves the conversation.** At a turn's start, a tool's output older than the last two turns is
  replaced by a short marker, its whole text kept in a file the agent can open again. It happens only when the
  provider's cache was lost anyway — the agent's prompt, model or tools changed, or an hour passed — or when 16k tokens
  or more can go, so a warm cache is not thrown away for a little.
- **The usage card on the home page shows each route** — provider profile and model — over the last week: requests,
  input, how much of it came from the cache, and the cost a million input. A route that caches under half of what
  another route of the same model does is named with what each costs. On one install, the same model cached 1 % of
  its input through one profile and 94 % through another.

### Skills

- **A skill changed on disk reaches every agent within a minute,** with no restart: a built-in skill updated, or one
  copied into the skills folder by hand. MCP servers are not touched.
- **An agent answered by Claude Code or Codex no longer wears a yellow "!"** on a skill whose tool is never given to a
  coding CLI (`nouride`, `update`). No pack edit could clear it; the Skills page now marks it apart, quietly, with why.

- **Every built-in skill says what it asks of the machine,** down to a 512 MB board. The heavy ones check the free
  memory before their heavy step — a browser, a slide render, a LaTeX build, a video render — and offer another of
  your machines when it is short, rather than a command killed halfway; the light ones say they run on a 512 MB board.

### Dashboard

- **Helpers & jobs is now Background Helpers,** in the menu and as the tab in System Logs.
- **The coding CLIs' card says plainly how an external agent runs:** inside the real CLI, signed in with its own
  login, over the Agent Client Protocol.

### Command line

- **A config file you may not read is one line,** in `nouride db`, `doctor`, `stop` and every command that reads the
  config itself — an agent's own user cannot read the service's. They printed the read error's stack trace.
