**0.8.14 updates from 0.8.0 or later.** From 0.7.x, start 0.8.0 once first:
[Upgrading to 0.8](https://nouride.com/en/docs/deployment/upgrading-to-0-8/) has the way across.

No database migration. The event protocol is unchanged, 1.7.

On Docker, check your configuration with the new image before you switch:
`docker run --rm -v ./nouride:/app/.nouride ghcr.io/nouverse/nouride:0.8.14 nouride config check`, with the volume your
compose file mounts.

### When a model fails partway

- **A failure the provider names in its answer is that failure, not an empty answer.** A gateway reports its
  upstream's failure inside the stream it had already started: an OpenAI-style `error`, or Anthropic's `error` event.
  Nouride read past it, and an agent answered "I did not manage to produce an answer" to every message, with nothing in
  the log saying why. Now a server error is asked again and an agent's fallback can answer it, a rate limit waits, and
  the provider's own words are in the log.
- **A conversation too long for the model's route is answered without its older half.** After an overflow the request
  was retried at half the model's window as listed. Behind a route that allows less, half of that was more than the
  whole conversation, so nothing was left out and the turn failed. The retry is now half of what was sent.
- **When even that is too long, the reply says so** and names `/compact` and `/new`. It used to say "I trimmed the
  oldest part and carried on" after a turn that had ended without an answer.

### LLM Gateway (router and Pro)

- **Codex's failures reach the agent as failures.** Codex reports a request it will not finish (its window exceeded, a
  usage limit, its own server error) inside an answer that began as a success, and the gateway passed it on as a
  finished, empty reply. A failure before the answer begins is now answered with its status: a window exceeded is a
  400, and a usage limit moves the request to the next Codex account. A failure after the answer began ends the stream
  with an error. Both are logged with Codex's own code and words.
- **Codex's parallel tool calls carry their arguments.** For calls Codex makes several at once it sends no stream of
  arguments, only each call's whole arguments as the call closes. They reached the agent empty, and each call failed
  for want of them.
- **An answer Codex cut at its output limit says `length`**, with its usage, instead of reading as finished.
- **A server's failure is labelled as one**, `server_error` (Anthropic clients: `api_error`). It was labelled
  `invalid_request_error`, which a client reads as a request it built wrong and does not retry.
