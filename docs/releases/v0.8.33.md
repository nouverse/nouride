**0.8.33 updates from 0.8.0 or later.** From 0.7.x, start 0.8.0 once first:
[Upgrading to 0.8](https://nouride.com/en/docs/deployment/upgrading-to-0-8/) has the way across.

On Docker, check your configuration with the new image before you switch:
`docker run --rm -v ./nouride:/app/.nouride ghcr.io/nouverse/nouride:0.8.33 nouride config check`, with the volume your
compose file mounts.

### Agents that know what the others are doing

- **An agent in a room knows what the other agents there are doing.** When you ask one, it is told which of the others
  are at work in that room, on which request and for how long, and which are asleep. Before, it knew who shared the
  room and what each was for, and nothing about what they were doing at that moment.
- **And what else is running on the box.** Its own work in other chats, helpers, missions and background commands
  with their folder, six at most and the rest counted, so it can wait or work somewhere else before it starts a build
  beside another one. Work somebody else asked for in a private chat is named without its words. This tells the
  agent and locks nothing.
- **Work handed to a busy agent is no longer lost.** When one agent tagged another that was already at work in the
  room, the room was told to ask again and the work stopped there. Now the hand-over waits: the room is told once,
  and the busy agent takes it as soon as it is free. Two hand-overs from the same agent become one turn. A message
  from a person to a busy agent is answered as before.
- **A way on when work stops in a room.** When agents have gone back and forth as many times as allowed, the line
  that says so has a **Continue** button. When an agent that was handed work fails or runs out of time, its line has
  **Continue** and **Hand to** another agent of the room. On Telegram and Discord these are buttons; elsewhere the
  line says the same in words. Anyone who may talk to that agent in the room can press, once.

### Fixes

- **A chat's progress line no longer says a reply is being written while the agent prepares another step.** After a
  step, an agent that said a few words and then wrote a long command to run had its line read "writing a reply" for
  as long as that took, and then ran another step. The line now says "writing a reply" only while the reply's text
  is arriving, "preparing the next step" while a command is being written, and "thinking" the rest of the time.

### Before you upgrade

Nothing to do. An agent's messages get one or two short lines only while something else is at work, and the fixed
part of its prompt is unchanged.
