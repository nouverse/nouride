**0.8.42 updates from 0.8.0 or later.** From 0.7.x, start 0.8.0 once first:
[Upgrading to 0.8](https://nouride.com/en/docs/deployment/upgrading-to-0-8/) has the way across.

On Docker, check your configuration with the new image before you switch:
`docker run --rm -v ./nouride:/app/.nouride ghcr.io/nouverse/nouride:0.8.42 nouride config check`, with the volume your
compose file mounts.

A release about an agent knowing what happened. It reads what its own missions told the chat, it learns skills from
work that comes back and from missions, and what it wrote beside a tool call is no longer lost.

### Skill learning that learns

An agent that worked out how to do something was meant to write it down as a skill. For somebody who talks to their
agent in one chat, it almost never did.

- **A new kind of work becomes a skill when it comes back in the same chat.** It waited for the work to turn up in
  another conversation, and one chat is one conversation for as long as you use it. Now the same chat counts, once the
  work was put down for six hours and picked up again.
- **A mission that ended done is looked at for a skill**, once, from its goal and its report. Only a chat's turns were
  looked at before, so the largest pieces of work taught an agent nothing.
- **A lesson changes a skill by an edit, not by writing the skill again.** The line it adds or corrects is the change;
  every other line stays word for word. Rewriting the whole skill for one new step pushed skills past their size and
  could drop a step nobody meant to touch.
- **A draft the daemon refuses goes back to the agent once, with the reason**, to be put right: an address becomes a
  placeholder, a long skill moves its detail to a file beside it. It was thrown away before, and the next try was
  thrown away for the same reason.
- **A skill is no longer refused for what it already held.** A skill that named an account could not be improved
  again: every revision was refused for the address its own text carried.
- **A skill the conversation read comes first.** A lesson about what that skill covers goes to it, not to a new one.
- **After a look that wrote nothing, the next one in that chat waits for twice the work.** A skill written, or the
  chat put down for six hours, sets it back.

### What learning holds, and why nothing came

The Skills page showed an empty queue and nothing else. Under the drafts on **Pending** there is now:

- **Seen once, not a skill yet.** Each kind of work an agent did once and is holding: when to use it, which agent saw
  it, how often and when last. **Write it now** has the agent write the skill from the conversation it was seen in,
  without waiting. **Forget** drops it.
- **What learning did lately.** The last twelve things it did or decided not to, each with its reason: "Looked, and
  found nothing to write down: a question answered, nothing done."
- **How often a skill is read** is on its row in **Live**: "read 12 times, 3 times since it was changed". Reads are
  counted from this release on.

The manual: [Skills](https://nouride.com/en/docs/manual/skills/).

### An agent knows what its missions told its chat

A mission's notices are sent under the agent's name, and the agent had not read them. Asked a minute after its
mission was done, an agent answered that the mission was still at work.

- **An agent reads back what its own missions told the chat**, with your next message there, once: queued, started,
  how far it is, what it needs from you, done.
- **Its newest progress line is the one it reads**, not every one in between.
- Another chat of the same agent is told nothing of it.

### What a mission left running ends with it

A mission's command that started something and did not wait for it left it running after the mission ended. On one
machine three build workers of a finished mission ran for eighteen hours.

- **What a mission's commands and background jobs left running is ended when the mission ends**, and the chat is told
  what was ended.
- **A program that set itself apart on purpose**, as a service or a process manager does, is left alone.
- This covers the commands Nouride runs for an agent. What a coding CLI started from its own shell is not seen by
  Nouride and is not ended.

### Let in a list, from the dashboard

- **Access has a "Let in a list" button on the Approved tab**, for an admin. Pick the connection, paste the list or
  choose a file, press **Check the list** to see how it would go with nothing written, then **Let N in**.
- It reads the same lines `nouride access allow --from` does.

### Fixes

- **Words an agent wrote beside a tool call are no longer lost.** An agent that wrote its whole report in the same
  step as a tool call, and then ended its turn on a full stop, sent nothing: the person was never told. Those words
  are now its answer. And more than one line written beside a tool call goes out at once; only a one-line status is
  held back for two minutes.
- **A helper's brief is as long as the work needs.** A brief past 6,000 characters was refused, and the agent was
  told to write less.
- **A coding CLI is told a once-only note once.** An agent on Claude Code or Codex was given the same note again with
  each message of the conversation.
