### Long work

- **Work notes: an agent keeps its place in long work.** Each chat has notes the agent writes itself — a section per task: the goal, what is done, what is next, the rules you set, the facts it found. They are shown to the agent at every step and are never summarized, trimmed or dropped by the nightly rollover, `/new` or a restart, so a task that runs for hours does not lose which step it was on. `/notes` shows them, `/notes clear` empties them, `/reset` clears them and says how many tasks went. A task nobody has touched for two weeks is set aside to an archive, and the agent is told.
- **A plan lasts as long as the work.** `plan` keeps its steps with a task in the notes while steps are left — through "confirm first" and an answer an hour later — and a step dropped is marked skipped with why. The chat's progress line says where the plan stands: "step 3 of 8: …".
- **An agent eight steps into long work with no notes is asked to write them**, once — a weaker model forgets the habit, the harness does not.
- **One piece of work stays one task in the notes.** An agent that writes a third task is shown the ones it has and told that a task's progress goes in its own section; a write refused for size says how much each task takes. Before, an audit's status updates each became a task of their own until the notes were full.
- **A background job whose log has gone quiet says whether it is still working.** The "still running" notices now say how much CPU the job used and how much it read or wrote since the last one, so a job writing to a file of its own — Claude Code run in the background — reads as working, and one that does nothing reads as waiting or stuck, without the agent checking by hand.
- **A helper or another agent asked to help gets a copy of the task it is part of** — read-only, and only that task: the agent that asked keeps the notes.
- **The chat page shows the agent's work notes beside the conversation**, each task with its plan and how far along it is, read again when a turn ends. An operator can correct them in place; a change that is too big or holds a credential is refused with the reason.

### Chat

- **A reply to an agent reaches it, wherever you are.** Hitting reply on what an agent said addresses it as plainly as a tag — in a WhatsApp group now as on Telegram and Discord, and still after a `/reset`, a `/new`, the nightly rollover or a restart. Before, a reply to an answer from before any of those went unanswered in a group that needs a mention, until the agent was tagged.
- **The first message of a new day in a group is answered, not questioned.** After the nightly rollover, an agent's first message in a group carried the question it had answered the evening before, marked as one it "was not addressed in", and the background note spoke of "the message you were tagged in" — so the front desk, answering a message that tags nobody, replied that nobody had asked it anything. A message an agent answered is never shown to it as background again, and the note speaks of the message being answered.
- **A reply goes to the agent you replied to, and the front desk stays quiet.** In a group where nobody needs tagging and the orchestrator answers what is addressed to nobody, a reply to another agent's message was answered by the orchestrator — Telegram shows a reply to a bot's message to that bot alone, and in a basic group each bot numbers messages its own way, so the agent replied to mistook the message for someone else's. Now the agent you replied to answers, the front desk waits a moment and stands back, and a reply that also tags another agent is answered by both — on every platform.
- `/reset` and `/new` say what they cleared: how many turns, messages and tokens.

### Models

- **`effort` sets how long a thinking model thinks before it answers** — `low`, `medium`, `high`, `xhigh` or `max`, for every agent in `[llm.defaults]` or for one in its own `[llm]`. Unset, the provider decides, as before. Claude Sonnet 5.5 at its default thinks for about twenty seconds before a short answer, and the chat shows nothing while it does; at `medium` the answer starts in about two, with a sixth of the tokens. A model that does not take it — one that does not reason, an older Claude, a level its endpoint does not know — is asked again without it and sent none from then on, and the log says so once; Gemini through Nougate takes it and keeps Nougate's own setting.
- **The bundled LLM gateway no longer offers Gemini 3.6 Flash or Gemini 3.7 Flash.** Gemini 3.8 Flash replaces both; a config that names either should name `gemini-3.8-flash` instead.
- **A conversation's cached prompt survives a change of speaker and a turn's last word.** Who is speaking now comes after the conversation instead of in front of it, so a system event in a direct chat, or another person in a group, no longer has the whole conversation written to the cache again — 70,000 to 120,000 tokens each time on the live box. A turn's closing answer keeps the tools in its request, offered and not to be called, so it reads the cache the turn built instead of starting it over. Text in a message that imitates the daemon's own sections is made inert before it reaches the model.

### Runtime

- **Built on Bun 1.4.4.** It carries the Brotli 1.2.1 fix for an out-of-bounds write in decoding (CVE-2026-111497): every request the daemon makes asks for Brotli and decodes the answer, so any server it reached — a page an agent fetched included — could send a stream that triggered it. 1.4.4 also carries the current root certificates with the revoked eMudhra keys blocked.

### WhatsApp

- **WhatsApp comes back by itself after the internet drops.** When the connection stayed down long enough for the WhatsApp link to give up, the restarted link never connected again: no message arrived and no reply went out until the daemon was restarted, while the gateway still showed as connected. Now a restart reconnects, a number that has been offline for more than three minutes shows as down and is restarted, and replies written while it was offline are kept and sent once the number is back instead of being dropped.

### Credentials sent in chat

- **A token sent in chat and handed to a `nouride` command reaches it as the token.** A credential you send is replaced by a `$TMP_SECRET_…` handle; given to `gateway add --stdin` or `secret set --stdin`, the handle was stored as written instead of its value — two Telegram bots added that way were refused with "Not Found". The handle is now replaced by its value there, and the secret store refuses to keep a handle as a credential.
- **In a group with several of our bots, a token is taken once and said once.** Each bot's copy of the message used to take it again: two notices, one from a bot that was not the group's lead, with different handles for the same token. Now the group holds it once, the notice comes from the orchestrator's bot, and the agent that answers uses the handle you were told.

### MCP

- **Reloading an agent no longer leaves an MCP server running behind it.** A stdio server is stopped in the order the MCP spec gives — its input closed, then asked to stop, then stopped — with a limit on every wait, and together with what it started. Before, a server that ignored the request to stop while its input was open (`mcp-atlassian`) was waited for without end: `nouride agent reload` connected nothing, the next reload connected everything, and each such pair left one more copy of the server running until the daemon restarted (#11).

### Memory

- **The helper model card says what the helper model does and whether it works.** The Memory settings name the model that summarizes long conversations and runs the nightly memory pass, and show "Working" or what has been failing.
- **A helper warning clears when the trouble is over** — once its job works again, once its model answers again, or once its model is no longer the one set — instead of staying for a day, and an old model's failures are no longer put on the new one.

### Skills

- **A skill review on an Anthropic profile reads its instructions again.** The review after a turn — and a conversation summary that falls back to the agent's own model — sends its instruction as a system message, which the Anthropic client left out instead of moving it to the request's system prompt. The model answered the transcript in prose, and the review saved nothing.
- **A skill an agent revises is written at the model's own output limit**, so a long skill is no longer cut off part-way. An answer that is cut at the limit says so in the log instead of reading as "did not answer with JSON".

### Long work

- **Every model call says why it ended.** `nouride turns show` gives each call the reason its provider gave — `stop`, `tool_calls`, `max_tokens` when the reply was cut at the output limit, or `error` — so a reply cut short is read off the record instead of guessed from a token count. A call the provider gave no reason for says nothing rather than a guess.
- **Work handed to the background keeps a record of its own.** A helper working in the background, or an agent asked with `ask_agent` once it moves there, is recorded like a chat turn: `nouride turns show` lists its steps, the reminders it read, and the report it handed back, and the turn that started it lists it. Its job's log names the record.
- **A reminder that a run has gone long is on record when it is read.** Each "you have been on this for 5 minutes" note shows up as a step of the turn that read it — a reply you are waiting on, a helper, or an agent asked — so whether it reached the work is read, not guessed. It stays out of the chat.
- **Each request to the model says what it carried.** `nouride turns show` lists, for every request of a turn, about how many tokens it was, how many earlier tool results had been cleared out of it and where they were kept, and whether a summary of earlier conversation was in it — the request itself is not stored.
- **The dashboard shows the same under a finished answer.** Opening the steps under an answer lists each model call and why it ended — a reply cut at the output limit marked — what each request carried, and the work handed to the background, each of which opens to its own steps and report.
