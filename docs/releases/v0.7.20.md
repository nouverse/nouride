### macOS

- **Nouride runs on a Mac with Apple Silicon.** A `darwin-arm64` build of the free and Router editions is published beside the Linux ones, and `install.sh` installs it as a LaunchAgent: `curl -fsSL https://get.nouride.com/install.sh | sh` — no `sudo` on a Mac. Intel Macs are not a published target. What a port of 0.7.10 found missing ([nouride-releases#7](https://github.com/nouverse/nouride-releases/issues/7)) is in: the installer asks for a LaunchAgent by name and creates the data directory before it starts, so the first boot's admin password is never lost; the LaunchAgent has a `PATH` with Homebrew first and the same umask as the Linux service; a command that times out or is stopped takes its whole process group with it; an agent's terminal sessions get a real terminal; and `nouride status` works from any directory.
- **An update never installs a build for another machine.** `nouride update` checks the platform and architecture the running process reports — not what its build was told — before it downloads, and the downloaded binary's own header before it swaps anything.

### Nouride Box and Pro

- **One Pro edition, with the LLM gateway in it.** Pro Router is Pro now: every Box runs the same build, and the gateway is there for a Box that must answer without a network — on with `[nougate] in_process = true`, off otherwise, at about half a megabyte and a megabyte and a half of memory when off. **Nothing to do on a Box:** a Pro Router box is offered this release under the name it asks for, and reports Pro after the update. One that used the gateway without writing `in_process` keeps it on: the first start writes `in_process = true` into `config.toml`, the old file kept beside it.

### The CLI

- **`nouride status` and every command find the daemon on the port it runs on.** The CLI read only `config.toml`'s port, so a daemon started on another — `--port` at install, `PORT` in the install's `.env`, or a container run with `-e PORT=…` — was looked for on 18254 and reported down. It reads the install's `.env` now, and inside the container image the container's `PORT`.

### Releases

- **The public tarballs are started on their own platform before a release is published, and the public images are built natively for each architecture.** Each free and Router tarball — Linux x64 and arm64, glibc and musl, and macOS — is unpacked and run on a machine of its kind, and asked its version, `/health` and `nouride status`; the `nouride` and `nouride-router` images are built for amd64 and arm64 on their own hardware rather than under emulation, and hold the exact bundle the release signed. The release appears once all of that passed, a little later than the Pro editions. Nothing changes in how you install or update.
- **The Docker docs follow the latest image.** Every compose file and `docker run` line names `ghcr.io/nouverse/nouride` with no tag, so a new install starts on the newest release. A container already on `:0.7` keeps working; change it to the plain image name when you next edit the compose file.
