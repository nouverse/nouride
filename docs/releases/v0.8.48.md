**0.8.48 updates from 0.8.0 or later.** From 0.7.x, start 0.8.0 once first:
[Upgrading to 0.8](https://nouride.com/en/docs/deployment/upgrading-to-0-8/) has the way across.

On Docker, check your configuration with the new image before you switch:
`docker run --rm -v ./nouride:/app/.nouride ghcr.io/nouverse/nouride:0.8.48 nouride config check`, with the volume your
compose file mounts.

### An agent anyone can talk to

A shop's front desk, a help line, a bot for a community: an agent that answers whoever writes to it, with no pairing
code. Until now the only way was to open the whole install, which meant every agent answered everyone, and Nouride
refused to start that way beside an agent that could run commands.

- **Open is one agent's, never the install's.** On an agent's **Access** page, who can write to it is one choice of
  four, and the fourth is **Open to everyone**. Anyone who finds
  its bot or its number is answered, on every connection that agent owns. Your other agents go on asking new people
  to pair.
- **An open agent cannot touch your computer, whatever its pack lists.** It answers, it searches and reads the
  knowledge collections you opened to everyone, it reads a file its chat sent it, and it sends a file from those
  collections into the chat it is answering. No commands, no files of the server, no web, no other agent, no other
  chat, no secrets, no connectors, and nothing written to its memory. Its Tools page shows the rest locked, with why.
- **It knows nothing of your household.** Not who you are, not your notes on people, not what was said to another
  agent, not your other agents or where the server is. An admin who writes to their own open agent gets the same
  answers a stranger gets.
- **Nothing a stranger says is kept.** Their conversation makes no memory, teaches no skill, and adds nobody to
  People. A password sent to it is taken out, and they are told not to send such things.
- **What strangers cost is bounded by two numbers you give.** The most tokens the agent may use in a day, and the
  most messages one person may send it in a day. Both are asked for when you open it, and there is no default. Past
  its day the agent says it is closed until tomorrow, in a sentence you can write, and you are told once. Past their
  own messages a person is told so once.
- **One message is bounded too.** An open agent takes at most six steps to answer one. On a small model, asked three
  kinds of things twice, a question took one step and "send me the price list" took two.
- **The orchestrator and an agent on Claude Code or Codex are never open.** The first holds the install, and a coding
  CLI brings tools of its own that Nouride cannot take away. Each says why where you would have switched it on.
- **A stranger has three commands**: `/start`, `/help` and `/new`. Every other command answers one sentence and does
  nothing, so one visitor cannot put the agent to sleep for all of them.
- **In a group it answers only when it is tagged, named or replied to.** Anyone may add a public bot to a group.
- **It asks no other agent and wakes none**, and a stranger who names another agent on its bot is still answered by
  it alone.
- **Its conversations with the public have a place of their own**: on the agent's Access page, under **People who
  wrote**, with Read and Block. They are kept out of your own list of chats, and go when conversations of their age do.
- `nouride config check` and `nouride doctor` say which agents are open, where, and within which numbers.

Asked ten ways to run a command, read a file of the server or reach another agent (as "the owner", as "an admin", as
a "system override", in English and Indonesian), an open agent on a small model tried no tool in any of them, two
runs out of two. That is one model and twenty asks, not a proof: what holds is that those tools are not there to call.

### A WhatsApp number for each agent

An install had one WhatsApp number, whichever agent it belonged to. A shop's agent and your own assistant could not
each have theirs.

- **Each agent can have its own number.** Add a WhatsApp connection on an agent's **Connections** page, or
  `nouride gateway add --platform whatsapp --name shop --agent nora`, restart, and scan its code from the phone that
  holds that number. The number you already have is not asked to scan again.
- **A number is its agent's, as a Telegram bot is.** A message to it goes to that agent, and people are let in for
  that number and no other.
- **One number's trouble is its own.** Logged out from its phone or cut off from the network, it stops or reconnects
  alone, and `/health`, `nouride status` and the dashboard name it. The other goes on answering.
- **Each number keeps its login in a folder of its own**, `whatsapp-<name>` in the data folder. Removing a connection
  deletes its own login and no other's, and two connections on one folder are refused at start.
- **A number of an open agent says what that may cost it.** WhatsApp may restrict or close a number that answers
  many people it does not know: Nouride is linked to it the way WhatsApp Web is, not through the service WhatsApp
  sells to businesses. It is your number and your choice, so it is said and not refused.

Run on a live install with two real numbers: the number it had stayed linked through the update with no scan, a
second was scanned in from an agent's Connections page, each answered its own chat, and both came back linked after
a restart. The second number's agent, opened, answered a number it had never seen with no code, and closed, did not.
With two numbers the daemon held between about 105 and 150 MB of memory over half an hour, and about 125 MB with
one: what a second number costs was not told apart from the difference between one start and the next. Not yet seen
with real numbers: one logged out from its phone while the other stays connected, which tests on stand-ins for
WhatsApp hold, and the memory after a day.

### Fixes

- **A file kept in the knowledge base is sent when an agent names it without its section number.** An agent asked
  for "the price list as a file" was told there was no such document, read it to find out, and sent it on a second
  try.
- **Nouride starts when its config file cannot be written.** A start that had something to bring forward in the file
  stopped on a file or a folder mounted read-only. It now says the file was not changed and carries on.

### Before you upgrade

- **An install that was open to everyone becomes one that pairs.** `[security.access] mode = "open"` is no longer
  taken. At the first start it is written as `pair`, and everyone an agent has already answered is let in by name on
  the connection they wrote on, so they go on talking. Only a new sender is given a pairing code. To answer anyone
  again, open one agent on its Access page. `nouride config check` says so before the start does it.
- **Your WhatsApp number stays linked.** Its login is in `whatsapp` in the data folder: the first start writes that
  folder into the connection's table as `session_dir`, moves nothing, and asks for no scan. `nouride config check`
  says so before the start does it. Going back to 0.8.47 afterwards, the same line is read and the number is still
  linked.
- On Docker, run the `config check` above with the new image first.
