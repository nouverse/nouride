**0.8.46 updates from 0.8.0 or later.** From 0.7.x, start 0.8.0 once first:
[Upgrading to 0.8](https://nouride.com/en/docs/deployment/upgrading-to-0-8/) has the way across.

On Docker, check your configuration with the new image before you switch:
`docker run --rm -v ./nouride:/app/.nouride ghcr.io/nouverse/nouride:0.8.46 nouride config check`, with the volume your
compose file mounts.

### An agent changes the automation you have open

You had an automation open, half changed, and asked the agent in the chat over the page to change it some more.
The agent could only propose a change to the automation as it was saved, which was not what your page showed, and
the page would not draw that proposal until you saved or threw away your own changes.

- **The agent now changes what is on your page.** In the dashboard's chat over an automation's page, it is shown the
  automation as the page holds it, your unsaved changes included, or a new one you have not saved yet. What it
  writes is drawn over yours, with each step it adds, changes or removes marked.
- **One press applies it.** A bar over the steps says who changed it and what the change does. **As you have it** and
  **With the change** show the two; **Apply** puts it in, **Discard** drops it. A change that brings a script says
  which step to read first.
- **Nothing is saved for you.** Applying puts the change into the page and nowhere else: **Undo** takes it back, and
  the page's own **Save** is still yours to press. Nothing is stored on the way and nothing is turned on.
- **The chat keeps the way back to it.** The step that made the change has **Show the change on the page**, for a
  day or until Nouride restarts. It draws the change on the page it was written for, and says so on any other.
- **A change belongs to the automation it was written for.** One written for an automation you are making goes with
  it once you save or cancel, and one you applied or discarded is not drawn again unless you ask for it.
- **Any of your agents can.** One that runs on Claude Code or Codex draws its change on the page the same way.
- This is the dashboard's chat. Asked from Telegram, Discord or WhatsApp, a change is still a proposal that waits as
  **Suggested**. An automation too long to show the agent whole is changed on the page itself, and the agent says so.

### The chat over a page

- **It has the model and effort picker.** The chat that floats over every page had none: you went to Chats to choose
  a conversation's model. The same picker is in its bar now, between the agent and New chat, and a pick is kept on
  that conversation, as on Chats.

### Memory and export

- **Ask your orchestrator to set up search by meaning.** The Semantic search card on Knowledge & Memory, Settings,
  asks for a provider that makes embeddings and a model's name, which is no help if you have neither. It now has
  **Ask Nouva to set up semantic search**: the agent asks where the model should run (this machine, another server of
  yours, or a cloud service), tells you what it will install before it does, adds the provider and switches it on.
- **An agent can switch it on.** `nouride memory set semantic <provider>/<model>` turns search by meaning on once the
  model has answered, and `off` turns it off. Before, only the dashboard could, so an agent could add the provider
  and not finish. `nouride memory` also says how many items have been embedded and when the model is not answering.
  Switched off, it names the model it was set to: `nouride memory set semantic on` goes back to that one, with what
  it had embedded.
- **The Knowledge & Memory page's button asks about both.** It reads "Ask Nouva about knowledge and memory", where it
  only offered to remember something.
- **Export and import counts when you ask.** The page counted every file as it opened. On an install with many files
  that took long, and it kept running after you had gone to another page. It now says what the file will hold in
  words, and **Count how large it will be** counts it: once, for both sizes, with the agents' folders and without.
- **The page has its own Ask button**, "Ask Nouva about export and import".

### In a chat

- **`/helpers` says whom the agent is working for.** Asked at an agent that was doing work for another agent, it
  said no helper was working and nothing else, which read as an agent doing nothing. It now lists that work under
  its helpers: who asked, since when, and what was asked where you may see it.

### Docker

- **The image runs the built-in skills.** It now holds Python 3, `git`, `ffmpeg`, Node.js with `npm` and `npx`, and
  `pdftotext`: with them fifteen of the eighteen built-in skills have every program they name, where an agent had to
  ask you to install them first. The other three (diagrams, document-authoring, nouclip) each want one more program,
  which an agent asks for when the work needs it.

### A mission with limits of its own

Every mission stopped to ask whether to go on at the same three limits, the ones on the Missions page. Work known to
need more had one answer: raise them for every mission.

- **An agent can draft a mission with its own limits**: hours of work, turns and tokens, each where that one mission
  stops to ask you. Ask for it ("give this one two days"), or the agent names them when the work is known to need
  more or less. Left out, a draft follows your limits as before.
- **The draft says so before you start it.** One line in its notice: "Its own limits before it asks you whether to
  go on: 24h of work (usually 12h) · 400M tokens (usually 250M)". Your Start is your yes to them. A draft with no such
  line has none of its own.
- **You change them in the draft's form**, on its page. Hours and Turns were there; Tokens is new, in millions.
- **A draft's limits keep to what the Limits form allows.** A draft took 1,000 hours, where the form refuses past 168.
- **Your limits stay as they are.** One mission's limits change nothing for the next.
- A piece of work a mission hands to another agent, and an automation's mission step, start with nobody there to say
  yes, so they keep your limits. A mission an automation drafts (below) takes your limits too, and you change them in
  its form before you start it.

### An automation can draft a mission

A mission step started its mission the moment the run reached it. Long work an automation had prepared ran at once,
with nobody having read what it was about to do.

- **A mission step can leave its mission as a draft.** Under the plus, **Draft a mission** stands beside **Start a
  mission**; a mission's step also has the choice as its first field, **When the run gets here**. The run starts
  nothing: the mission is put in your Backlog, the automation's chat gets the
  draft with Start it and Drop it, and the run goes on to its next step at once.
- **It runs when you start it**, from that message or from its page, however much later. Change its goal, its checks
  or its limits there first, as with any draft.
- **The step after it is told.** It is handed one line saying which mission was drafted, so a message step can say
  "this week's work is drafted".
- **One draft of an automation waits at a time.** A run that reaches the step while the last draft has not been
  started or dropped stops there and says which draft it waits on, so an automation that runs every hour does not
  fill your Backlog. A draft that waits holds none of the automation's other steps back.
- **On the canvas the box reads "Draft a mission"**, and a run's page links to the mission it drafted.
- An agent writes it with `draft` on a mission, and its proposal says first that nothing starts. From the command
  line it is `--draft` beside `--mission`, or `"draft": true` on a mission in a steps file.

### Limits that fit a day of work

- **A mission asks to go on after 12 hours of work, 250 turns or 250 million tokens.** It asked after 8 hours, 100
  turns or 100 million, and long work kept stopping to ask. A limit you set yourself stays as you set it.

### Fixes

- **An agent on Google's Gemini API can use its tools.** Gemini sends a signature with a tool call and wants it back
  with the next request. Nouride did not send it back, so an agent set up on Google's own address answered a plain
  question and failed at its first tool, every time. An agent that reaches Gemini another way was not affected. Run
  against Google's API on Gemini 3 Flash and Gemini Flash Lite.
- **WhatsApp and Discord connect from behind a proxy.** Where the only way out is a proxy (`HTTPS_PROXY`), Telegram
  worked and these two never connected: they went straight out and were dropped. Both now go through the proxy, and
  `NO_PROXY` is kept to.
- **WhatsApp says it is connected when it is.** It said "connected" as soon as its own part had started, before
  WhatsApp had answered, and again after every round of tries. A WhatsApp that could not be reached looked connected
  for hours and nobody was told. It now says "connecting" with what it waits on ("Waiting for the phone to scan the
  pairing code.", or the reason the last try failed), and "connected" once WhatsApp has opened.
- **A connection that cannot be reached is not given up on.** Once its quick tries ran out, a connection stopped for
  good and waited for `nouride gateway restart`: a box whose internet was out for half an hour kept its chat apps
  down until somebody noticed. It now tries again by itself every ten minutes for as long as it takes, its row says
  when, and you are told when that begins and when it is back. `/health` no longer answers 503 for it, which had a
  hosted install restarted. A connection whose token is refused, or whose WhatsApp session is gone, still stops:
  that one needs you.
- **The dashboard no longer stands still while an export is counted.** Counting what an export would hold read every
  file in one go, and nothing else was answered until it ended: 26 seconds on a box with 1.2 million files in its
  agents' folders, at each look at Export and import and again as a file began to be made. The count now lets
  everything else go on, and making a file no longer counts twice.
- **A stop says what it could not send.** Messages an agent had written while a chat app was unreachable are held
  until it is back. Stopping Nouride then lost them without a word; the log now says how many.

### Before you upgrade

- **Missions run longer before they ask**, unless you set your own limits: 12 hours, 250 turns, 250 million tokens.
  To keep the old ones, open **Missions**, then **Limits**, and set Hours 8, Turns 100 and Tokens 100.
- **The Docker image is larger**: 587 MB on disk where it was 246 MB, measured on arm64, for the programs the
  built-in skills run on. Leave room for it before you pull.
- On Docker, run the `config check` above with the new image first.
