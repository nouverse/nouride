**0.8.47 updates from 0.8.0 or later.** From 0.7.x, start 0.8.0 once first:
[Upgrading to 0.8](https://nouride.com/en/docs/deployment/upgrading-to-0-8/) has the way across.

On Docker, check your configuration with the new image before you switch:
`docker run --rm -v ./nouride:/app/.nouride ghcr.io/nouverse/nouride:0.8.47 nouride config check`, with the volume your
compose file mounts.

### Your agent knows what is yours, wherever you ask

You told an agent something in a direct chat, your car's plate or a plan, and asked about it in a family group a
minute later. The agent knew nothing of it: what was said in private was kept out of every group, whoever was asking.

- **What you told an agent in private is used in a group when you are the one asking.** On the messages you send
  there, and on nobody else's. Someone else in the group who asks for it is told the agent does not have it. Who is
  asking is the sender your chat app reports, never a name written in a message.
- **It leaves nothing behind.** What an agent looked up for you is not kept in the group's conversation, so the next
  person's question cannot reach it. What the agent says out loud in the group is there for everyone, as it always was.
- **One switch turns it off.** Knowledge & Memory, Settings: **In a group, an agent uses what a person told it in
  private when that person is the one asking**. An admin can also ask an agent to switch it. Off, a group knows only
  what was said in it, as before.
- **One thing can stay between you and the agent.** Say so in your direct chat ("keep that between us") and that one
  fact is kept out of every group, your own messages included.
- **The agent tells you where it kept something**, and where it will be known. It said "only in this chat" of every
  fact, which was wrong: a fact from a direct chat was known in every direct chat with you.
- The Memory page says, beside each fact, where it is known.
- An agent that runs on Claude Code or Codex is not given this in a group. Its coding CLI keeps everything it is
  told, so it could not be kept from the next person there. In a direct chat it knows you as any agent does.

### The knowledge base keeps any file, and hands it back

You sent an agent a photo and said "keep this". The knowledge base kept pictures without being able to find them
again, and an agent had no way to send a kept file back into a chat.

- **A photo, a video or a scan is kept and found.** It is kept as it is, and found by its title and by a line
  saying what it is, which the agent writes from what it saw ("the QR code a pump attendant scans, car BG 1234 XY").
  Pictures already in your collections are found by their names once 0.8.47 has read the folder again, within five
  minutes of the update.
- **An agent sends a kept file back.** Ask for it and the photo, the PDF or the spreadsheet arrives as an
  attachment, in any chat that may be answered from its collection.
- **A collection of your own goes with you into a group**, on your own messages, by the rule above. Each such
  collection has **In a group** in its settings: follow the memory setting, yes, or no. From the command line it is
  `nouride knowledge in-groups <collection> on|off|default`.
- A link is kept as what it is and its address, and the agent answers with the address.
- A document's row says why its words are not read and what it is found by, where it said "kept, not searched".

### A mission's brief reaches you in the chat

An agent drafted a mission, and its goal ended with "Full brief:" and a path on the server, or the draft said "brief:
on the mission's page". In a chat app you could open neither, and started work whose instructions you had not read.

- **The brief is sent as a file under the draft.** `BRIEF.md`, whole, in the chat the draft is in, and again when the
  agent changes it. A chat that cannot take the file is told so, and the brief stays on the mission's page.
- **Agents write the brief with the draft.** Nouride itself had told them to put a long goal's detail in a file of
  their own and name its path. The brief now has one place, the mission's own, and a goal says what must be true when
  the work is done. A brief an agent still points at by its path, in its own folder, is sent to you the same way.
- A piece of work a mission hands to another agent takes a brief too, and you are sent it when that piece starts.
- A draft an automation leaves for you is sent the brief its goal names, the same way.
- **New mission on the dashboard takes a brief and the mission's own limits.** Hours, turns and tokens for that one
  mission, as the draft's form already had them; a limit left empty is the one every mission starts with. They apply
  whether you save it to the backlog or start it at once.

### Fixes

- **What an agent writes in its own notes is read on its next turn.** An agent's `MEMORY.md` was read when Nouride
  started and not again, so a note an agent kept "for every chat" was unknown in the next chat until a restart. It is
  read as it changes now, whoever changed it: the agent, you on the Files tab, or an edit on disk.
- **On a phone, the conversation stays at its newest message while you type.** With a message of several lines in
  the box, each letter typed slid the conversation down, so the newest answer went under the message box, and a new
  line put it back. The box is now measured without anything around it moving.
- **A helper started from a group reads what the group reads.** A helper's own turn was built as a direct chat with
  whoever had spoken, so in a group it could search what that person had told the agent in private, and its report
  stayed in the group's conversation. An agent asked by another agent is held to the same.

### Before you upgrade

- **In a group, an agent now uses what a person told it in private, on that person's own messages.** To keep groups
  as they were, switch it off after the update: Knowledge & Memory, Settings, or
  `nouride memory set private_in_groups off`, or `private_in_groups = false` under `[memory]`.
- On Docker, run the `config check` above with the new image first.
