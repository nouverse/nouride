**0.8.38 updates from 0.8.0 or later.** From 0.7.x, start 0.8.0 once first:
[Upgrading to 0.8](https://nouride.com/en/docs/deployment/upgrading-to-0-8/) has the way across.

On Docker, check your configuration with the new image before you switch:
`docker run --rm -v ./nouride:/app/.nouride ghcr.io/nouverse/nouride:0.8.38 nouride config check`, with the volume your
compose file mounts.

A release about agents that a coding CLI answers (Claude Code, Codex): which version really runs them, updating it,
picking a model in a chat, and what happens when an account reaches its limit. With it, a dashboard whose pages
scroll as pages, a Workspace view in it, and fixes.

### The dashboard knows which Claude Code you are on, and when a newer one is out

A coding CLI is installed as an adapter that carries the CLI inside it. Nouride read the adapter's version alone, so
the dashboard said "up to date" for an install whose Claude Code was a version behind and did not have the newest
model.

- **Everything a coding CLI runs on is listed**, each part with its version: Node, the adapter, the CLI the adapter
  carries, and the adapter's other packages. **Models → Coding CLIs** and an agent's **Brain** tab name the CLI by its
  own version (Claude Code 2.1.323), with the rest under Details. `nouride agents scan`, `nouride doctor` and `/status`
  in a chat say the same. Where Node is older than the adapter asks for, that is a warning.
- **A newer version is offered as soon as it is out**, whether or not this Nouride was tested with it. One that was not
  says so beside the offer; it is yours to take or leave. **Update** installs the version on offer, and
  `nouride agents update <cli>` with no version does too. Where a newer CLI is out that no adapter carries yet, the
  badge reads **newest you can get**, with nothing to press.
- **Home tells an admin** when a coding CLI one of the agents works in has an update out, beside Nouride's own update
  badge. It opens the CLI's card.
- **After an update, the models are the new version's.** The list each agent offers is read again at its next session,
  so a model that came with the update can be picked, and one that went is not offered.
- **An agent knows what runs it.** Asked which Claude Code it is on, or to update it, an agent a CLI answers reads the
  version from what is installed, and says who can update it: the orchestrator, on your word. It used to name another
  copy of the CLI found on the box.
- Claude Code is tested with its adapter up to 0.107.0, which carries Claude Code 2.1.323, and Codex with its adapter
  up to 2.6.0.

### `/model` in a chat with a coding CLI agent is checked

`/model fable` was taken as written. Which model that was depended on the CLI installed, and a name the CLI did not
have was found out only when the next message failed.

- **A name is checked against the models the CLI offers**, and the reply says what it stands for. A name it does not
  have is refused, with the list of the ones it has. `/model` alone says the model now and the ones offered.
- **Before the CLI has said its list** (before its first session, or right after an update), a name is taken as
  written and the reply says it is not checked yet.
- **`default` says which model it stands for again**, on the Brain tab and in `/status`. With the newest Claude Code
  adapter it read only "default".
- **`/status` names the model the chat is on.** In a chat put on another model with `/model`, it still named the
  agent's own.
- **A message the CLI refused says so.** The line under it said the CLI "did not start" for a CLI that had started and
  refused the message, an account's limit for one. It now tells the two apart, and where the chat is on a model picked
  with `/model`, it says which, and that `/model default` goes back.

### An agent goes on with its next account when one reaches its limit

An agent can have more than one account of its coding CLI. When the account it is on reaches a usage limit, Nouride
starts its CLI on the next one and sends the message again. The conversation goes on where it was.

- **Pick the accounts on the agent's Brain tab**, under **When its account reaches its limit**, from the ones signed in
  on **Models → Coding CLIs**, in the order they are used. In the agent's `config.toml` it is `profile` as a list.
- **The chat gets one line**: which account reached its limit, until when, and which one the agent goes on with.
- **A limit is kept per model**, and across a restart. An account at its limit for one model still answers on another.
  It is passed over until the limit ends; where the CLI did not say when, it can be tried again after an hour.
- **An agent that moved stays where it moved**, for as long as that account is not at a limit itself. After a restart
  of Nouride it starts from the top of its list again.
- **Each agent moves by its own list.** Agents that share an account all see that it is at its limit, and each goes to
  its own next one. Nothing is switched for every agent at once, and one agent's sign-in never becomes another's.
- **With every account at its limit**, nothing is sent: the agent's own model answers that message and says which
  accounts are spent, and until when.
- **It can move on before the limit.** On the Brain tab, **Move on before the limit** and a share of a limit, 90% to
  begin with. Claude Code says how much of an account's limits is used while it works; once that share is used, the
  agent finishes the message it is answering and its next one starts on the next account, with a line in the chat.
  Nothing is cut off or sent twice. Off unless you switch it on; in the pack it is `move_at = 90`.
- **Models → Coding CLIs** says, under an account, each limit it is at or near, and beside an agent that moved, where
  it is now. `/status` names the account an agent is on.
- For Claude Code, whose account is signed in once for every agent on it. Codex signs in once per agent, so there is no
  other account to go on with, and the list is not offered.

Which accounts go in a list is yours to decide. A subscription is one person's, and its maker's terms say what it may
be used for: moving between several people's accounts to get past their limits may break those terms.

### Workspace: what your agents keep, in the dashboard

An admin can look through the agents' folders without opening System's Files and finding the way down.

- **An agent's page has a Workspace tab**, beside Model: that agent's own folder, and nothing else. There is no way
  up or out of it, and its files scroll inside the card under the path, which stays.
- **Agents has a Workspace tab**, beside Agents: it opens on the workspace and goes into its two folders,
  `private`, with a folder for each agent, and `shared`.
- **On Agents**, an agent's row, opened, has **Workspace**, which opens that agent's tab.
- Files open, download and delete there as they do in Files, and what holds a credential is left out the same way.
  Anyone who is not an admin has none of the three.
- **An agent's coding CLI folders cannot be deleted from the page**, here or in Files: `.cli` in an agent's folder, and
  the folder of each account in it. They hold the agent's sign-in and its conversations, and had a delete button like
  any other folder. What is inside an account's folder can still be cleared.

### The dashboard: pages scroll as pages, and Agents opens on the Office

Most pages held their list in a card that scrolled inside the page, under a title and tabs that stayed. On a laptop
that left a strip for the list, with a blank band under it kept for the chat button.

- **A page scrolls as a page.** Where it has tabs, a filter or a search of its own, that row stays at the top of the
  window while the list scrolls under it: Missions, Helpers, Models, Connectors, Skills, Groups, Access, Memory,
  Agents, and an agent's own tabs.
- **A long list is shown in full.** One with another card under it is cut short, its last rows fading out, and
  **Show all** opens it. The small boxes that scrolled inside a page (a mission's brief, an automation's runs, a
  connector's tools) open the same way.
- **Files, the Workspace and Logs** still scroll their list inside the card, since the path and the filters over it
  have to stay. Their card now runs to the foot of the window, with the chat button over its corner; the blank band
  is gone.
- **Agents opens on the Office**, and under it every agent is a row: its cat, its name, what answers it, where it is
  reached and what it is doing. A row opens the agent's page. Click a cat, or the arrow at a row's end, for what you
  do with that agent: **Details**, **Open chat**, **Sleep** or **Wake**, **Workspace**, **Edit look**. The Office has
  no tab of its own any more; its old address opens Agents.

### Fixes

- **A mission no longer waits for its own server.** A mission that started a server to look at its work (a preview, a
  static server) stood still once that server was the only thing it had left running: it waited for it to end, which a
  server never does, with nothing said. It now goes on to its next step, and the server is stopped when the mission
  ends. A mission that has waited an hour for any other job is told which one, once, in case that job never ends.
- **`nouride setup` goes on from where it stopped.** Run again after it stopped halfway, it refused to start because
  `config.toml` existed, with a provider written and no agent. It now reads what is set up, as the dashboard's wizard
  does: with a provider and no agent, it goes on at the agent. An agent id that cannot be used is refused before
  anything is written, and asked again. In a container, the next step it names is `docker compose up -d`.
- **A saved browser login is never printed.** An agent that saved a browser's sign-in with the `browser-automation`
  skill is now told to load it and never to open, print or read the file, which holds the session itself.
- **Files sent alone from the dashboard are just the files.** Pictures or files sent to an agent with nothing typed
  showed a bubble of yours saying only the agent's name (`nix:`), kept "8 file(s)" under the agent while it worked,
  and half a minute later said no agent had started on the message, while the agent was answering it. The chat now
  shows the files alone, and the agent is handed no words you did not write.
