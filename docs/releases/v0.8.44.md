**0.8.44 updates from 0.8.0 or later.** From 0.7.x, start 0.8.0 once first:
[Upgrading to 0.8](https://nouride.com/en/docs/deployment/upgrading-to-0-8/) has the way across.

On Docker, check your configuration with the new image before you switch:
`docker run --rm -v ./nouride:/app/.nouride ghcr.io/nouverse/nouride:0.8.44 nouride config check`, with the volume your
compose file mounts.

A release about automations: a page somebody who has never made one can read, scripts your agent writes for the
steps that need no AI, and a "tell me when…" that gives up by itself.

### An automation is drawn as a canvas

The automation's page was a column of cards, each one a form. It is now a picture of what the automation does: a box
for how it starts, a box for each step in the order they run, and a box for where its results go.

- **Press a box to change it.** On a wide window its fields open beside the canvas, which stays in view; on a
  narrower one and on a phone they open inside the box. With nothing pressed, the last runs are there.
- **What happens if a step fails is a question with four answers**: **Stop and tell me**, **Go on anyway**, **Ask me
  first**, or **Do something else**. It was a dropdown that said `Go to "step 4"`.
- **"Ask me first" is written where you chose it**, and shown in the step's own box with the question and where yes
  and no lead. The wait it asks with is no longer a step of its own to keep track of.
- **"Do something else" draws its steps beside the step**, or under it where there is no room beside, and they end
  in one of two marks: back into the steps below, by name, or "The run stops here".
- **A new automation starts as that canvas, empty**, with "Add the first step" in the middle.
- **A run and a change your agent suggests are drawn on the same canvas**: each box says how its step went with the
  path the run took lit, and a suggested change marks what it would add, change and remove.
- **An automation you made by hand or at the command line is kept as it is.** A path the canvas has no drawing for,
  such as a jump to a later step, is shown under its step with a line to where it lands, until you pick another
  answer.
- **You can hand your own automation to somebody else.** Open the menu at the head of its page, **Whose it is**, and
  pick a person. You are asked first, since it is then theirs to change. Only an admin could move one before.

### A script as a step

A step that is the same every run, such as fetching a page, comparing a number or calling a service, does not need a
model. **Run a script** runs a few lines of shell, Python or JavaScript in the agent's workspace, with no AI.

- **The automation keeps the script.** What runs is what you read before you turned it on, and a change to it is a
  change to the automation like any other.
- **It reads what the step before said, and what it prints goes to the next step.** Printing nothing is "nothing to
  say", and ending with an error is a failure, so each of the four answers above works for it.
- **Your agent writes it.** Ask in a chat for an automation and, where the work is the same every run, your agent
  writes the script, tries it once, and proposes it. Its card says what the script does, what runs it and how long
  it is, and shows its text. Nothing runs until you turn it on.
- **You read it in words first.** Its box says what it does and who wrote it. Its fields say what it is written in,
  how long it is and which saved keys it uses, with **Show the script** for the text.
- **Try it** runs the script once, on what the step before said in the last run or on what you type, and shows what
  it printed. It is a real run: a script that sends or saves something does so.
- **A program that is not on the machine is said when you save**, not when the automation fires at 07:00.
- From the command line: `nouride cron add --script <file> --about <what it does>`, with `--run python3` for what
  runs it.
- A one-line command in an automation you already have runs as it always did. Its step offers **Write it as a
  script instead**.

### "Tell me when…" that gives up by itself

"Tell me when the build is done" is a check on a clock that tells you once. A check for something that never happens
went on checking for good.

- **Stop by itself after**, where an automation says where it reports: an hour, six hours, a day, a week or thirty
  days, counted from when it is turned on. When the time is up it turns itself off and says so in its chat.
- **A watch your agent proposes always has one.** Asked "tell me when the file is there", it proposes a script that
  checks, tells once, and stops by itself.
- Its page says "It ran for the time it was given, and turned itself off", in the colours of information: nothing
  failed. Turn it on again to give it that time again.
- From the command line: `nouride cron add … --once --for 6h`.

### Going on after a failed step

- **The step after a failed one is still given what the failed step had been given.** With "Go on anyway" (or a
  path that led on after a failure before this release), the next step was handed only the error, so a message
  after a failed save had nothing true to send. An agent's step is told both; a script reads the earlier words.

### An agent knows when the machine is short of room

- **A turn is told when the box is nearly full**: when the commands running on it hold most of the memory they may
  use together, or the disk is nearly full. Your agent can then wait, or do the light part first and say so. Nothing
  is said while there is room, and nothing is held back by it.

### Fixes

- **`nouride cron` no longer lists an automation that told once, or lasted its time, in red.** Both did what they
  were set to do.
- **An automation that is nobody's says who can change it**, on the page of somebody who can only read it: an admin.
- **The manuals on nouride.com now change when a release is out.** They changed when its work was merged, which
  could be before you could install it.

### Before you upgrade

Nothing to do first. Every automation you have runs as it did: its steps, its paths and its one-line commands are
kept as they are, and the new page draws them.
