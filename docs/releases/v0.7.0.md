0.7.0 is about agents that keep going: a turn survives a restart, a message sent during one is still answered, one turn can carry an hour of work, and you can steer it while it runs. Around that, memory search moves onto SQLite's own full-text engine, a person in People becomes one entry with notes the agents can keep, and who may talk to your agents is one page.

### Highlights

- **Nothing a turn did is lost to a restart**, and the agent carries on by itself once the daemon is back.
- **Messages sent while the daemon was down are answered**, once.
- **Steer a turn while it works**: a message you send mid-turn is read at its next step.
- **Long work in one turn**: 250 tool calls and an hour by default, up from 25 and ten minutes.
- **Coding agents**: hand work to OpenCode, Claude Code, Codex, Gemini CLI and others, in the background.
- **Memory search on FTS5**: a database less than half the size, keyword matches in 1.6 ms instead of 150.
- **One Access page** for every pairing request, approval, denial and block, and **People** where somebody can be added by name alone.
- **`USER.md` is gone**: who somebody is lives in their notes in People, which they can change through an agent.

### Turns that survive a restart

Every step of a turn is saved as it happens: the question, each model reply and the tools it asks for, each result. If the daemon stops in the middle (a power cut, an update, a crash, a provider failing halfway through), the conversation keeps everything that was done, and the agent says what happened:

> ⚠️ I was interrupted by a restart while working on "deploy the site". Done: `read site.toml`, `git status`. Cut off: `exec ./deploy.sh` (it may have partly run). Everything I did is kept, and I'll carry on once I'm back — if I don't, say "continue".

- **Back within 15 minutes,** the agent carries on by itself with everything it had. A tool that was cut off is marked so, and the agent checks what it did before repeating anything that changes something. It carries on once: a turn that was itself carrying on is not taken up again, so a turn that crashes the daemon cannot loop. A scheduled run is never taken up. Back later than that, say "continue". To stop the work for good, use `/stop`, not a restart.
- **Messages are written down the moment they arrive.** One sent during a restart is answered once the daemon is back, if it was sent in the last 15 minutes; an older one gets a short note that it came in while the daemon was offline, instead of a late answer to yesterday's question. A message a platform delivers twice is answered once. Telegram no longer throws away what was sent while the daemon was down.
- **Replies arrive, once.** A reply written just before a crash is sent after the restart, and so is the message that a turn was cut off or failed. A long reply that fails halfway no longer sends its first part again.

### Restarts that wait

- **Updates and restarts wait for idle.** `nouride update --start`, the dashboard's install, the agent's own update tool, `nouride restart`, the dashboard's **Restart** and `/daemon-restart` all restart once nothing is running. A turn or an approval is waited for ten minutes at most, and a turn cut off then keeps its work and carries on. A background job (a build, a test suite, a coding agent's run) is waited for until it finishes, and the note says so: "restarting once the background job `make build` (12m) finishes, however long that takes". A service such as a dev server does not count. `--now` restarts at once and stops the jobs.
- **Restart from a chat.** `/daemon-restart` (`/daemon_restart` in Telegram's menu, which allows no hyphen) waits the same way, `/daemon-restart now` does not, and the chat gets "✓ Restarted — I'm back." from the daemon itself. Only an admin may: somebody whose person in People is linked to a dashboard account with the admin role.
- **An agent can restart and report back.** `nouride restart --then "<what to check>"` works like `update --then`: the follow-up fires a few seconds after the daemon is back.
- **Shutdowns let turns finish their step.** Running turns stop at their next step, close with what they did, and tell their chats. That includes a running command: systemd now signals the daemon alone, and the Compose files allow 45 seconds instead of Docker's 10.
- Background jobs do not survive a crash or a stop. The agent is told at boot which were interrupted, and can run them again.

### Long work, and steering it

**A turn now defaults to 250 tool calls and an hour**, up from 25 and ten minutes, so one turn can carry a piece of work through the way a coding agent does. The conversation is compacted as it grows, `/stop` ends a turn at once, and other chats are not held up. Work that waits on something slow still belongs in a background job, which wakes the agent when it is done.

**Steer a turn while it works.** In a one-to-one chat (Telegram, Discord, WhatsApp or the dashboard), a message you send while the agent works is read by that turn at its next step, never mid-step. You are told at once: "↪ Got it — I'll read that before my next step." The dashboard keeps **Send** beside **Stop** while the agent works.

- Several messages before the next step are read together. A turn reads five this way; after that, a message waits for the turn.
- A turn already writing its final answer has no next step, so your message starts the next turn the moment it ends. Once the answer has been written you get no "Got it": the agent may still be tidying the conversation for a few seconds, but it will not read anything more in that turn.
- A turn waiting on an approval reads your message once the approval is answered. Answer with `/approve` or `/deny`: a "yes" typed as a message is not an answer.
- Words only. A file, a picture or a slash command goes the ordinary way.
- In a room, the person who started the turn steers it the same way. Anybody else who addresses a busy agent is told so, once per turn, instead of meeting silence.

It is on by default; `[queue] steer = false` turns it off.

**Model hiccups are ridden out.** A request that fails with something waiting can fix (a rate limit, an overload, a 5xx, a timeout, a dropped connection) is tried for about half a minute, six attempts 1 to 16 seconds apart, instead of three in a second and a half. A `Retry-After` up to a minute is honoured; a quota that ran out fails at once. A provider down for longer still ends the turn with its work kept, and the daemon tries once more about three minutes later, unless you have said anything in that chat since, it was a scheduled run, or the failure is one no wait fixes, such as a refused key or an empty balance.

### Coding agents

Your agent can hand coding work to a coding agent CLI (OpenCode, Claude Code, Codex, Gemini CLI, pi, oh-my-pi, Command Code, or another with a non-interactive mode) and drive it. Ask for one by name, or just for a feature, a refactor or a failing test suite. The new built-in **coding-agents** skill covers installing it without root, signing it in on the provider the agent already uses (or with a subscription token such as `claude setup-token`, stored with `nouride secret set`), running it in the background in its own worktree, checking the diff and the tests itself, and following up in the same session.

**Working while a job runs.** Starting a background job used to end the agent's turn. With `keep_working`, it carries on with other work that does not need the job's result, and hears the result after.

### Installing without root

Agents run as an unprivileged account, so every installer's default global install used to fail. Now the obvious command works the first time:

- **Global installs land in the agent's own bin directory**, `.nouride/bin`, with no root and no flags: `npm i -g`, `bun add -g`, `pipx install`, `uv tool install`, `go install`, `cargo install`, or a release binary with `install -m 755`. On `PATH` everywhere, across restarts and updates.
- **`pip install` just works**, in one shared environment, `.nouride/opt/python`, that still sees the system's own packages.
- **Agents are told what is already installed**, which build to download for this host, and get a one-line hint where they used to improvise: Python refusing `pip`, no `sudo`, the wrong architecture, a missing compiler.
- **`nouride pkg install`** runs as a background job, and **`nouride doctor`** lists what agents have installed and warns about broken links or a program hiding a system one such as `git`.

### Memory

**Search runs on SQLite's own full-text engine (FTS5).** Nouride used to keep its own word index, which had grown to two thirds of the database. On a box with 895 remembered conversations:

- **The database file shrank from 76 MB to 31 MB**, the keyword index from 48.5 MB to 4.7 MB, and every snapshot with it.
- **Finding and ranking keyword matches takes 1.6 ms** at the 95th percentile, down from 150 ms; a whole keyword search 8 ms, down from 161.
- **Rebuilding the index from your vault takes 2.3 seconds**, down from 3.6.
- **The same conversations match.** Some come back in a different order: a word in a summary counts for more than the same word deep in a transcript. On that box's 31 real searches, the new order was as close or closer in meaning in 24, and never dropped one of the closest answers.

**Related conversations, both ways.** A conversation found by a search brings the ones linked to it, now following links both ways and up to two steps out, at most five per result. **Search by meaning** reads every vector in one query: 2.7 ms for 940, down from 14.9.

**Tags stay one vocabulary.** The nightly pass used to coin a tag for almost every subject; on one box, three quarters of 668 tags were on a single conversation. The model is now shown the tags already in use, a new spelling is folded into one in use when the match is certain, a conversation adds one new tag at most and keeps four, and the morning after, the Memory page lists the night's new tags with **Merge into** beside each. **Tidy tags** (or `nouride memory tags tidy`) shows what the same rules would clean up in the tags you already have, applies what you tick after a backup, keeps merged tags working as aliases, and has **Undo**.

**Memory is written in English**, whatever language you chat in, so one search finds it across every chat; names, quoted terms and transcripts stay as said. It is checked now: an answer in another language is asked for again, and an agent's `memory_write` in another language is refused with the reason.

**A folder per month.** Day pages live in `days/YYYY/MM/`, and a tag gets its own page only once two conversations share it, so the graph stays readable in the dashboard and in Obsidian.

### Who may talk to your agents, on one page

Pairing requests used to be answered on the Agents page, and each agent kept its own list. Now there is one **Access** page for every agent, because the questions are about people: one person can ask two bots, and "who did we block?" names no agent.

- **Pending**: every waiting request with its code and when it runs out. Approve, approve *as* somebody, deny or block. While anybody waits, a count beside **Access** shows on every page, because a code lasts fifteen minutes.
- **Approved**: everyone paired, with the platform, the person in People the account belongs to (or "not in People"), and Revoke and Block.
- **Denied**, **Blocked** and **History**: who was turned away and for how long, who is kept out, and every request and answer with who gave it.

**Deny and block are different answers now.** Deny is "no, this time": the sender is ignored for a day, then may ask again, and **Reset** ends the wait at once. Block is "no, until somebody says otherwise", until **Unblock**. Neither is said to the sender, and a block beats an id in your config too. Deny used to be for good, with nothing on any screen to show it. From a terminal: `nouride access deny|block|revoke|reset|unblock <gateway:sender>`, and `nouride access allow <gateway:sender>` lets somebody in before they ask.

### People

**A person is recognised on every bot.** An account is the platform and the account now, `whatsapp:628…@s.whatsapp.net` rather than `whatsapp:nouva:628…`, which named somebody only while they wrote to one bot's number. Access itself stays per connection.

**Add somebody by name; attach their accounts later.** On the People page only the name is needed. The **Person Key** fills itself in (`Kak Sam` → `sam`) and can be changed before saving: lowercase letters and digits, words joined by `-`. It is the person and the name of their memory file (`people/sam.md`), so it is fixed once saved, and a duplicate or malformed key is refused in the dashboard, the CLI and at load. When they pair, **Approve as…** on Access attaches their account to the person you already added. `nouride people set sam --name "Kak Sam"` does the same from a terminal.

**`USER.md` is gone.** It was one description of "the user" in every agent's pack, read whoever was speaking, so a household's second person was greeted by the first one's name. Who somebody is now lives in their **notes** in People: markdown, as long as needed, read by every agent and only while that person is speaking. How an agent behaves belongs in its `SOUL.md` or `AGENTS.md`.

**Notes are what does not change; memory is what does.** Tell an agent "my birthday is 12 May" and it keeps that in your notes with the new `person_notes` tool, a line at a time, never rewriting the page around it. Only ever your own: nobody's notes change through an agent at somebody else's request, an admin's included. An admin edits anyone's on the People page, and every change is in the audit log with who asked and what the line read before. What changes over time (work, plans, tastes) still goes to that person's memory profile, and an agent's own `MEMORY.md` is for how it works, never for facts about a person.

### Agents and tools

- **The first agent has every tool, including ones later releases add.** Setup writes `enabled = ["*"]` instead of the tools of its release, which froze an agent set up before `skill_search` existed without it. Turning one tool off on the agent's Tools page makes it a list again. Any pack can use the star.
- **`read` opens `HOME` and `.nouride/bin`, `lib` and `opt`** by path, for an agent that has a shell.
- **An agent sees a picture it made.** `read` of a PNG, JPEG, GIF or WebP in its workspace shows it the picture, and an image an MCP server returns reaches the model.
- **Credential files are read with their values hidden**: `.env`, `.npmrc`, `.netrc`, cloud CLI logins and private keys show which keys are set, never the values. `send_file` will not send one.
- **An agent cannot rewrite its own `config.toml`** with the file tools. Its tools, roots and approvals are yours to change.

### Dashboard

- **Notes open in one dialog with Edit and Preview**: a person's from People or Memory → People, and each agent's `MEMORY.md` from Memory → Agent notes, now editable there. A save over notes that changed since you opened them is refused instead of overwriting them.
- **Every confirmation is the page's own dialog**, saying what will happen, instead of the browser's.
- **Access shows the platform** of every account, and the agent it wrote to as a badge.

### Safer by default

- The shell a command runs in, and the `tar` that unpacks an update, are always the system's: a `bash` dropped into an agent's bin directory is never the one that runs.
- The daemon's own install is not the agents' to change. Copying a build over the `nouride` binary or editing a shipped skill in place is refused, with the right way named.
- Root running `nouride` runs it as the service account. `install.sh` puts a small launcher on `PATH` instead of a link.

### Fixes

- Recording somebody's name from their second account no longer makes them a stranger on the first.
- An agent updating a section of its `MEMORY.md` replaces it, instead of leaving the old version underneath so the same notes piled up, sometimes contradicting each other.
- Part of a secret is hidden like the whole of it.
- A scheduled job interrupted by a restart no longer stops running for good.
- An agent remembers the answer it gave when a turn ended by wrapping up.
- Revoking, denying or blocking somebody also drops their `/auto` setting.
- Typing `/stop` or `/approve` in the dashboard's chat acts at once instead of waiting behind the turn.
- An agent set to never ask runs every command, `sudo` included, even with no chat or dashboard open.
- A command killed at its time limit says whether it was working or waiting, and an installer piped into a shell goes to the background by itself.
- A background job that finished just before a restart is still reported, and one started by a scheduled run reports where the job delivers.
- A webhook called while its last call still runs answers 409 and says why, instead of 202 and dropping it.
- Saving or removing an agent's MCP server connects or closes it at once.
- A stranger who tags one bot in a group is paired by that bot alone, which answers with the code under their message.
- Replying to an agent's progress line ("⏳ 💻 exec …") reaches the agent.
- Expired dashboard sign-ins are cleaned up, `nouride doctor` shows its offline checks without the control token, and the setup wizard no longer calls stored keys encrypted.

### Upgrading

- **Docker:** `docker compose pull && docker compose up -d`
- **Binary:** `nouride update --start`

The first start on 0.7.0 does the rest by itself, in a few seconds:

1. **Checks the SQLite in the binary** has what the new index needs, and refuses to start before changing anything if it doesn't. Release binaries all do.
2. **Snapshots your database** as `data/backups/db/nouride-<time>-before-048.db`, kept outside the daily rotation.
3. **Updates the schema** (including the tables durable turns run on), then **compacts the file**.
4. **Rebuilds the memory index from your vault** before memory answers anything.
5. **Moves day pages into month folders**, after backing the vault up.
6. **Stops reading `USER.md`.** Each agent whose pack still has one says so at load. Move what it says about a person into their notes on the People page, and how the agent should behave into `SOUL.md` or `AGENTS.md`, then delete the file.
7. **Keeps denied senders out.** A sender denied before the upgrade (which meant "for good") is listed as blocked.
8. **Reads `[[people]]` the new way.** An entry that names its first account `id = "…"` is read as one of its accounts and written with them all in `ids` the next time that person is saved. One with no `key` is given one from its name.

No configuration changes are needed. A pack that lists its tools gets `person_notes` by adding it to `[tools] enabled`; the daemon names each pack that records people without it.

**Optional, once:** a binary install updated with `nouride update` keeps its old systemd unit. Re-run `install.sh` once to get the unit that lets a running command finish its step, and the launcher; `nouride doctor` reminds you until then. With Docker, add `stop_grace_period: 45s` to your compose file, as the shipped ones have.

**Going back to 0.6.7:** stop the daemon, run `nouride db restore nouride-<time>-before-048.db`, then install 0.6.7. The restore also moves the day pages back, and 0.6.7's first start reads its memory index again (about 40 seconds for 900 conversations). 0.6.7 also needs every `[[people]]` entry to name its first account `id = "…"`: for each person saved since the upgrade, move the first entry of `ids` to an `id` line, and take out anybody added without an account.

### For developers

- **SQLite is the database now (TD-015).** The portable-SQL rule is retired: stores may use FTS5, recursive CTEs and JSON functions. Loadable extensions stay out.
- **`lint:sql` checks that SQL is fast and safe**: interpolated values, SQL built with `+`, `LIKE` without `ESCAPE`, raw FTS5 syntax, table scans in the query plan, queries run once per item, `INSERT OR REPLACE`, SQLite's clock, double-quoted strings.
- **One gate for tags, one check for English**: `fileTags` (`modules/memory/tags.ts`) and `looksEnglish` (`modules/memory/english.ts`).
- **A person is their key** (`modules/people/entry.ts`), and `[[people]]` writes take turns per config file.
- **The database adapter** uses a 16 MB page cache, keeps temporary data in memory, and refreshes the planner's statistics at shutdown and after the nightly pass.
