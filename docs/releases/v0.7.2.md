### Safer by default

- **A session asks before it starts, and before every line typed into it.** At the default approval level (`risky`), an agent's `session start bash` used to run with no prompt: an open shell with the agent's `exec_secrets` in its environment. Starting a session, and each `send` into one, now asks at every level but `none`.
- **An agent can no longer answer approvals for you.** The `nouride` CLI reads the daemon's own token, so an agent holding the `nouride` tool could run `nouride approvals allow-always`, which answers whatever is first in the queue — its own request included. That now asks a person first, and so do `grants revoke`, `access approve|allow|block|…`, `secret set|rm`, `mcp-server on|off|token` and `service install|uninstall`. Reading them (`nouride approvals`, `nouride grants`, `nouride secret list`) stays free. Run by an agent, the command also needs the approval's id, and refuses a request its own agent made.
- **`web_fetch` refuses loopback and private addresses written as IPv6.** `http://[::ffff:127.0.0.1]/` reaches the guard as `[::ffff:7f00:1]`, which read as public, and so did the cloud metadata address and the NAT64 and 6to4 spellings. An address that carries an IPv4 one is now judged as that address.
- **Stopping a background job stops what it started.** `nouride jobs kill` on `sh -c "npm run dev"` stopped the shell and left the server running, and the job stayed listed as running. A job now runs in a process group of its own: SIGTERM to all of it, then SIGKILL after five seconds. Shutdown does the same, and waits for it.

### Easier on SD cards and eMMC

- **A restart no longer copies the whole database.** Every boot took a snapshot, so a box restarting in a loop wrote its database once per restart. Boot skips it when the newest snapshot is under twelve hours old, and the daily one comes a day after the newest rather than a day after boot.
- **Snapshots can live on another disk.** `[daemon] backup_dir` moves the scheduled snapshots of the database, the memory vault and the packs — onto a USB drive, say. Name a directory on the drive (`/mnt/usb/nouride`, not `/mnt/usb`): it is never created, so while the drive is unplugged snapshots are skipped and logged instead of filling the card under the empty mount point. A newly flashed Nouride Box keeps 3 snapshots instead of 7.
- **The health check no longer writes to the database.** It checkpointed SQLite's log on every call, and the dashboard's Home page calls it every ten seconds. The log is now bounded by itself and emptied after the nightly memory pass.
- **The scheduler sleeps until a job is due.** It woke every second to look; it now sets one timer for the next job, which fires at its exact time. `[cron] tick_interval_ms` is now the longest it sleeps, a minute by default.
- **The dashboard is cached.** Its scripts and styles are kept until the next update, and the page itself is checked with a `304`, so opening it no longer downloads about 2 MB every time.

### Cheaper conversations

- **The previous turn stays in the prompt cache.** The message being answered was sent with its time note and stored without it, so every turn wrote the previous one into the provider's cache again, at cache-write prices. It is stored as sent now — and an agent sees when each earlier message was sent.

### The LLM Gateway page (Router and Pro Router)

- **One dashboard.** The bundled gateway's dashboard is now a page of Nouride's: "LLM Gateway" in the sidebar, behind the same login, for admins.
- **Set up without an API key.** The setup wizard offers "Use Nougate LLM Gateway": sign in to Claude, ChatGPT, Copilot, Gemini or Kiro, and Nouride makes its own gateway key and writes the provider for you.
- **An update replaces the gateway's dashboard too.** It stayed at whatever version the box was installed with.

### Fix

- **A one-shot job kept with `--keep` is no longer reported as missed.** It fired, and its run said so, yet the job was switched off as `missed` with a warning that it had not fired. It now stays in the list as `fired`.

### Upgrading

- **Docker:** `docker compose pull && docker compose up -d`
- **Binary:** `nouride update --start`

No configuration changes are needed. If your `config.toml` sets `[cron] tick_interval_ms = 1000` — copied from an older example — remove it, and the scheduler sleeps between jobs.
