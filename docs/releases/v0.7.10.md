These notes cover everything since 0.7.7.

### Config

- **A value of the wrong type or out of its bounds is refused at boot**, by its path in the file — as 0.7.7 said it would be. `allow_private_urls = "false"` (a string), a negative spend cap, a retention of `-1`: 0.7.7 reported each and used its default; 0.7.10 does not start until it is fixed. Run `nouride config check` before you upgrade — it lists them.
- **`config.toml` is brought to today's spelling once, at boot.** What 0.7.x only translated as it read — `[security] sender_allowlist`, `[session_memory]` and its reset, `bridge_transport = "stdio"` and `bridge_command`, a person's `id` and accounts in an old spelling — is written the way it is read now, under the file's lock, checked to load exactly as the file it replaces, with the old file kept as `config.toml.bak.1`. Each change is logged; a file that cannot be written is left, and still loads. 0.8.0 reads 0.7.x's spellings no longer; `docs/DEPLOY.md` § Upgrading lists every one.
- **A saved `config.toml` keeps its permissions.** Every save — from the dashboard, the CLI, an agent or the boot bringing the file forward — left it, and its `.bak.N` copies, readable by every local user (0644) however it had been set.
- **A save is what the next boot reads.** A save from the dashboard, the CLI or an agent puts in the running daemon what the loader makes of the file: a WhatsApp connection saved from the dashboard took Telegram's reconnect timings, and a session directory lost its `~`.
- **A provider profile can say its calls are a subscription:** `billing = "included"`, as Nougate's OAuth accounts are. Those calls cost nothing per token — they are kept out of `max_daily_cost_usd`, still counted by `max_daily_tokens`, and shown as included rather than as list-price spend.
- **What the last boot said about the setup is listed** by `nouride doctor` and on Overview's Setup notes, one line per thing with the agents it concerns — not only in the journal at warn once.

### WhatsApp

- **The bridge runs inside the daemon, one WhatsApp number per daemon.** `bridge_transport = "ws"` is refused at boot with what to do: nothing ever served the far side of it, and reading it as in-process would quietly start a second session for the number. `"stdio"` is read as in-process with a warning, `bridge_command` is ignored, and `bridge_url` is an unknown key.

### Spend

- **Every model call is metered.** Compaction — on by default, and often the largest request a long conversation makes — a reflection pass, an image read, a clip transcribed: none of these reached the usage table, so both daily caps, the dashboard's spend and `nouride turns show` missed them. Each is recorded now, with what it was for: the turn's own, a helper's, a peer's, a steering reply's, a compaction, a reflection, the nightly memory pass, an embedding, an image, a transcription — a transcription by the clip's length, not by tokens nobody counted.
- **Past either cap, the work nobody waits on stops too:** `/compact` says it will not, and the compaction after a reply, a reflection pass, the memory pass's questions (forget, backfill, tag suggestions) and embeddings are not made.
- **A provider's silence is estimated, and said to be.** A reply that was only tool calls counted as zero output, and an embedding with no usage as zero input; both are estimated now, and the row says it is an estimate.
- **The price book is each vendor's own list, by exact model id**, read from Anthropic's, OpenAI's and Google's pricing pages on 2026-10-17, with the page and the day beside each row. Opus 4.5 to 5 cost $5/$25 per million tokens, not $15/$75; Opus 5.5 $4/$20; Sonnet 5 and 5.5 $2/$10. Gemini 3.8 and 3.6 Flash are $0.75/$3.75 until 2027-01-01 and $1.50/$7.50 from it, priced by when the call was made. Each row has its own cached-input price, and a long-context tier where the vendor lists one. A model the pages do not list — `gemini-3.7-flash`, a preview, a local model — is unpriced, never given a plausible rate.
- **Thinking a gateway left out of `completion_tokens` is counted:** Nougate's Gemini route reports it only in `total_tokens`.
- **`nouride turns show` says what each call was for** — a compaction, a reflection, a helper's — when it is included in a subscription, and when its counts are an estimate.
- **A summary paid for before an answer is kept** when the turn then fails or is stopped; the next message no longer pays for the same summary. A `/stop` during "compacting the conversation…" now stops the summary too.

### Memory

- **Forgetting someone reaches every copy memory keeps.** Undo no longer brings their facts back, every earlier version of every profile is scrubbed of them, Recent changes and Gave up stop showing them, and day hubs are redrawn. Undo restored them from `.history`, and Recent changes showed them word for word for 90 days. Deleting a single conversation does the same for what it taught.
- **A forget cuts every chat first**, so the night's pass does not file what the person said since the last cut as a new conversation with them in it.
- **`nouride people remove` replaces `people forget`, which forgot nothing.** Removing someone revokes their MCP tokens, and their key is not handed to a new person unless you pass `--reattach` — a new "Sam" inherited the old one's profile, conversations and tokens.
- **A conversation deleted on purpose stays deleted.** Cutting a chat twice cuts it once — after a crash, a `db restore`, a rollback or `/new` during the pass, the next cut filed the same conversation again as `…-2`, at one model call per copy — and a conversation you deleted is not filed again when its chat's place in the log is lost.
- **One bad file, chat or day no longer stops the nightly pass for every agent** — a pack named `nouva.v2`, a day fixed by hand in Obsidian. It is passed over, named under the last run, and the rest is done. A catch-up that fails is logged where it fails.
- **A conversation deleted during the pass keeps none of its facts**; approving a proposal no longer drops a revision written at the same moment; a tag tidy cut short can be undone.
- **What a turn writes to memory after reading a web page, an MCP answer or a received file says so**, in MEMORY.md and on the fact.
- **Deleting a dashboard account unlinks it from the person it was linked to.**
- **Search:** an item keyword and meaning search agree on outranks a lone keyword match. **The nightly pass is lighter**: a bounded word-index merge each night and a full rewrite once a week.
- **The vault says which format it is in** — `.nouride-vault.json` in the memory folder. A vault a newer build wrote refuses the boot, by name, with the way back, instead of being read wrong and written over; an older one is snapshotted and brought forward; `nouride db restore` puts the vault in the format the restored database's build reads, going by the marker rather than the schema number.
- **A memory proposal of another shape is skipped, not cast:** one from before 0.6.0, read as today's, would have filed a fact under `people/undefined.md`.
- **`nouride memory backfill` imports 0.5 and 0.6 captures only.** The day-summary importer and its `--person` flag are gone; archive episodes already in a vault are read, searched and recalled as before.

### Gateways and conversations

- **`nouride gateway rename` reaches everything that names the gateway** — the room log, the event stream, the inbox, memory's index and cursor, every agent pack's `[channels]` and `sender_allowlist`, and the memory vault, snapshotted first. It rewrote only `config.toml` and part of the database: agents bound through `[channels]` failed to load after it, and a group on the renamed gateway lost its memory.
- **A rename that cannot finish is refused before anything is written** — onto a name a removed gateway's rows still use, while a message is waiting on the old name, or when a pack would stop loading.
- **Deleting a conversation leaves nothing of it**: its `/model` override, its spilled tool output and the approvals it was waiting on go with it.
- **A reply a platform refuses for good is not retried** as a formatting problem, and a scheduled run whose reply was refused is recorded failed, with why — it was recorded as delivered.

### Security

- **A credential never reaches the journal, the log table or the audit log.** Every log line is scrubbed where it is written: a value under a key named like a credential, `Bearer` and `Basic` values, a URL's password, credential-named parameters inside any string.
- **An agent gets the ssh-agent socket only when its pack asks for it**, with `[security] ssh_agent = true`. Every command, session, scheduled command and stdio MCP server of every agent held `SSH_AUTH_SOCK`. Boot names each agent that loses it. A key named in `~/.ssh/config` is not affected.
- **A fetch behind the SSRF guard connects to the address the guard checked** — the check and the fetch resolved the name separately, so DNS rebinding could send the connection somewhere the guard refused. A scheduled run's webhook is no longer redirected past the guard.
- **An agent asked by another works at its own approval level**, not at the asking person's.
- **Another site's page cannot write through your dashboard session**: a cross-site write to the control API or the LLM Gateway page is refused. The hosted gateway's own port takes keys only once its dashboard is in Nouride's, and its pages are served under a content policy written from what they load.
- **The Docker image never installs a package from npm at runtime.** Bun installs any import nothing resolves, and an edition imports the plugins it leaves out by names nobody owns on npm — whoever published one would have had it run in every container that started. The image runs with `--no-install`, as the binary already behaved.
- **A secret is asked for bound to the command that needs it.** Every agent's instructions asked the operator to add a secret to the list form of `exec_secrets`, which hands every command every secret; they ask for `[security.exec_secrets] <name> = ["<command>"]` now, as do the bundled skills and the example pack.
- **MCP:** a pack whose servers' tools would share a name is refused at load, and each server's schema cost per request is shown (`nouride mcp`, `doctor`, the MCP tab). Tokens for Nouride's MCP server expire — 90 days unless `--ttl` says otherwise; tokens made before this release keep working. A quiet legacy SSE server is pinged, and reconnected when it does not answer.

### Commands an agent runs

- **Nobody is at the keyboard, and the command is told so:** `DEBIAN_FRONTEND=noninteractive` and `GIT_TERMINAL_PROMPT=0` are set for every command, so `apt` takes its defaults and `git` fails at once instead of waiting on a prompt nobody sees.
- **A command killed for memory is killed alone**: systemd stopped the whole daemon with it. The commands agents run are what the kernel reclaims first.

### Context and tokens

- **Long sessions over logs are trimmed and compacted at their real size.** A log of timestamps and ids counts about 2.3 tokens for every one Nouride estimates; the window, the trim before each round, `compact_at_tokens` and the cap on one tool result now go by what the provider reported for the conversation's last request.
- **Estimating a conversation's size is about 150× cheaper per turn** — 1–2 ms where a 160k-token conversation took about 0.2 s of CPU before every round.
- **A summary no smaller than the history it would replace is not kept**: `/compact` on a short chat says it is short enough to keep verbatim instead of making every later turn bigger.

### Logs and scheduled jobs

- **A tool's refusal and a turn a background job ended are not logged as faults**: "tool refused the call" is a warning and a job's wrap-up is info, where both were errors and warnings among the daemon's real ones.
- **A crash says what failed.** An uncaught error is logged with its class name and its whole stack, and a command that crashes — `nouride start` included — names the error's class and prints its stack.
- **A background check that fails no longer stops the daemon.** The daemon shuts down on an error nothing caught, on purpose, and about thirty of its timers — the maintenance sweeps and snapshots, the scheduler, the jobs watchdog, an approval's expiry, an update's health check, a gateway's or an MCP server's reconnect, a provider's retry — could each end every conversation over one failed read. Each now logs where it failed and carries on; an approval whose expiry could not be written still lets its turn go, as a denial.
- **The stored log has a ceiling of 200,000 rows** as well as its days, so a reconnect storm cannot fill a card in a day. **`nouride logs -f` follows a restart**: it ended at the first poll the restarting daemon could not answer, and once it could reach the new one it skipped that daemon's lines, boot included.
- **An idle daemon stays idle:** the audit log and the log table flushed on a clock, sixty wake-ups a minute with nothing to write; they flush when they hold something.
- **A job whose chat refused its run is reported through the alert channel**, not to that same chat again.
- **The journal names an idle Telegram bot's health from its last poll**: about 1.2 requests a minute instead of 4.

### The event stream (protocol 1.1)

- **The stream says what it will not send.** Asked with `frames=1`, it opens with `hello` — the protocol, the oldest and newest rows, and the database's `epoch` — and says `gap` for rows it will not replay (swept with their turns, or more than one stream replays), `reset` for a cursor past the newest row (a database restored to an older state), and `bye` before it ends a stream. Every stream sends the cursor it starts from right after `retry:`, so a drop before the first row resumes there.
- **It goes at the reader's pace.** A replay is read a page at a time as the reader takes it and stops at 5,000 rows; a reader that lets 2,000 new rows pile up is closed, and comes back with nothing missed. `nouride events -f` follows from now, prints the frames, and stops on a refusal instead of retrying it every three seconds; a bare `nouride events` shows the newest page.
- **A turn's rows add up to the turn:** the answer's last characters before the end are in the stream, a long chunk comes as several rows instead of being cut, a turn a restart cut off ends `interrupted`, and text cut before the size bound says so.
- **`tool_done` says how a call ended** (`outcome`: `ok`, `exit`, `failed`, `timed_out`, `killed`), and **`usage` says what a call was for and how it is billed** (`purpose`, `basis`, `priceAsOf`).
- **Loss is said:** a row the daemon could not write is counted, logged at warn, and named on `/health`.
- **`seq` is never handed out twice**, whatever is deleted, and the steps of turns recorded before 0.7.4 are rows of the stream now — copied in once, with their own times. `docs/EVENTS.md` has the contract.

### The dashboard

- **It loads in about a tenth of the bytes.** A first visit to Overview transferred 2.1 MB and now about 250 KB: scripts and stylesheets go compressed (brotli or gzip, as the browser asks), each page's code loads when the page is first opened, and the avatar is a 6 KB image instead of a 922 KB one.
- **A page opens on your theme.** On the light theme every load flashed dark until the page started.
- **A failed load says so:** Agents no longer reads it as no agents, and Overview says operational only when it is.
- **Answering an approval says what happened**, and one answered elsewhere or expired is said as that, not as an Allow. **Run on a scheduled job says how it went** — a refusal, an outcome, or that it is still going — and pause, resume and delete say when they fail.
- **The tool-call budget's advice holds its own default.** A turn has allowed 250 tool calls since 0.7.0, while the dashboard, `nouride tool-budget` and the config's refusal still advised 25–100 — so a fresh install was told to prefer a background job at its own setting. All three say 50–250 now: in a month of real turns, one in 35 needed more than 25 tool calls, and past 250 a turn runs out of its hour first.
- **An agent's Skills tab shows what the agent has:** a skill turned off for everyone no longer shows as on, and a built-in overridden by your own copy is listed once.
- **A page named like another does not take its layout:** an agent called `chatbot`, `logs-bot` or `secrets` scrolls.
- **Every icon-only button has a name a screen reader says**, and the error banner is announced.
- **Steps are paired by the call they belong to and read red by how the call ended** — a `which` that answered "no" is not a failure, a timeout is — and a turn a background job woke is headed by how the job ended, not by matching its wording.
- **A hidden tab holds no event stream**, and polls slower: six open tabs no longer use up the browser's connections to the daemon. **A tab left open across an update says so**, with Reload.
- **Scheduling and webhook forms send what the daemon reads**, typed: a misspelt field is a build error, not a job that quietly ignores it.
- **The docs site's loading screen waits for a 97 KB logo**, not the 1.4 MB original.

### The CLI

- **A flag a command does not read is refused**, exit 2, naming it and what the command does read: `nouride memory pass --dry-run` ran a real pass. A flag's value is a value (`--arg -y`), and after `--` nothing is a flag.
- **A refusal is not a success.** About twenty paths printed their usage or a refusal and exited 0 — so the `nouride` tool read "restart needs --then" as done, and `--json` said `ok: true`. They exit 2 for a call missing what it needs and 1 for a refusal; an answer that is not JSON (a proxy's 502 page) is exit 1 with that said, and any failure under `--json` is an envelope rather than empty output.
- **`nouride help` has every action and flag** a command takes.
- **`nouride chat` reads a whole script.** A piped script's lines arrive together, while its first message is being answered, and every one after the first was dropped: a scripted run sent one message and ended, and a last line with no newline left it waiting for good. Each line is sent now, once the one before it is answered.

### Model wire

- **Malformed tool-call arguments are an error the model reads**, not an empty object it acts on; **a stream that just stops** — no finish reason, no end marker — is an answer cut off, not a finished one; and **a body the API never promised** is a clear error, not a crash. A steering reply describes the steps the turn recorded.

### For integrations

- **The MCP server's surface is pinned** in `docs/contracts/mcp-surface.json`. `memory_read` no longer offers `earlier` and `query`, which read back the calling chat's archive and meant nothing to a client; a parameter not offered is not taken by name.
- **A transcript's older part is `earlier`, not `legacy`**, in `GET /api/control/sessions/:id/turns` and `/rooms/:chatId/turns`: it is the part of a session older than the oldest turn the log keeps. **`GET /api/control/sessions/:id/messages` is gone** — undocumented, and nothing called it.
- **A body of JSON `null`, an array or a number is a 400** on every control route; several read a field of it and answered 500.
- **`GET /api/control/sessions/:id/live` honours `after` only beside the `turn` it counted**, as its contract said: a count sent without a turn — of steps in a turn that may have ended — starts at the beginning instead of skipping a new turn's first steps.
- `GET /api/control/events?newest=1` answers the newest page; `GET /health` answers `eventProtocol`.
- `nouride pkg` and `doctor` refuse a package service that speaks another protocol than the daemon, and say how to bring it in step.

### Updates and the service

- **A Pro server off a Box is told an update exists** and how to install it, where it was told it was up to date.
- **What an update replaces is one list**, shared by the update, its rollback and `install.sh`; `config.example.toml` is kept current with the rest.
- **The unit is no longer frozen at install time.** `nouride doctor` and `nouride service diff` show what an older unit lacks, and say when its memory ceiling or `/tmp` size is more than a quarter off this machine; the ordinary unit gains `CapabilityBoundingSet=`, `RestrictAddressFamilies` and `RestrictRealtime`, and carries only what the machine's systemd knows.
- **`install.sh` re-runs** take `--host` and `--port`, wait on the daemon's real port, and keep the data directory private from the start. On macOS an install no longer stops at "unknown group". A Pro `--tarball` install finds its checksum file by what it lists, and checks the signature beside it.
- **Snapshots keep history**: three restarts in a row no longer rotate out every older vault and pack backup, nothing unchanged is copied again, and a database snapshot is refused when the disk could not hold it twice. On macOS the launchd log is kept under 16 MB.
- **Docker:** the image runs with `--smol`, on the same Bun as the binaries (1.4.2), and the compose healthchecks ask the port the daemon listens on.

### The Box (Pro)

- **A Box's upkeep no longer depends on Wi-Fi**: on Ethernet, `nouride.local` follows the box's address, and the dashboard's actions reach the journal.
- **"Three short power-ups" counts power-ups, not daemon restarts.**
- **Reset accounts asks the daemon** and says when it did not happen; only a reset that happened restarts the box. Its settings files survive a power cut, and its links follow the dashboard port you set.
- **Nouverse sign-in gives up after 10 seconds** on an identity provider that does not answer.
- **A release whose checksum file is not served yet is tried again**, not refused as a bad release until the daemon restarted — a box that looked while a release was still being published refused it.
- **An OpenWrt box can update**, with the same rollback guard as the others — untried on OpenWrt hardware so far.

### Releases

- **Binaries and Docker images stay fully minified, and an error is still named by what it is.** Every error class carries its own name, so the journal says `ConfigError: …` where 0.7.7 said `jm: …`. Each build keeps a private map of its own code, checked against what ships, which Nouverse uses to read a stack trace you send back into the source.
- **A tag builds every edition**, and fails if none was planned for the fleet; the Pro code is tested, typechecked and linted before a Box edition is built from it. **Signing happens in a job of its own** that holds the signing key and installs nothing, and a Pro edition's checksum file is always signed. **Both release pages carry these notes.**
- **The licence is stated once:** Nouride is proprietary (`LicenseRef-Proprietary` on every image); the WhatsApp bridge, `packages/wa-bridge`, is MIT.

### Upgrading

- **Docker:** `docker compose pull && docker compose up -d`
- **Binary:** `nouride update --start`

Before you upgrade:

- Run `nouride config check`. A value it marks ✗ stops 0.7.10 at boot until it is fixed; 0.7.7's own check already marks each one ("from 0.7.8 a daemon will not start with it"). Docker has no update guard to put the previous version back, so check with the new image before you pull: `docker run --rm -v ./.nouride:/app/.nouride ghcr.io/nouverse/nouride:0.7.10 nouride config check`.
- A pack that names two `[[mcp_servers]]` the same does not load in 0.7.10 — the daemon starts without that agent — and `config check` does not say so yet: give each server a name of its own first. `nouride doctor` names a pack that did not load; fix it, then restart.
- An image pinned to `:0.7.8` or `:0.7.9`: both releases were withdrawn and their tags removed. Use `:0.7.10`, or `:0.7` to follow 0.7.x.
- A WhatsApp connection with `bridge_transport = "ws"`: remove `bridge_transport` and `bridge_url` from its table.
- Scripts that call the CLI: a flag a command does not read now fails with exit 2 instead of being ignored.

After:

- On a Box or a server whose models are Nougate's subscriptions, add `billing = "included"` to that provider profile, so the dollar cap and the spend figures stop counting them at list price.
- An agent that used `SSH_AUTH_SOCK` from the daemon's environment needs `ssh_agent = true` under `[security]` in its pack; boot names each one.
- A non-Box install: re-run `install.sh` once to take the new unit (`nouride doctor` says when it is older).
- Back to 0.7.7, once 0.7.10 has started: 0.7.7 refuses the newer database and says how to go back — restore the snapshot 0.7.10 took before migrating (`nouride db list` shows it as `…-before-0NN.db`; then `nouride db restore <that file>` — in Docker, both inside the container). What was said since the upgrade is not kept.

**config.toml:** the first boot writes it in today's spelling and keeps the previous file as `config.toml.bak.1`; the journal lists each change.

**Memory vault:** a `.nouride-vault.json` file appears in the memory folder on the first boot. Obsidian ignores it.

**Database:** migrations 052 (the event stream's cursor and the usage columns; the steps of turns from before 0.7.4 move into the stream), 053 (`mcp_tokens.expires_at`) and 054 (two indexes on `memory_changes`). A snapshot is taken first, as before every migration.
