**0.8.49 updates from 0.8.0 or later.** From 0.7.x, start 0.8.0 once first:
[Upgrading to 0.8](https://nouride.com/en/docs/deployment/upgrading-to-0-8/) has the way across.

On Docker, check your configuration with the new image before you switch:
`docker run --rm -v ./nouride:/app/.nouride ghcr.io/nouverse/nouride:0.8.49 nouride config check`, with the volume your
compose file mounts.

### Three more coding CLIs

An agent can now be answered by Google's **Antigravity**, **Cursor CLI** or xAI's **Grok Build**, beside Claude Code
and Codex. Antigravity was tried on a real account: it answered, and wrote and edited files in its folder. Cursor CLI
and Grok Build were installed, started and asked for a session on a Linux box, but neither has answered a turn on a
real account yet, so each is marked **Experimental** on **Models → Coding CLIs** and where an agent's CLI is picked. It
may not answer, or answer only in part: tell us in an issue if one does not.

- **Antigravity** signs in with a Google account on a Google AI Pro or Ultra plan, **Cursor CLI** with a Cursor
  account, and **Grok Build** with a Grok account on a SuperGrok or X Premium+ plan, with a link, and a code where the
  CLI asks for one.
- **Set it up** on their cards asks the orchestrator to install them, as it does Claude Code and Codex. They install
  with their makers' own scripts, not npm: the new `nouride agents install <cli>` runs that script and puts the CLI
  where every agent runs it (the manual's
  [External agents](https://nouride.com/en/docs/manual/external-agents/#installing-a-cli) page).
- **A message you send while an Antigravity agent works goes into the work it is doing**, as it does for Claude Code
  and Codex agents. While it waits for your approval, it is read once its prompt ends.
- On **Free in its folder**, what a CLI still asks before it acts is allowed by Nouride without asking you, for these
  three as for any CLI. Antigravity's three presets are its own modes `auto`, `accept-edits` and `default`. Cursor CLI
  and Grok Build start in their own modes, and on the other two presets what they ask comes to you as an approval.
- **A coding CLI of your own named `antigravity`, `cursor` or `grok` stays yours.** Your `[[external_clis]]` row is
  kept in the built-in one's place, and the start says so once, as `nouride config check` does.

### Every coding CLI's account is signed in on the Models page

- **Sign in** is on each account on **Models → Coding CLIs** for every CLI now, Codex and the three new ones as Claude
  Code has had it: the account is signed in once, there, and an agent is put on it on its **Brain** tab or when you make
  it. Before, an account of a CLI other than Claude Code was only a name, and each agent on it signed in on its own Brain
  tab; that sign-in is no longer there.
- Those CLIs keep their sign-in in files: Nouride keeps them in a folder of the account's, which no agent can read,
  writes them into each agent's folder as its CLI starts, and copies back what the CLI renewed after each turn. Two
  agents on one account working at the same moment can still renew it under each other, and one is then asked to sign
  in again: one account per agent avoids that.
- An agent that signed in by itself before, as every Codex agent had to, keeps answering with its own sign-in until
  its account is signed in on the page; from then on it takes the account's.

### How much of each account is used

- **Models → Coding CLIs** shows, under each account, how much of its plan is used: each limit, the share of it used,
  and when it starts again. Claude Code, Codex and Cursor CLI are read from their makers at most every five minutes,
  with the account's own sign-in, the same question each CLI's usage page asks; between reads, what the CLI says while
  it works, said as that. Grok Build is read while an agent on the account runs. Antigravity says nothing of its use
  yet, and its accounts say that it is not known. Where each agent signs in by itself, each agent's own is shown under
  its name.
- **An account whose limit is used up is passed over before a message is refused there,** where its maker says no
  credits are left beyond it; a model's own limit, for that model alone. An agent with more than one account starts its
  next turn on the next one. Where credits are left, or nothing is said of them, nothing changes: the account answers
  as before. A later read showing room again lets it answer at once. The read runs beside a turn, never before it.
- **A message refused for a limit that said when it ends is held, and goes on by itself then.** Where the agent has no
  other account to go on with, the chat is told so, and at the limit's end the agent picks the message up again, as if
  you had said "continue". A restart in between keeps it. It is not held if you said something in the chat since
  (someone else in a room, or a scheduled job, does not count), or where the limit ends more than eight days on.
- **A signed-out CLI is said at once.** Told its sign-in method, a signed-out CLI that does not take it is said to be
  signed out within seconds, not after a minute and a half.

### Nougate on the Models page, and two providers on every new install

- **Nougate's page is opened from Models**, with **Open Nougate**, and is no longer in the Settings menu. It is the
  same page: turning Nougate on or off, its accounts, keys and usage. **← Models** on it goes back.
- **A new install has two providers on Nougate, `nougate-openai` and `nougate-anthropic`,** whether or not you choose
  Nougate in setup. Nougate stays as you chose: off, unless you chose it. On **Models** they are marked **Off** while
  Nougate is off and **No account** while no account is signed in there, and an agent's model picker offers them only
  once one is. Nougate gives them their key as it starts. Choosing Nougate in setup uses these two; it no longer writes
  a provider named `nougate` of its own.
- An install from before is not given them, and keeps its providers as they are.

### xAI as a model provider

**How to get an API key** on the model providers' page lists xAI beside DeepSeek: a key from console.x.ai, its Grok
models at `https://api.x.ai/v1`, charged per use.

### Before you upgrade

- **Going back to 0.8.48** takes the database snapshot the update kept, as after any release that changes the
  database: `nouride db restore`, which 0.8.48 names when it meets the newer data. A message held for a limit's end
  when you go back is not picked up again by 0.8.48: say "continue" in its chat.
- An agent on Antigravity, Cursor CLI or Grok Build is new: none existed before, so nothing of yours changes.
- On Docker, run the `config check` above with the new image first.
