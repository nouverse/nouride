**0.8.2 updates from 0.8.0 or 0.8.1.** From 0.7.x, start 0.8.0 once first:
[Upgrading to 0.8](https://nouride.com/en/docs/deployment/upgrading-to-0-8/) has the way across.

### Nouride Pro on your own server

Nouride Pro now runs on your own Linux server (x64 or ARM64), licensed by Nouverse and updated the way a Nouride Box
is: `nouride update` and the dashboard's Update page take Pro releases from Nouverse, with nothing to download by hand.
A server starts no setup hotspot and no `nouride.local`, so its port 80 stays yours; My Box says a server has none.

### Fixed

- **`nouride tools run` on Docker, macOS and Linux without the helper** installed the program and then said "installed,
  but not every agent can run it yet", exit 1 — and so did the orchestrator's install of a coding CLI on your yes.
  Where no agent has a user of its own there is nothing to share, and nothing is reported.
- **A Nouride Box below a release's upgrade floor** is offered the release it needs on the way first.
- **The `coding-agents` skill** hands work to an agent its CLI already answers — Nix on Claude Code — with `ask_agent`,
  rather than running the CLI again under a second sign-in.

### Docs since 0.8.1

A new [Upgrading to 0.8](https://nouride.com/en/docs/deployment/upgrading-to-0-8/) page; external agents with the
official ACP adapters, how to install and sign in each CLI, and what Nouride decides and what the CLI does; missions in
a repository; each agent its own user; troubleshooting for what 0.8 can refuse.

### Not in 0.8.2

- Codex reads `AGENTS.md` from its git root down, so in a mission's repository it does not read the agent's persona
  block in the agent's own folder. Claude Code, which reads `CLAUDE.md` upward, does.
